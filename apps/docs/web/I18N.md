# Docs internationalization handoff — 2026-09-25

Local implementation; final integration status and local commit are recorded in `docs/quality/handoff.md`. No push, deployment, remote host, outbound email or real `data/` access in this round.

## Shared interface

`@synwevo/ui` exports the agreed API:

```ts
type Locale = 'zh-Hans' | 'zh-Hant' | 'en';
useI18n(): { locale: Locale; t: Translator; setLocale: (locale: Locale) => void };
I18nProvider({ children, title? });
LanguageMenu({ className? });
registerMessages({ '简体中文来源': { en: 'English', 'zh-Hant': '繁體中文' } });
```

`t(source, params?)` is text-only, replaces parameters once, and uses `Intl.NumberFormat` for numeric parameters. English plural entries may be `{one, other}` and use `count`/`Intl.PluralRules`. Both translations and every plural form must have the same parameters as the source. `formatNumber` and `formatDate` use Intl; stored values do not change. `getLocale`, `normalizeLocale`, `setLocale`, `subscribeLocale` and the React-free `@synwevo/ui/i18n-core` entry support session synchronization and tests.

Initial preference order: exact navigation `?lang=zh-Hans|zh-Hant|en`, saved `synwevo.locale`, first supported browser language, then zh-Hans. A valid navigation choice is saved and only `lang` is removed with `replaceState`; other query parameters, router history state and hash survive. Unsupported query values do not override a saved preference. Locale switches publish state without re-keying the application. The provider updates document language/title. Domain catalogs register locally; shared packages do not import applications.

Catalogs: Docs interface 1,255 entries, Docs service presentation 197 entries, shared API errors 23 entries, shared widgets 13 entries. These counts include reused source keys. Resources cover both translations and parameter parity. Every literal Docs `t`/`tr` call is checked against its catalogs.

## Preserved contracts and data

Document paragraphs, cells, images, uploaded text, file names, field names/IDs, templates, number/date format codes, `{序号}`, value maps and persisted mapping-history notes stay unchanged. TipTap React node views localize field/repeat chrome while serialized attributes remain unchanged. No DOM translation or runtime translation service is used. Regression engine differences and user/engine record labels remain their original payload; they can contain Chinese independently of the interface language.

Known service diagnostics use stable code/presentation mapping (94 Docs codes and 51 shared API codes). Unknown failures display a localized generic sentence plus code/request id when supplied; unknown informational/warning codes receive a neutral processing notice. Real browser review caught `formula_computed` falling into the generic failure text: it now correctly describes successful formula calculation in all three languages, with a regression test. `ApiError.originalMessage`, `code`, `detail`, `status`, `upstream`, `retryAfter` and `requestId` retain diagnostics/contracts. Legacy string-only failures cannot provide detail-specific translation or a missing request id; their original records are untouched. Fixed capability descriptions and known location/output-format patterns are translated locally.

Server refusals (CI-86, 2026-09-28): `issueText` presents a refusal from its `detail` first (`lib/refusals.ts` templates, also registered with the shared `registerErrorTemplates`), then the server's own sentence (`messages.refusals.ts` and the other catalogues), then a catalogued engine sentence shape with its values read back (`refusalPatterns`; a nested `{reason}` is presented the same way or not at all outside zh-Hans), and only then the code maps. `tests/refusals.test.ts` reads every server refusal and fails on one that is not catalogued, templated, a pattern, code-mapped sentence by sentence, or listed as API-only with a reason. Adding a server refusal means making that decision there.

## Workspace and session behavior

`api(path, {workspaceId?: string})` applies headers in this order: custom headers, `authHeaders`, explicit workspace. It does not store an unvalidated workspace or confer permission; the backend validates it. Existing CSRF/workspace storage logic is preserved. Authenticated `unauthorized`, `session_expired`, `session_revoked` 401 responses emit `synwevo:session-expired` only with a Synwevo request-id/server marker. Fetch, XHR and binary requests use this path; wrong credentials and gateway 401s do not emit it.

`FilePanel` and `TemplateChooser` multipart mutations use shared `upload()` and `authHeaders('POST', false)`. No owned Docs raw mutation bypasses this. The sole Docs raw fetch is `src/lib/resources.ts`, an authenticated GET using `authHeaders`.

All former direct API download anchors now use `DownloadLink` and an authenticated blob request:

- `pages/JobPage.tsx`: `/api/jobs/{jid}/zip`, format ZIPs, `/report.csv`, `/api/artifacts/{id}`.
- `pages/Regression.tsx`: `/api/regression-cases/{id}/download`.
- `pages/Workspace.tsx`: `/api/templates/{id}/download?which=working|original`.
- `components/FilePanel.tsx`: `/api/sources/{id}/download`.
- `components/PreviewPane.tsx`: `/api/preview-files/{blob}`.
- `components/DesensitizeDialog.tsx`: `/api/desensitized/{blob}`.

PDF source/template/preview page images in `views/PdfView.tsx` and `components/PdfRepeatEditor.tsx` use authenticated `ApiImage`, abort on unmount and release object URLs. Other document/slides images are embedded data URIs. No tenant query parameter was introduced.

There is no EventSource, WebSocket or events-feed consumer in Docs web. Read-only backend audit identified `/api/v1/events` (`api/v1_webhooks.py`), `/api/jobs/{jid}/events` (`api/app.py`) and `/api/v1/jobs/{jid}/events` (`api/v1.py`) for the main task's cross-client authorization review; no owned frontend stream remains to bind.

## Limits and coordination

The component fixture remains useful for async refusal/state preservation checks. Both isolated-service and registered-user full-stack runs now cover XLSX upload → mapping → generation → downloaded artifact readback in all three locales. The full-stack run establishes positive registration/file-mail/SSO and workspace-header behavior for one personal workspace; it does not establish cross-workspace denial, revocation, idle expiry, organization administration or every export format. Portal/identity links and SessionProvider/PlatformNav are owned by the other tasks. Backend migration, H07/H08 fixes and API-platform policy work are outside this assignment.

Downloads currently buffer a blob before saving. Very large archives need a separate backend-authorized streaming/download-ticket design to avoid browser memory pressure; no tenant-query bypass has been added. Unknown engine prose receives a localized generic diagnostic rather than an invented translation; document/engine payload content and diff output deliberately remain verbatim. No known untranslated static Docs UI source remains outside the intentional data/format literals above. Full editorial review of every English sentence and every browser route is not claimed.
