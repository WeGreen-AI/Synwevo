# 内置回归用例（合成测试数据）

这个目录只放**随代码提交的合成用例**：只读，由 pytest（`apps/docs/tests/test_regression_cases.py`）
与运维脚本 `python apps/docs/scripts/regression.py` 运行，**不会通过任何 HTTP 接口列出、下载、重放或删除**。

界面中「更多 → 保存为回归用例」保存的是**工作空间数据**，不写到这里：

* 位置：`$SYNWEVO_DATA_DIR/regression/<工作空间>/<用例编号>/`（设置了 `SYNWEVO_DOCS_REGRESSION_DIR`
  时为 `$SYNWEVO_DOCS_REGRESSION_DIR/<工作空间>/<用例编号>/`）；
* 内容：来源文件**原样**（未脱敏）、模板工作副本、规则、映射与期望结果；
* 可见范围：只在所属工作空间内列出、下载、重放和删除；跟随数据目录备份，不进入源代码树。

**这里只允许合成测试数据或已脱敏的文件。** 不要把从界面保存的用例复制进来；提交前确认目录中没有真实个人信息。

## 目录中的用例

| 用例 | 类型 | 用途 |
|---|---|---|
| `20260923-085124-3d8d48` 合成种子：订单分组 + 重复明细（XLSX） | **合成测试数据** | 让内置用例链路真正在 CI 中运行（此前目录为空，`test_committed_cases_still_pass` 被跳过，该路径等于没有覆盖）。15 条样本，覆盖每组一份 + 重复明细行 |

**合成种子不等于真实业务验收。** 它证明的是回归机制本身可用：用例能从磁盘加载、重放、并逐字段比对期望值
（实测把期望值改成别的内容后 `run()` 返回 `ok=False` 并给出
`字段「订单号」：保存时 "…" → 现在 "DD-014"`）。真实业务验收仍待用户提供脱敏样本，见
`docs/quality/verification.md` 的「仍需用户材料」一节。

## 旧版本保存的用例

* 升级前在部署上保存到本目录的用例不会自动迁移，也不再通过接口列出；需要保留的，由运维人员按所属工作空间
  移到上面的数据目录位置。
* 分组值含 `/` 的样本，其样本标识格式已改变（`json:` 前缀）。重放旧用例时按旧标识找回对应样本，
  不会因为标识格式变化而报告「样本已不存在」。
