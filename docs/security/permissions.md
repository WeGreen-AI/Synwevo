# 身份、信任边界与权限矩阵

本文件是授权实现的**契约**：代码、测试与评审都以此为准。写在这里的每一条都必须有对应的服务端
强制点和测试；没有实现的不写进来，实现了但没测的标注为「未验证」。

状态：**实施中**。本文件先于实现落地，逐条打勾。已完成的条目在「强制点」列给出 `file:line`。

---

## 0. 出发点：现状有什么、没有什么

改造前（HEAD `164cfba`）的真实情况，由代码核实：

| 项 | 现状 |
|---|---|
| 身份 | **没有用户概念**。`ui_users` 只是一张共享口令表，所有人登录后看到同一份数据 |
| 会话 | **没有**。HTTP Basic 每请求重发凭据，因此没有登出、没有会话列表、没有撤销、没有重新认证 |
| 授权 | **没有**。任何通过 Basic 的人对全部项目有完全权限 |
| 数据归属 | `projects` / `templates` / `jobs` 有 `tenant` 列，但**全部是 `'default'`**；`projects` 没有 owner 列 |
| 机器接口 | `/api/v1*` 需要 API 密钥，密钥带 `tenant` 与 `scopes`，是目前唯一真实的作用域机制 |
| 匿名面 | `DOCWEAVE_UI_AUTH=none` 时 `/api/*`（非 v1）、SPA 与静态资源**完全匿名** |

所以这不是「给已有权限系统加角色」，而是**在一个单租户应用上从零引入身份与授权**，同时不能弄丢
已有数据，也不能破坏已交付的文档引擎与 `/api/v1` 契约。

## 1. 信任边界与数据流

```
                    ┌─ 不可信 ─────────────────────────────────────┐
  浏览器 ──────────►│ Cloudflare / 反向代理（可伪造头，见 §2）      │
                    └────────────────┬─────────────────────────────┘
                                     │  HTTP（源站只监听回环）
                    ┌────────────────▼─────────────────────────────┐
                    │ FastAPI 单进程                                │
                    │  _gate 中间件：身份 → 工作空间 → 限流          │
   信任边界 ①───────┤  services / views：逐对象授权                 │
                    │  job-runner 线程：请求之外，需自带身份上下文   │
                    │  webhook 线程：出站，受 SSRF 限制              │
                    └───┬─────────────┬──────────────┬─────────────┘
                        │             │              │
   信任边界 ②──────► SQLite       blob 存储      子进程（LibreOffice /
                     （WAL）      （内容寻址）    Tesseract / PDF）
                                                  ▲ 处理不可信文件，
                                                    必须限权限/网络/资源
```

* **边界 ①**：请求进入进程。此处确定「调用者是谁、属于哪个工作空间、有哪些权限」。
  之后**一律不再相信客户端传来的 `user_id` / `tenant_id` / `role`**。
* **边界 ②**：进程访问持久化。此处不做授权判断——授权必须在 ① 之后、访问 ② 之前完成，
  否则 job-runner 这类非请求路径会绕过。
* **子进程边界**：解析器处理的是攻击者可控的文件，按不可信代码对待（§7）。

## 2. 反向代理与转发头

源站只监听回环，对外经 Cloudflare Tunnel。因此：

* `X-Forwarded-For` / `X-Forwarded-Proto` / `X-Forwarded-Host` **只有在明确配置了可信代理时才采信**。
  限流与审计里的来源 IP 必须走同一套判定，不能一处信一处不信。
* 目前签名下载链接的域名取 `DOCWEAVE_PUBLIC_URL`，否则才回落到转发头（`api/v1.py:public_base`）。
  伪造这些头只能改到攻击者自己拿到的 URL，令牌仍独立校验。

## 3. 身份种类

| 种类 | 载体 | 生命周期 | 用途 |
|---|---|---|---|
| 用户会话 | 服务端会话 + `HttpOnly` Cookie | 空闲过期 + 绝对过期，可即时撤销 | 浏览器里的一切操作 |
| 机器身份（API 密钥） | `Authorization: Bearer dw_…` | 长期，可撤销/轮换，带作用域 | `/api/v1` 自动化 |
| 签名链接 | URL 中的一次性令牌 | 短期（默认 15 分钟） | 下载单个产物/压缩包 |
| 引导令牌 | 一次性 CLI 产物 | 单次 + 短有效期 | 建立首位平台管理员 |

**机器身份的权限 = 密钥作用域 ∩ 该身份当前权限**。密钥不继承管理权限，也不因为「密钥还在」
而绕过账户停用。

## 4. 权限矩阵

权限以稳定标识符表示（不是可自由输入的表达式）。角色是权限集合的命名快照。

### 4.1 平台级

| 角色 | 可以 | 明确不可以 |
|---|---|---|
| 平台管理员 | 管理账户状态、工作空间状态、服务运行、查看安全事件 | **不自动获得任何工作空间内文档正文的读取权** |
| 平台运维 | 查看服务健康、容量、任务队列状态 | 不改权限、不读文档正文 |

平台权限**不是**工作空间权限的超集。要读某个空间的文档，必须走「支持访问」流程：显式授权、
限时、限定对象、记录理由、完整审计（§6）。默认关闭，没有「代登录」。

### 4.2 工作空间级

| 角色 | 读 | 写 | 运行任务 | 下载/导出 | 管成员 | 生命周期 |
|---|---|---|---|---|---|---|
| 只读成员 | ✓ | ✗ | ✗ | 按单独权限 | ✗ | ✗ |
| 编辑成员 | ✓ | ✓ | ✓ | ✓ | ✗ | ✗ |
| 空间管理员 | ✓ | ✓ | ✓ | ✓ | ✓ | ✗ |
| 空间所有者 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓（需重新认证） |

* 空间管理员**不能**授予平台权限，**不能**访问其他空间。
* 「下载/导出」与「读」分开：只读成员能看预览不等于能把文件带走。
* 最后一名所有者受保护，不能被移除/降级到无人拥有。

### 4.3 授权的默认

* **默认拒绝**。没有明确匹配的规则即拒绝。
* 工作空间由**可信认证上下文 + 当前有效成员关系**确定，不由请求参数确定。
* 每一次读/写/删/关联/导出/下载都做**对象级**判断，批量操作**逐个**判断。

## 5. 必须覆盖的旁路

引入授权时最容易漏掉的不是主表，而是派生物。下列每一项都要有授权，且缓存键必须包含身份/空间：

原文件 · 工作副本 · 解析结果 · OCR 文本 · 缩略图 · 页面图 · 预览产物 · 搜索与自动补全 ·
错误详情 · 统计计数 · 任务事件流 · 产物下载 · ZIP 打包 · 结果清单 CSV · 签名链接 ·
blob id 直取接口 · 临时文件 · 日志导出

> 具体端点清单由 `entry-points` 调查产出后逐条勾选，见 §9。

## 6. 任务快照与撤权

任务在提交时固定**数据与配置版本**（已实现），但**不固定权限**。必须在以下时点用执行身份的
**当前**资格重新判定：排队转运行、重试、崩溃恢复、访问关键资源、发布产物。

| 事件 | 对运行中任务 | 对已产出产物 |
|---|---|---|
| 成员被移出空间 | 停止新执行 | 该身份不再可访问 |
| 账户停用 | 停止新执行 | 不可访问 |
| 空间冻结 | 停止新执行 | 按冻结策略 |
| 机器密钥吊销 | 停止新执行 | 该密钥签发的链接失效 |

取消时记录「已完成」与「未完成」范围，避免半成品对外发布。

## 7. 文档处理隔离

解析器处理攻击者可控文件，按不可信代码对待：限制文件系统可见范围、网络、CPU/内存/时长；
每任务独立临时目录并在成功/失败/取消/崩溃后清理；不把数据库凭据或主密钥暴露给解析进程。
已实现的公式计算保留，但外部工作簿/网络引用、宏、DDE、PDF 脚本不得自动执行或联网。

## 8. 审计

敏感变更记录：操作者（用户或机器身份）、空间、当时权限范围、动作、对象、结果、时间、请求 ID。
**不记录**密码、令牌、TOTP 种子、恢复码、文档正文。审计写入与被审计的操作保持事务一致；
审计通道故障时按风险拒绝或持久排队，不静默丢弃。普通管理员没有改写/删除审计的入口——
但同库的一张可写表**不等于**不可篡改日志，本文件不做这种声称。
