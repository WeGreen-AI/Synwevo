## 0. 首要目标与不可误解的定义

目标是把 Synwevo 建成一个由独立、可复用、可自动化调用的业务应用组成的平台，并提供属于每位用户自己的全局个人 Agent。

本轮必须交付：

1. Synwevo Forms：表单与资料收集。
2. Synwevo DataPrep：数据清洗、校验、匹配与转换。
3. Synwevo Approvals：人工审批、确认与决定。
4. Synwevo Extract：文件信息提取与人工复核。
5. Synwevo Tables：结构化业务数据管理。
6. Synwevo Agent：类似 ChatGPT 的个人对话应用，可调用本人在多个工作空间内获授权使用的全部应用。
7. 以上应用与现有 Docs、Message、统一身份、工作空间、权限、API、任务与事件机制的真实集成。

“独立”指应用具有明确业务边界、可直接打开的完整界面、业务记录、权限、输入输出和生命周期，不依赖用户先创建一个自动化流程才能使用。独立不强制意味着新仓库、新账号、新数据库、微服务或新域名。

“可复用”至少包括：同一业务能力由界面、API、自动化和 Agent 复用；同一份已发布模板/规则被多个流程引用；每次执行都有独立的身份、输入、状态、结果和审计。不得为了复用模板而混用客户数据或执行状态。

“自动化优先”意味着从第一轮就实现真实、类型明确的操作接口和事件，而不是做完 UI 后再补一套与界面行为不一致的 API。

“个人 Agent”归用户本人所有，不归某一个组织或单个工作空间所有。用户无需建立多个 Agent 或不断重开会话，就能在一次对话中查询、比较并操作其多个工作空间内的应用。

“所有工作空间中的所有应用”指：发现并使用该用户拥有有效权限的空间、应用和资源；它不意味着 Agent 获得超级管理员权限。必须真正支持合法的跨空间任务，不能为了省事强制每个会话只能访问一个空间。

“世界顶尖”是贯穿产品、交互、可靠性、性能和交付的质量目标。将它转化为明确验收，不能用夸张自评替代证据。

## 2. 先核查现场，再开始第一个完整交付

首次运行完成有针对性的现场调查：

- Git 分支、HEAD、未提交 diff、未跟踪文件、其他正在运行的开发/部署任务。
- 实际技术栈、启动方式、数据存储、文件存储、队列、实时通信、任务状态、身份与权限。
- Docs/Message/Accounts/工作空间/Admin/API 的已实现能力、回归风险和可复用模块。
- CI/CD 的触发分支、环境、构建、测试、迁移、产物、部署步骤、健康检查和恢复流程。
- 模型、OCR、邮件、对象存储等实际已配置的服务；只核实配置是否存在与可用，不输出密钥。
- 当前关键页面及首要错误；区分原有缺陷、本轮引入缺陷、尚未验证事项。
- 当前自动化编排或调用能力是否真实存在。不要根据“已有 API”推断已有可靠流程引擎。

建立简短的能力差距与验收矩阵：需求编号、现状、依赖、实施位置、验收、证据和状态。选择技术方案时继承成熟实现，避免无必要换框架、拆微服务或引入同类依赖。

可并行使用子任务负责调查、独立模块、视觉审查和安全审查。明确文件所有权或使用独立 worktree；协调者负责共享契约、合并、迁移、集成与发布。禁止多个任务同时修改同一套迁移或部署同一环境。

研究应服务于实现。参考 ChatGPT 类对话体验、成熟表单工具、OpenRefine 类数据处理、Airtable/Baserow 类数据管理、审批系统和自动化工具的公开资料。每个关键参考记录来源、日期、借鉴的具体行为、适配理由及验证方式，不抄品牌或根据外观臆造内部架构。完成必要调查后直接实现，不长期停留在竞品研究。

## 3. 应用共同架构：一套业务能力，多种使用方式

### 3.1 应用与能力注册

沿用或建立轻量的应用能力注册机制，描述：

- 应用 ID、展示名称、入口、对象类型、支持的操作、权限与版本。
- 每项操作的稳定 ID、输入/输出 schema、所需权限、目标对象、副作用、错误契约。
- 操作是同步还是异步，能否取消、能否重试、幂等策略及耗时/费用边界。
- 应用产生的事件及其 payload/schema 版本。
- 哪些操作适合被 Agent 发现和调用；哪些是管理专用或必须满足人工决定规则。

优先生成或共享契约与适配器，避免 UI、API、Agent 各自维护不一致的验证和权限代码。自动化节点和 Agent 工具是调用入口，业务规则留在应用服务中。

新应用注册后，应能按用户权限进入应用目录、搜索和 Agent 工具发现；不要为每个应用另写一个聊天机器人或硬编码大量条件分支。不要把整个代码库、任意 SQL、系统 shell 或平台管理员 token 作为“全能工具”交给模型。

对外提供真实、经过验证的 API 说明；有现成规范时沿用，HTTP 接口可用 OpenAPI，结构化工具契约使用明确 schema。MCP 适配只有在当前接入需求和授权下才加入，不作为完成本任务的额外前置条件。

### 3.2 统一的业务对象与版本

每个应用至少具备适用的：

- 配置/模板：草稿、校验、发布版本、停用、归档。
- 执行/请求：owner、workspace、来源、模板版本、输入引用、参数、状态、结果。
- 文件/产物：稳定资源引用、版本、内容类型、来源、大小、访问权限。
- 审计：实际操作者、委托者、空间、动作、资源、时间与结果。

已经发布并被运行引用的版本不可原地改写。修改后发布新版本；运行始终固定具体版本及输入快照或可验证的版本化引用。旧版本停用与已有运行的关系必须明确。

模板跨流程复用；跨空间复制或共享必须验证权限、重新绑定成员/字段/连接器，不夹带真实提交数据、凭据、隐藏链接或旧空间 ID。导入后验证所有依赖。

### 3.3 统一的执行与自动化契约

- 长任务返回运行 ID；支持查询状态、查看产物、错误定位、适用的取消与恢复。
- 任务状态至少区分排队、执行中、等待输入、等待审批、成功、部分成功、失败、取消；具体枚举按真实架构统一，不用一个成功布尔值掩盖等待和失败。
- 任务上下文明确绑定 user/delegation、workspace、app、resource、config version、correlation ID；不能复用浏览器可变的“当前空间”变量。
- 副作用操作支持按业务作用域定义的幂等键。同一键参数变化时拒绝或显式冲突；不同合法运行可以重复处理相同文件，不能只因文件哈希相同误去重。
- 幂等覆盖重复请求、消息重复投递、worker 重启和网络超时。对外部写入结果不明时先对账，不能盲目重试造成重复发送。
- 使用现有队列与持久化机制；需要时采用事务事件表等可靠模式，避免业务成功但事件永久丢失。接受现实的重复投递并去重，不宣称任意外部系统的绝对 exactly-once。
- 有限重试、退避、超时、死信或人工处理出口；重试与重新运行、重新评估、补偿必须有不同语义。
- 分页、游标、批量上限、异步队列、资源配额、取消与部分失败都有真实行为，不能默默截断。
- webhook 具备签名验证、重放防护、订阅授权、投递记录与受控重试；对自定义回调目标落实网络边界与 SSRF 防护，不允许访问云元数据和未授权内部端点。
- 事件携带来源和因果关联；设置必要的重复触发、递归深度及运行预算限制，避免 Tables 更新触发流程后再次无限更新自己。
- 原有 Docs/Message 通过兼容适配器加入这套契约，不另造一套文档生成或发消息业务。

如已有流程编排能力，优先扩展。若缺少，建立满足本轮实际链路的持久化编排能力：有参数的步骤、结果映射、条件分支、失败处理、等待/恢复、定时或事件触发、取消和执行历史。先跑通真实流程，不额外扩张为一个无边界的通用低代码平台。

人工审批或填表等待期间不占用常驻模型进程；重启后继续。区分“固定业务流程的确定性执行”和“Agent 根据结果选择工具”，二者共用底层运行与权限机制。

## 4. Synwevo Forms：完整的数据采集应用

独立页面至少包括：表单库、编辑器、真实预览、发布与版本、填写请求列表、填写页、提交详情和补件记录。

必须交付：

- 文本、数值、金额、日期时间、选择、布尔、文件与重复明细等适合业务采集的字段；稳定字段 ID，字段改名不破坏映射。
- 必填、格式、范围、跨字段条件、条件显示与服务器校验。明确隐藏字段的保留/清除/提交规则，防止旧隐藏值流入业务。
- 草稿恢复、分步填写、预填、发布版本、一次或多次提交策略、截止时间、关闭和撤销。
- 通用公开表单和带身份/有效期的专属资料请求分清楚；公开入口不能泄露他人的预填或提交。
- 附件真实上传、权限和有效状态检查。限制格式、大小、解压规模等资源消耗；存在扫描服务时真实调用，不存在时不得标“安全扫描通过”。
- 逐项或按修订要求补件，保留原提交、审阅意见、修改历史与最终确认结果。
- 字段与附件结果可被 DataPrep、Tables、Docs 和 Agent 正常读取；提供真实资源链接。

自动化至少能创建填写请求、传入预填值、查询提交、关闭请求；发出正式提交、补件提交、过期等明确事件。保存草稿不等同于正式提交，正式提交后需要业务审核的也不等同于已批准。

验收包括：两种方式（界面/API）创建请求、断线恢复、重复提交、过期/撤销访问、版本固定、附件失败与补件；每次有独立请求 ID 和结果。

## 5. Synwevo DataPrep：可复用的数据处理应用

独立页面至少包括：数据导入、工作表与范围选择、处理方案编辑、前后预览、逐行错误定位、运行历史和结果导出。

必须交付：

- 真实读取 CSV/XLSX 及现有可用记录集；声明支持的编码、分隔符、工作表、数据范围与规模。
- 类型转换、清理空白、拆分/合并字段、过滤、排序、去重、多源追加、关联匹配、聚合与规则校验。
- 可复用处理方案，步骤可检查、排序与参数化；方案草稿和发布版本独立。
- 样本预览使用实际选定样本并明确范围；正式执行处理整个声明范围，不能拿前几行的成功代表全量成功。
- 数据异常分为可继续的行级问题与必须终止的结构问题，输出完整错误清单、统计和可追溯结果。
- 金额精度、标识符前导零、空字符串/null/缺失、日期/时区、重复匹配、多对多合并与排序稳定性有明确规则。
- 表格公式明确采用缓存值、受支持计算还是拒绝；不暗中运行 Excel 宏。导出处理公式注入风险。
- 规则表达式必须受限，不让用户表达式或模型输出变成任意 Python/JavaScript/shell/SQL 执行；有代码能力时必须是独立受控沙箱。
- 大文件按当前规模选择流式、分块或受控队列，明确资源限制；不把整个文件无限堆入内存。

自动化输入为数据引用、方案版本和参数，输出为结果引用、行数、异常、执行与来源信息。相同固定输入、参数和确定性方案应可重现；如果引入外部非确定性步骤，单独标明并记录版本与来源。

验收包括真实多源合并、重复与空值、精度、坏行、大文件边界、worker 中断、重跑、取消和导出；不得用静态 JSON 冒充处理结果。

## 6. Synwevo Approvals：可独立工作的审批中心

独立页面至少包括：审批模板、我的待办、已发起、已处理、请求详情、审批意见、影响内容和完整时间线。

必须交付：

- 顺序审批、并行会签/或签、条件路由，规则准确可解释。
- 退回补充、最终驳回、撤回、转交/委托、超时提醒与升级，状态含义不能混用。
- 对审批依据建立业务快照、版本与必要哈希，展示提交后改变了什么。
- 依据发生实质变化时按规则建立新修订并重新审批，不能沿用针对旧内容的决定。
- 发起、读取、决定、转交和模板管理分别鉴权；审批人候选范围受实际成员与权限限制。
- 审批人与发起人分离等业务约束可以表达并在服务端执行；Agent 不能绕过。
- 到期和人员离职有明确处理路径；没有有效审批人时等待修正，不自动批准。
- 多人最后一票、批准与撤回竞争、重复点击、迟到事件、重试都通过事务或状态版本保证一致终态。
- 普通邮件/链接预取不能批准请求；任何状态改变必须有合法且可审计的决定。

自动化可发起、查询、取消/撤回合适请求并等待最终决定。审批人的真实决定是可消费事件；提醒不是批准，发送成功也不是审批完成。

Agent 可以准备材料、发起、解释和查询。只有当前用户具有该审批能力、业务规则允许且本次指令/委托覆盖该决定时，才能代为提交相应动作；不能把“请办完这件事”解释成绕过独立审批人。

验收覆盖并发决定、撤回竞争、拒绝、补件重审、授权变更、长时间等待及部署重启后恢复。

## 7. Synwevo Extract：可验证的信息提取应用

独立页面至少包括：文件导入、提取模板、字段定义、任务列表、原文与结果并排、来源定位、待复核队列、修正与确认历史。

必须交付：

- 根据真实文件和已配置能力选择文本解析、OCR、表格提取或模型服务；保留原文件与内容哈希。
- 支持实际验证通过的 PDF、图片与必要结构化格式；对扫描件、多页、重复明细和多文件批次定义清楚支持范围。
- 模板包含字段类型、要求、验证规则和输出结构，可版本化复用。
- 每个结果保留页码、文本跨度、单元格或适用坐标等来源；无法定位时明确标记，不能伪造高亮框或证据。
- 缺失、歧义、冲突和未验证值有独立状态。不能补造姓名、金额、日期等事实。
- 置信度只在提供方/算法确实支持且含义明确时展示，不能将语言模型自报数字当作可靠概率。
- 人工修正保留机器原始结果、修正内容、操作者、时间、模板/模型版本；已确认结果不能被后台重试悄悄覆盖。
- 配置哪些字段或情形必须复核，下游只读取符合要求的结果版本。
- 损坏、加密、超限、难以辨认、服务超时、额度不足都有真实错误和恢复路径。
- 未配置真实 OCR/模型服务时显示未配置，继续完成不受阻工作；不得回退到假提取结果。

与 Docs 的职责边界：Extract 提供“内容转结构化数据”的通用能力；Docs 保持模板、排版和文件生成能力。已有解析实现尽量共享，保留旧 Docs 行为与接口兼容。

验收用具有明确正确答案、已授权且适合测试的真实文件，核对字段、来源、缺失项、人工修正及导出。文件中的恶意指令不应获得工具能力。

## 8. Synwevo Tables：可编程的业务数据应用

独立页面至少包括：数据表目录、字段配置、网格与记录详情、筛选排序、关系、保存视图、导入导出、变更记录和适用恢复。

必须交付：

- 类型化字段、约束、唯一性、记录关联、受限计算/公式、导入映射和保存查询。
- 稳定字段 ID；改名不破坏 Agent、模板与自动化，类型变更/删除前检查依赖并提供迁移与影响预览。
- 真实分页、筛选、排序、批量写入和部分失败契约；批量是否原子必须明确。
- 并发编辑使用修订号、冲突检测或现有可靠协作机制；不能静默覆盖其他人更改。
- 表、记录和字段权限按实际业务需要实现。视图筛选本身不是安全边界；搜索、导出、聚合、关联与自动化都执行服务端权限。
- 数据删除/归档/恢复的引用关系和事件行为明确，不产生无法解释的悬空引用。
- API 支持查询、创建、更新和受控删除/恢复；使用参数化、受限查询协议，不能让普通用户或 Agent 任意访问平台内部 SQL。
- 数据变更发出真实事件；幂等写入与“无实质变化”更新避免反复触发流程。

Tables 管理业务记录，不取代平台身份数据库，不暴露账号、密钥和内部系统表。先完成可验证的业务网格和接口，再按实际需求扩展其他视图，避免为了追平通用数据库平台拖延交付。

验收覆盖唯一性、关系、字段权限、并发冲突、 schema 变化影响、分页、批量失败、撤权及事件去重。

## 9. Synwevo Agent：个人拥有的全局对话与执行应用

### 9.1 产品形态

实现一个正式的、可独立进入的个人 Agent 主界面，同时提供在各应用内便捷唤起的入口。主界面应具备类似 ChatGPT 的直觉体验，并符合 Synwevo 品牌：

- 会话侧栏、新建、搜索、重命名、归档/删除与历史恢复。
- 中央流式对话区，舒适的内容宽度、可读排版、代码/表格/引用和附件显示。
- 输入区支持多行、附件、上下文资源选择、停止生成与明确错误恢复。
- 工作空间/应用范围选择器，能够在一段会话中选择多个空间，也可按任务发现有权资源。
- 可展开的执行卡片：目标、当前步骤、正在调用的应用、目标空间、等待状态、结果与重试/取消。
- 可点击的真实产物卡片：文档、表单请求、记录、审批和消息，打开时再次鉴权。
- 对需要确认的实际写入显示具体变更、来源、目标、收件人和影响；不让用户批准抽象的“执行一些操作”。
- 关联现有页面时保留会话和任务状态，侧栏/抽屉切换不能创建重复运行。
- 桌面高效操作，移动端完成聊天、查看产物、确认与审批；复杂编辑器可明确提供适配布局。

以真实服务器事件驱动流式显示与执行状态。用户滚动阅读历史时不强行拉回底部；提供明确的新内容提示。支持中文输入法组合状态，回车行为、附件上传和键盘快捷键正确。

重新生成或编辑旧消息可以产生新的回答分支，但不能自动重放已经成功的写入/发送/审批等副作用。重新执行必须创建清晰的新运行或使用既定幂等恢复语义。

### 9.2 个人归属与跨工作空间权限

- Agent、个人会话、个人偏好和个人配置绑定稳定 user ID，不借用任一组织 workspace 来伪装个人所有。
- 业务记录仍归目标工作空间；个人 Agent 发起的操作不会把所有成果自动变成个人私有资产。
- 个人会话默认仅本人可见；工作空间管理员仅凭空间治理身份不能读取完整个人会话或其他空间内容。
- 对应工作空间保留必要的业务操作审计，记明真人、委托执行、应用、对象和结果；审计不得夹带其他空间正文或个人模型密钥。
- Agent 可以在一次会话中读多个有权空间并写入明确目标，不能以“安全”为理由取消合法跨空间能力。
- 每次搜索、工具调用、实际资源读取与结果展示均由服务器鉴权。过滤工具目录只是体验优化，不是唯一安全措施。
- 多空间同名对象或目标含糊时先解析、提供候选；仅在不能安全确定时问最少必要问题。目标确定的正常任务直接执行。
- 跨空间复制/发布要核对来源读取及必要导出权限、目标写入、组织数据流策略和目标可见者。两边都有读取权不代表可以向任意目标公开。
- 已经明确授权且策略允许的跨空间任务不重复请求相同许可。新的目标受众、范围或动作实质变化时再校验。
- 人工确认和任务授权绑定服务端保存的运行、操作、目标资源、受众、关键参数及依据版本；提交副作用前再次比对。实质变化使原确认失效，不能由模型替换参数、扩大受众或重复利用一次确认执行新的动作。

### 9.3 真实模型和工具运行

- 接入实际可用的模型提供方，复用现有服务/配置模式；模型名称与能力由真实配置和官方文档决定，不硬编码虚构未来模型。
- 至少一条真实模型、工具调用、产物返回的链路通过验证。缺少密钥时记录具体阻塞，不能使用模拟回答通过验收。
- 提供方凭据在服务端保管并适当加密，前端与日志不返回完整密钥。
- 个人模型配置和工作空间允许的数据处理提供方政策分别校验。用户自备密钥不等于可以把所有组织数据发给任意服务。
- 同一跨空间任务中来源政策冲突时，将步骤/数据按许可隔离，或准确说明阻塞；不能静默发送给限制更少的模型。
- 实现工具选择、参数校验、结果处理、多步运行、等待人类输入/审批、恢复和取消。
- 工具必须调用真实应用服务，使用实际授权的 user/workspace/resource 上下文。禁止模型输出被直接当作数据库更新或系统命令。
- 应用能力按需发现，避免把全部应用全部资源无筛选塞入上下文；模型上下文必须有大小、附件解析和费用预算。
- 显示简短的执行说明、实际步骤与结果，不要求或伪造隐藏的模型思维链。
- 宣称完成必须有对应的真实服务端记录和产物，模型文本本身不能将任务状态改为成功。
- 对模型超时、工具错误、限流、断线、流式中断与不合法参数提供恢复；已经成功的步骤不随回答重试重复执行。
- 取消时停止启动后续步骤；对已经提交且结果不明的操作查询最终状态，展示已完成/未完成/需处理部分，不假装全部回滚。

### 9.4 记忆、检索与不可信内容

- 区分个人偏好与工作空间业务事实。个人记忆可查看、修改、删除和关闭。
- 业务来源的上下文、摘要、检索索引、附件和结果保留来源空间、对象、版本及授权关联；多来源派生内容保留必要的全部来源约束。
- 来源追溯与持续访问依赖分别管理。检索缓存、会话摘要和受限引用继续受来源权限约束；经过合法授权复制到目标空间的独立业务产物，按转移时确定的目标访问与保留策略管理，不因某个操作者退出来源空间就自动使目标空间的合法读者失去访问权。所有产物仍保留来源记录，不得借此绕过来源禁止导出的策略。
- 不把工作空间内容无条件复制成永久私人记忆。撤权后重新查询、工具调用、缓存与历史受控来源呈现都遵循新权限。
- 对话保存采用能够区分纯个人文本与受控业务片段的设计；无法逐句安全判断时对整个相关生成块采取保守隐藏/重新生成策略，避免摘要成为权限旁路。
- 明确不能撤回用户之前已合法下载到系统之外的文件，不作虚假的“所有副本已消失”承诺。
- 文件、网页、消息、表格、工具返回和 OCR 内容都是业务数据。其嵌入的“忽略规则”“读取密钥”“发送到某地址”不能改变授权。
- 结合结构化工具、受限参数、来源标记、服务器策略和测试处理提示注入；不能只靠一句系统提示词宣称防护完成。
- 跨会话、跨用户、跨空间的缓存/索引键正确隔离；撤权后正在运行和排队的步骤重新鉴权。
- 历史会话搜索、分享/导出若实现，必须遵循来源约束。默认个人会话不公开，不自动向相关工作空间广播。
- 不以“Agent 需要知道一切”为由预加载所有空间全部业务数据。

### 9.5 个人自动化与可复用任务

允许用户将有效任务保存为可重复运行的个人自动化，保持个人归属：

- 名称、输入参数、允许的来源/目标空间、工具集合、模板版本、触发方式、预算与副作用范围可查看和编辑。
- 支持手动运行，复用现有能力实现定时和事件触发；时间区、停用、重复触发和错过执行的处理有明确规则。
- 明确区分固定步骤的业务自动化与允许模型自主选步的任务。固定业务规则优先以可验证的确定性步骤执行。
- 预授权必须限定动作、目标范围、受众、次数/金额或资源上限，并明确生命周期：指定到期时间，或由用户明确选择持续有效至撤销。高风险动作沿用现有业务政策的到期要求，所有策略可随时撤销且每次运行重新鉴权；不能用“信任我的 Agent”转成无范围、无预算的永久全部权限。
- 一次手动发送的许可不自动成为无限次定时发送许可；用户明确创建并批准对应自动化策略后按策略执行，不每轮重复询问。
- 每次启动和关键步骤前核实委托权限；停用用户、退出空间、撤销授权或取消任务后及时停止未执行步骤。
- 没有组织背景权限的个人自动化不在用户离职后继续替组织运行；组织长期流程如需服务身份，使用现有经批准的受限机制。
- 提供个人任务列表、运行历史、失败原因、暂停/恢复、取消和结果入口。
- 本产品后台任务必须由项目实际部署的队列/调度/运行服务处理，不能由 Claude Code /loop 承担。

## 10. UI、操作、动画与产品完整性

每个应用必须有专业且一致的界面，不是把同一张空 Dashboard 换六次标题。优先保证信息层级、编辑效率、可读性和真实反馈。

### 10.1 统一设计基础

- 复用或完善设计令牌：字体、字号、间距、颜色、边框、阴影、圆角、状态色、层级与动效。
- 共享导航、面包屑、应用切换、工作空间识别、搜索、命令面板、筛选、表格、编辑器、确认、空态和错误组件。
- 与现有白蓝品牌及正式 Logo 一致；避免大面积无意义渐变、玻璃效果、装饰图表和过度卡片化。
- 普通产品界面使用业务语言；数据库、队列、工具 schema 等实现细节放在适当诊断或技术文档中。
- 个人 Agent 清楚标为个人应用；业务操作卡片标出实际目标空间。
- 简繁英术语、布局、复数/日期/时间/数值格式适配，用户输入保持原样。

### 10.2 完整交互

- 设计正常、加载、无数据、无权限、未配置、验证失败、部分成功、失败、超时、取消和断线恢复状态。
- 编辑器自动保存状态真实；适合的编辑支持撤销/重做。真实发送或外部写入不伪装成可撤销。
- 支持关键快捷键、合理焦点、键盘导航、输入法、触控、长文本与大数据。
- 拖拽提供等价的非拖拽操作；批量行为显示范围和逐项失败。
- 只对确实可撤销且风险低的操作采用合适乐观更新，失败可恢复；审批、权限变化和不可逆副作用依据真实确认结果。
- 能一屏完成的事情不强迫用户经过多层无意义弹窗；必要范围与数据去向提示不能为了“简洁”删除。

### 10.3 动效与性能

- 动效表达状态、空间关系和操作反馈；统一曲线、时长与打断行为，不用定时器伪造任务进度。
- 一般交互可从约 120–240ms 的短动效起步，根据真实体验调整；这不是硬性等待时间。
- 支持 prefers-reduced-motion，避免遮挡焦点、滚动劫持、闪烁、长时间阻止交互和昂贵布局抖动。
- 长列表、流式对话、数据网格按需要虚拟化/分页；加载真实内容，避免全页重绘和每个 token 触发昂贵布局。
- 设定并测量当前环境下的关键页面、API、首个响应、批处理与长任务性能预算；记录数据规模、并发和设备条件，不捏造“毫秒级”指标。
- 以 WCAG 2.2 AA 相关要求检查关键流程：对比度、焦点、键盘、标签、错误提示与操作目标；自动检查之外做人工操作验证。

### 10.4 必须在浏览器中验收

启动真实服务，完成用户操作并检查网络、控制台、页面截图和必要录屏。至少覆盖桌面、窄屏和真实长内容；对关键流程检查键盘与减少动态效果。

截图验证布局，操作验证行为；不能只读 JSX/CSS 就宣称 UI 已完成。保存适量前后证据，修复溢出、遮挡、跳动、不可点击、焦点丢失和状态误导。

## 11. 数据、运行与维护要求

- 使用兼容迁移，保护现有用户、空间、Docs、Message 和运行中任务。迁移可重复性、历史数据回填、旧代码兼容和失败恢复真实验证。
- 区分个人拥有对象与工作空间业务对象；所有后台索引、导出、任务、事件、文件路径及缓存都遵循同一隔离模型。
- 严格服务器输入校验；文件名、路径、模板、CSV/Excel、HTML/Markdown、用户公式和 URL 均按对应威胁处理。
- 密钥、口令、访问令牌、个人模型凭据和敏感正文不进入 Git、错误回显或普通日志。
- 对异步任务提供结构化日志、关联 ID、耗时、错误分类与必要指标；用户只看到与解决当前问题相关的信息。
- 对存储增长、失败任务、死信、模型费用和通知量设置可用的限额与维护机制；长期运行不能无限堆积临时文件。
- 备份与恢复使用现有机制；重要结构变更前确认可恢复路径，不把“有备份脚本”当成“恢复已经验证”。
- 自动重试、补偿、管理员重跑和用户重新执行分别审计，不能使用“修复任务”绕过普通权限。

## 12. 分阶段实施顺序

各阶段都要交付可以验证的纵向切片；阶段拆分是实施顺序，不是允许最终只交付一个 MVP。

P0：恢复现场、基线与风险；确认契约、身份与应用边界，确定发布路径和验证环境。

P1：完成共享应用/操作注册、版本与运行记录的最小可靠实现。实现 Forms 的完整独立使用与 API 链路，打通现有 Docs 和 Message，验证一次真实结果。

P2：尽早实现个人 Agent 的真实聊天、身份范围、工具调用、产物返回与运行记录；先调用已完成能力。不得将 Agent 推迟到所有应用结束后，也不得用空工具目录宣称完成。

P3：完成 Tables 与 DataPrep 的独立界面、版本化操作、数据权限和自动化集成，并让 Agent 能真实使用。

P4：完成 Extract 与 Approvals，包括来源复核、长时间等待、重启恢复；跑通完整跨应用业务链路。

P5：补齐各应用完整规格、跨工作空间任务、个人自动化、记忆/检索授权、性能、可访问性、视觉和故障恢复。

P6：回归与发布验证、文档、运维和最终验收。阶段发布使用现有 CI/CD；未通过验收的功能不向普通用户显示为可用。功能开关只能隔离未完成范围，不是隐藏缺陷后宣称任务完成。

允许根据真实代码依赖调整顺序并记录理由，但不能遗漏任何一个新应用或核心能力。

## 13. 必须通过的验收矩阵

为以下场景建立稳定编号和证据。测试用隔离用户、空间与合法测试材料；外部消息发给已授权测试收件人，不能向真实客户随意发送。

### A. 独立与复用

A1. 六个新应用分别可直接进入；用户无需先设置流程即可完成其核心任务。
A2. 同一已发布 Forms 模板用于三个不同流程，产生独立请求、数据、权限与结果。
A3. 模板更新到新版本后，旧运行保持原版本；已发布配置的导入/复制不夹带凭据或业务数据。
A4. UI、API、自动化、Agent 调用同一操作时，权限与结果语义一致。
A5. 旧 Docs/Message/登录/空间切换的关键路径无回归。

### B. 真实跨应用链路

B1. Forms 提交真实测试附件；Extract 提取并核实来源；DataPrep 处理并产出异常信息；Tables 保存待审记录；Approvals 作出真实决定；通过后 Docs 生成实际文件，Message 发送到指定测试会话。
B2. 必填缺失、提取不确定、校验失败或审批拒绝时，流程进入对应状态，不继续伪造成功。
B3. 一项审批等待期间重启服务；恢复后正确继续。同一审批事件重复投递不重复生成或发送。
B4. 中途步骤失败后从安全恢复点继续，能够区分已经完成的副作用与尚未执行步骤。
B5. 并发、重复请求、乱序事件和网络超时不能导致多份意外业务结果；结果不明进入核实状态。
B6. 所有输出可以打开、查询或下载，界面的统计与数据库/业务记录一致。

### C. 个人 Agent 与跨空间

C1. 同一用户在 A 可编辑、B 只读，Agent 可以授权读取并比较两边数据，只向有权目标写入。
C2. 用户明确要求将 A 中可合法转移的数据用于 B 的文档；Agent 正确执行，显示来源、目标和真实产物。
C3. 两个空间有同名表或模板时，正确确定身份；存在写错风险而信息不足时才澄清。
C4. 执行中撤销 B 权限，后续 B 操作停止；A 已完成部分如实保留，仍依赖来源权限的缓存/历史内容按新权限处理；合法转移的独立产物按既定目标策略管理。
C5. 个人会话不会因为关联一个空间而向其管理员或成员自动开放。
C6. 附件、消息或单元格包含恶意指令时，不能扩大工具范围、读取密钥或向未授权目标传数据。
C7. 用户重新生成回答、刷新或重连不会重复发送消息、生成文件或提交审批。
C8. 有效预授权的个人自动化可重复运行，超范围动作被阻止；撤销后不再执行未开始步骤。
C9. 模型断线、工具超时、额度不足和提供方不可用显示真实状态，能恢复的恢复，不能恢复的明确失败。
C10. 平台管理员与普通用户的工具权限不同；Agent 不向普通用户暴露管理密钥或提供管理级 API 权限。

### D. 应用专项

D1. DataPrep 金额精度、前导零、日期时区、多对多合并、空值和异常行符合声明规则。
D2. Extract 每个关键字段有证据或明确“无可靠来源”状态；人工修正与机器结果可追溯。
D3. Approvals 并发批准/撤回、多审批人、内容修订和无审批人场景得到一致结果。
D4. Tables 字段/记录权限不能被搜索、聚合、导出或关联查询绕过；并发写入不会静默丢失更改。
D5. Forms 公开链接、专属预填、撤销、到期与补件不会泄露其他请求。

### E. 工程、体验与发布

E1. 适用的构建、类型、静态检查、单元、契约、集成和端到端检查通过。
E2. 关键流程的浏览器视觉、操作、键盘、窄屏、长文本、加载/错误状态检查通过。
E3. 代表性规模下的性能、配额、取消与超限行为有实际测量。
E4. 测试准确绑定本轮提交，部署产物对应同一已验证版本；上线健康和最小业务冒烟验证通过。
E5. 没有已知未解决的越权、数据损坏、关键业务失败或本轮回归被藏在“完成”状态下。

本轮“无错误”落实为：适用门槛通过、已知问题修复、真实关键路径验证和剩余限制如实记录。不能承诺数学意义的绝对零未知缺陷，也不能通过删测试、禁检查、吞异常、改断言、降低标准或隐藏日志制造全绿。

生产产品禁止 demo、mock、硬编码成功、假数据、假模型、假发送、假审批、假进度、空按钮和不可运行功能。测试可以使用明确隔离的测试数据及故障注入/测试替身，但不得作为生产 fallback，也不能替代真实集成与发布验收。

测试聚焦实际风险和契约，不追求虚假的测试数量；不为低影响文案改动机械编写冗余测试。测试失败时修根因，不用“再跑一次碰巧通过”代替处理。

## 14. Claude Code 持续执行协议

每轮执行：恢复状态 → 选择最高优先级可执行工作包 → 实现真实闭环 → 验证 → 修复 → 集成 → 达到发布门槛时发布 → 更新进度 → 继续下一项。

### 14.1 持久进度

优先沿用仓库已存在的有效机制，没有时建立：

- docs/agent-work/MASTER_PROMPT.md：本轮完整需求与边界。
- docs/agent-work/STATE.md：当前分支/HEAD、正在做什么、下一条具体动作、阻塞、运行环境与最后检查时间。
- docs/agent-work/BACKLOG.md：需求 ID、优先级、依赖、验收及状态；状态区分未开始、进行中、阻塞、已验证、已发布。
- docs/agent-work/EVIDENCE.md：命令结果摘要、测试/截图/CI/发布引用及其提交版本。
- docs/agent-work/DECISIONS.md：少量有影响的架构和产品决定，必要时建立。

仓库有同等文件就复用，不维护两套互相矛盾的真相。避免把重复日志、私密业务数据或密钥提交到进度文件。

在完成工作包、遇到阻塞、准备提交、上下文不足或会话结束前写明可靠断点。下一轮读取记录后检查实际 Git/代码/CI 状态，不因旧状态写“完成”就跳过真实验证，也不重做已经有充分证据的工作。

### 14.2 防重入与并行

对同一工作树和交付循环只允许一个协调者。使用适合当前环境的进程锁/租约或等效机制，记录持有者和活动信息；不要因超出固定时间就删除另一个仍活跃任务的锁。

并行代理负责边界明确的任务，迁移、合并、提交和同环境部署由协调者串行完成。恢复过期锁前核实原持有者已结束，释放时只释放自己持有的锁。

/loop 触发时，如果已有本任务工作仍在执行，检查其真实状态并避免重复启动；不要再创建一个 loop 递归触发自己。

### 14.3 自主推进与阻塞

- 在已授权范围内主动处理合理实现选择，不把普通工程决策逐项退回用户。
- 一项受外部条件阻塞时完成其他可执行工作，不用一个缺失密钥让整个项目停摆。
- 需要用户输入时说明实际缺少什么、影响哪项验收、已完成哪些准备；不要泛泛要求“补充需求”。
- 连续相同失败达到合理诊断阈值时切换有证据的调查方式或记录阻塞，不无限重复同一命令、同一调用或付费请求。
- 有可执行工作时继续，不以“下一步可以做”结束；本轮范围完成、全部余项确被外部依赖阻塞或运行环境必须中断时，保存断点并如实结束当前轮。
- 无待办时不为了制造活动而重构稳定代码、升级所有依赖、频繁部署或新增无关功能。
- 全部验收完成时，保存最终状态并取消本专项对应的重复调度；只取消自己创建且已确认身份的任务，不影响其他循环。全部余项被外部依赖阻塞时，记录具体恢复条件并暂停无意义重复唤醒，提供使用实际进度路径的恢复命令；只有确实需等待的 CI/部署状态才做有界轮询。若当前环境不能主动取消调度，明确告知具体任务标识与取消方法，不能声称已停止。
- 范围内的缺陷修复、关键可访问性和恢复能力可以自主补齐；新增大型产品线、商业模式或付费依赖不得借“必要增加”无限扩张。

### 14.4 简明汇报

持续工作时给出简短的有效进展，不刷屏。每个工作包结束说明：
实际新增的用户能力、关键改动、验证证据、Git/CI/部署状态、具体阻塞和下一项。
严格区分：计划完成、代码完成、已验证、CI 通过、已部署、上线验证通过。未执行的测试或发布不写成成功。

## 15. 推送、CI/CD、部署与恢复

正常推送和必要部署已经授权。按以下方式完成：

1. 读取实际 workflow、分支保护、环境配置、部署与迁移机制，确认哪些 push/PR 会触发发布。
2. 保留并整理当前工作；只提交本任务合理范围内的文件，审查 diff、敏感信息与生成物。不得为“干净工作区”删用户文件或重置他人修改。
3. 运行适用本地门槛，建立可用恢复点；数据库采用兼容迁移，确认新旧应用、worker 与事件版本在发布窗口内可共存。
4. 按既有流程建立分支、提交、推送、PR/集成。已有 PR 和分支可复用；不擅自关闭保护或强推。
5. 跟踪实际提交 SHA 对应的 CI，而不是看旧提交绿色状态。CI 失败读取日志、修复根因、更新提交并重新核对。
6. 走已经配置好的正式 CI/CD 发布；若它自动发布，不重复手工部署。不要另起竞争性的 SSH/容器更新路径。
7. 将目标提交、最终合并提交、构建产物/镜像标识、部署记录与运行版本关联。实际发布对象变化后重新检查对应门槛。
8. 发布后验证健康、静态资源、身份回跳、关键页面/API、worker、迁移和最小真实业务；使用隔离验收数据与受控通知目标。
9. 验证失败暂停后续发布，按现有恢复机制安全回滚或修复，再次验证。数据库不可逆变化不能盲目向后执行迁移或覆盖业务数据。
10. 报告真实 CI/部署链接、提交或版本、已检查路径及未检查原因。没有访问权限确认线上时写“尚未完成上线验证”，不能冒充已上线。

发布是按实际功能和修复需要触发，不是每轮必须发布。纯进度记录、无功能变化或门槛不满足时不制造重复部署。

若存在必须由人批准的仓库/环境门禁，准备好完整可审阅结果后准确说明门禁和来源；不重复请求已经给出的普通部署许可，也不绕过门禁。

- 完成矩阵与仍被真实外部依赖阻塞的条目。外部阻塞的功能不得标“已完成”。
