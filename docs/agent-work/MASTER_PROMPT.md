## 4. 应用共同架构：一套业务能力，多种使用方式

### 4.1 应用与能力注册

沿用或建立轻量的应用能力注册机制，描述：

- 应用 ID、展示名称、入口、对象类型、支持的操作、权限与版本。
- 每项操作的稳定 ID、输入/输出 schema、所需权限、目标对象、副作用、错误契约。
- 操作是同步还是异步，能否取消、能否重试、幂等策略及耗时/费用边界。
- 应用产生的事件及其 payload/schema 版本。
- 哪些操作适合被 Agent 发现和调用；哪些是管理专用或必须满足人工决定规则。

优先生成或共享契约与适配器，避免 UI、API、Agent 各自维护不一致的验证和权限代码。自动化节点和 Agent 工具是调用入口，业务规则留在应用服务中。

新应用注册后，应能按用户权限进入应用目录、搜索和 Agent 工具发现；不要为每个应用另写一个聊天机器人或硬编码大量条件分支。不要把整个代码库、任意 SQL、系统 shell 或平台管理员 token 作为“全能工具”交给模型。

对外提供真实、经过验证的 API 说明；有现成规范时沿用，HTTP 接口可用 OpenAPI，结构化工具契约使用明确 schema。MCP 适配只有在当前接入需求和授权下才加入，不作为完成本任务的额外前置条件。

### 4.2 统一的业务对象与版本

每个应用至少具备适用的：

- 配置/模板：草稿、校验、发布版本、停用、归档。
- 执行/请求：owner、workspace、来源、模板版本、输入引用、参数、状态、结果。
- 文件/产物：稳定资源引用、版本、内容类型、来源、大小、访问权限。
- 审计：实际操作者、委托者、空间、动作、资源、时间与结果。

已经发布并被运行引用的版本不可原地改写。修改后发布新版本；运行始终固定具体版本及输入快照或可验证的版本化引用。旧版本停用与已有运行的关系必须明确。

模板跨流程复用；跨空间复制或共享必须验证权限、重新绑定成员/字段/连接器，不夹带真实提交数据、凭据、隐藏链接或旧空间 ID。导入后验证所有依赖。

### 4.3 统一的执行与自动化契约

- 长任务返回运行 ID；支持查询状态、查看产物、错误定位、适用的取消与恢复。
- 任务状态至少区分排队、执行中、等待输入、等待审批、成功、部分成功、失败、取消；具体枚举按真实架构统一，不用一个成功布尔值掩盖等待和失败。
- 任务上下文明确绑定 user/delegation、workspace、app、resource、config version、correlation ID；不能复用浏览器可变的“当前空间”变量。
- 副作用操作支持按业务作用域定义的幂等键。同一键参数变化时拒绝或显式冲突；不同合法运行可以重复处理相同文件，不能只因文件哈希相同误去重。
- 幂等覆盖重复请求、消息重复投递、worker 重启和网络超时。对外部写入结果不明时先对账，不能盲目重试造成重复发送。
- 使用现有队列与持久化机制；需要时采用事务事件表等可靠模式，避免业务成功但事件永久丢失。接受现实的重复投递并去重，不宣称任意外部系统的绝对 exactly-once。
- 有限重试、退避、超时、死信或人工处理出口；重试与重新运行、重新评估、补偿必须有不同语义。
- 分页、游标、批量上限、异步队列、资源配额、取消与部分失败都有真实行为，不能默默截断。
- webhook 具备签名验证、重放防护、订阅授权、投递记录与受控重试；对自定义回调目标落实网络边界与 SSRF 防护，不允许访问云元数据和未授权内部端点。
- 事件携带来源和因果关联；设置必要的重复触发、递归深度及运行预算限制，避免 Tables 更新触发流程后再次无限更新自己。
- 原有 Docs/Message 通过兼容适配器加入这套契约，不另造一套文档生成或发消息业务。

如已有流程编排能力，优先扩展。若缺少，建立满足本轮实际链路的持久化编排能力：有参数的步骤、结果映射、条件分支、失败处理、等待/恢复、定时或事件触发、取消和执行历史。先跑通真实流程，不额外扩张为一个无边界的通用低代码平台。

人工审批或填表等待期间不占用常驻模型进程；重启后继续。区分“固定业务流程的确定性执行”和“Agent 根据结果选择工具”，二者共用底层运行与权限机制。

必须交付：

- 真实读取 CSV/XLSX 及现有可用记录集；声明支持的编码、分隔符、工作表、数据范围与规模。
- 类型转换、清理空白、拆分/合并字段、过滤、排序、去重、多源追加、关联匹配、聚合与规则校验。
- 可复用处理方案，步骤可检查、排序与参数化；方案草稿和发布版本独立。
- 样本预览使用实际选定样本并明确范围；正式执行处理整个声明范围，不能拿前几行的成功代表全量成功。
- 数据异常分为可继续的行级问题与必须终止的结构问题，输出完整错误清单、统计和可追溯结果。
- 金额精度、标识符前导零、空字符串/null/缺失、日期/时区、重复匹配、多对多合并与排序稳定性有明确规则。
- 表格公式明确采用缓存值、受支持计算还是拒绝；不暗中运行 Excel 宏。导出处理公式注入风险。
- 规则表达式必须受限，不让用户表达式或模型输出变成任意 Python/JavaScript/shell/SQL 执行；有代码能力时必须是独立受控沙箱。
- 大文件按当前规模选择流式、分块或受控队列，明确资源限制；不把整个文件无限堆入内存。

自动化输入为数据引用、方案版本和参数，输出为结果引用、行数、异常、执行与来源信息。相同固定输入、参数和确定性方案应可重现；如果引入外部非确定性步骤，单独标明并记录版本与来源。

验收包括真实多源合并、重复与空值、精度、坏行、大文件边界、worker 中断、重跑、取消和导出；不得用静态 JSON 冒充处理结果。

## 7. Synwevo Approvals：可独立工作的审批中心

独立页面至少包括：审批模板、我的待办、已发起、已处理、请求详情、审批意见、影响内容和完整时间线。

必须交付：

- 顺序审批、并行会签/或签、条件路由，规则准确可解释。
- 退回补充、最终驳回、撤回、转交/委托、超时提醒与升级，状态含义不能混用。
- 对审批依据建立业务快照、版本与必要哈希，展示提交后改变了什么。
- 依据发生实质变化时按规则建立新修订并重新审批，不能沿用针对旧内容的决定。
- 发起、读取、决定、转交和模板管理分别鉴权；审批人候选范围受实际成员与权限限制。
- 审批人与发起人分离等业务约束可以表达并在服务端执行；Agent 不能绕过。
- 到期和人员离职有明确处理路径；没有有效审批人时等待修正，不自动批准。
- 多人最后一票、批准与撤回竞争、重复点击、迟到事件、重试都通过事务或状态版本保证一致终态。
- 普通邮件/链接预取不能批准请求；任何状态改变必须有合法且可审计的决定。

自动化可发起、查询、取消/撤回合适请求并等待最终决定。审批人的真实决定是可消费事件；提醒不是批准，发送成功也不是审批完成。

Agent 可以准备材料、发起、解释和查询。只有当前用户具有该审批能力、业务规则允许且本次指令/委托覆盖该决定时，才能代为提交相应动作；不能把“请办完这件事”解释成绕过独立审批人。

验收覆盖并发决定、撤回竞争、拒绝、补件重审、授权变更、长时间等待及部署重启后恢复。

## 8. Synwevo Extract：可验证的信息提取应用

独立页面至少包括：文件导入、提取模板、字段定义、任务列表、原文与结果并排、来源定位、待复核队列、修正与确认历史。

必须交付：

- 根据真实文件和已配置能力选择文本解析、OCR、表格提取或模型服务；保留原文件与内容哈希。
- 支持实际验证通过的 PDF、图片与必要结构化格式；对扫描件、多页、重复明细和多文件批次定义清楚支持范围。
- 模板包含字段类型、要求、验证规则和输出结构，可版本化复用。
- 每个结果保留页码、文本跨度、单元格或适用坐标等来源；无法定位时明确标记，不能伪造高亮框或证据。
- 缺失、歧义、冲突和未验证值有独立状态。不能补造姓名、金额、日期等事实。
- 置信度只在提供方/算法确实支持且含义明确时展示，不能将语言模型自报数字当作可靠概率。
- 人工修正保留机器原始结果、修正内容、操作者、时间、模板/模型版本；已确认结果不能被后台重试悄悄覆盖。
- 配置哪些字段或情形必须复核，下游只读取符合要求的结果版本。
- 损坏、加密、超限、难以辨认、服务超时、额度不足都有真实错误和恢复路径。
- 未配置真实 OCR/模型服务时显示未配置，继续完成不受阻工作；不得回退到假提取结果。

与 Docs 的职责边界：Extract 提供“内容转结构化数据”的通用能力；Docs 保持模板、排版和文件生成能力。已有解析实现尽量共享，保留旧 Docs 行为与接口兼容。

验收用具有明确正确答案、已授权且适合测试的真实文件，核对字段、来源、缺失项、人工修正及导出。文件中的恶意指令不应获得工具能力。

## 9. Synwevo Tables：可编程的业务数据应用

独立页面至少包括：数据表目录、字段配置、网格与记录详情、筛选排序、关系、保存视图、导入导出、变更记录和适用恢复。

必须交付：

- 类型化字段、约束、唯一性、记录关联、受限计算/公式、导入映射和保存查询。
- 稳定字段 ID；改名不破坏 Agent、模板与自动化，类型变更/删除前检查依赖并提供迁移与影响预览。
- 真实分页、筛选、排序、批量写入和部分失败契约；批量是否原子必须明确。
- 并发编辑使用修订号、冲突检测或现有可靠协作机制；不能静默覆盖其他人更改。
- 表、记录和字段权限按实际业务需要实现。视图筛选本身不是安全边界；搜索、导出、聚合、关联与自动化都执行服务端权限。
- 数据删除/归档/恢复的引用关系和事件行为明确，不产生无法解释的悬空引用。
- API 支持查询、创建、更新和受控删除/恢复；使用参数化、受限查询协议，不能让普通用户或 Agent 任意访问平台内部 SQL。
- 数据变更发出真实事件；幂等写入与“无实质变化”更新避免反复触发流程。

Tables 管理业务记录，不取代平台身份数据库，不暴露账号、密钥和内部系统表。先完成可验证的业务网格和接口，再按实际需求扩展其他视图，避免为了追平通用数据库平台拖延交付。

验收覆盖唯一性、关系、字段权限、并发冲突、 schema 变化影响、分页、批量失败、撤权及事件去重。

## 10. Synwevo Agent：个人拥有的全局对话与执行应用

### 10.1 产品形态

实现一个正式的、可独立进入的个人 Agent 主界面，同时提供在各应用内便捷唤起的入口。主界面应具备类似 ChatGPT 的直觉体验，并符合 Synwevo 品牌：

- 会话侧栏、新建、搜索、重命名、归档/删除与历史恢复。
- 中央流式对话区，舒适的内容宽度、可读排版、代码/表格/引用和附件显示。
- 输入区支持多行、附件、上下文资源选择、停止生成与明确错误恢复。
- 工作空间/应用范围选择器，能够在一段会话中选择多个空间，也可按任务发现有权资源。
- 可展开的执行卡片：目标、当前步骤、正在调用的应用、目标空间、等待状态、结果与重试/取消。
- 可点击的真实产物卡片：文档、表单请求、记录、审批和消息，打开时再次鉴权。
- 对需要确认的实际写入显示具体变更、来源、目标、收件人和影响；不让用户批准抽象的“执行一些操作”。
- 关联现有页面时保留会话和任务状态，侧栏/抽屉切换不能创建重复运行。
- 桌面高效操作，移动端完成聊天、查看产物、确认与审批；复杂编辑器可明确提供适配布局。

以真实服务器事件驱动流式显示与执行状态。用户滚动阅读历史时不强行拉回底部；提供明确的新内容提示。支持中文输入法组合状态，回车行为、附件上传和键盘快捷键正确。

重新生成或编辑旧消息可以产生新的回答分支，但不能自动重放已经成功的写入/发送/审批等副作用。重新执行必须创建清晰的新运行或使用既定幂等恢复语义。

### 10.2 个人归属与跨工作空间权限

- Agent、个人会话、个人偏好和个人配置绑定稳定 user ID，不借用任一组织 workspace 来伪装个人所有。
- 业务记录仍归目标工作空间；个人 Agent 发起的操作不会把所有成果自动变成个人私有资产。
- 个人会话默认仅本人可见；工作空间管理员仅凭空间治理身份不能读取完整个人会话或其他空间内容。
- 对应工作空间保留必要的业务操作审计，记明真人、委托执行、应用、对象和结果；审计不得夹带其他空间正文或任何模型密钥。
- Agent 可以在一次会话中读多个有权空间并写入明确目标，不能以“安全”为理由取消合法跨空间能力。
- 每次搜索、工具调用、实际资源读取与结果展示均由服务器鉴权。过滤工具目录只是体验优化，不是唯一安全措施。
- 多空间同名对象或目标含糊时先解析、提供候选；仅在不能安全确定时问最少必要问题。目标确定的正常任务直接执行。
- 跨空间复制/发布要核对来源读取及必要导出权限、目标写入、组织数据流策略和目标可见者。两边都有读取权不代表可以向任意目标公开。
- 已经明确授权且策略允许的跨空间任务不重复请求相同许可。新的目标受众、范围或动作实质变化时再校验。
- 人工确认和任务授权绑定服务端保存的运行、操作、目标资源、受众、关键参数及依据版本；提交副作用前再次比对。实质变化使原确认失效，不能由模型替换参数、扩大受众或重复利用一次确认执行新的动作。

### 10.3 真实模型和工具运行

- 接入实际可用的模型提供方，复用现有服务/配置模式；模型名称与能力由真实配置和官方文档决定，不硬编码虚构未来模型。
- 至少一条真实模型、工具调用、产物返回的链路通过验证。缺少密钥时记录具体阻塞，不能使用模拟回答通过验收。
- 提供方凭据在服务端保管并适当加密，前端与日志不返回完整密钥。
- 平台模型配置、用户允许的模型范围和工作空间数据处理政策分别校验。平台支付模型费用不等于可以把所有组织数据发给任意服务；兼容保留的 BYOK 也不例外。
- 同一跨空间任务中来源政策冲突时，将步骤/数据按许可隔离，或准确说明阻塞；不能静默发送给限制更少的模型。
- 实现工具选择、参数校验、结果处理、多步运行、等待人类输入/审批、恢复和取消。
- 工具必须调用真实应用服务，使用实际授权的 user/workspace/resource 上下文。禁止模型输出被直接当作数据库更新或系统命令。
- 应用能力按需发现，避免把全部应用全部资源无筛选塞入上下文；模型上下文必须有大小、附件解析和费用预算。
- 显示简短的执行说明、实际步骤与结果，不要求或伪造隐藏的模型思维链。
- 宣称完成必须有对应的真实服务端记录和产物，模型文本本身不能将任务状态改为成功。
- 对模型超时、工具错误、限流、断线、流式中断与不合法参数提供恢复；已经成功的步骤不随回答重试重复执行。
- 取消时停止启动后续步骤；对已经提交且结果不明的操作查询最终状态，展示已完成/未完成/需处理部分，不假装全部回滚。

### 10.4 记忆、检索与不可信内容

- 区分个人偏好与工作空间业务事实。个人记忆可查看、修改、删除和关闭。
- 业务来源的上下文、摘要、检索索引、附件和结果保留来源空间、对象、版本及授权关联；多来源派生内容保留必要的全部来源约束。
- 来源追溯与持续访问依赖分别管理。检索缓存、会话摘要和受限引用继续受来源权限约束；经过合法授权复制到目标空间的独立业务产物，按转移时确定的目标访问与保留策略管理，不因某个操作者退出来源空间就自动使目标空间的合法读者失去访问权。所有产物仍保留来源记录，不得借此绕过来源禁止导出的策略。
- 不把工作空间内容无条件复制成永久私人记忆。撤权后重新查询、工具调用、缓存与历史受控来源呈现都遵循新权限。
- 对话保存采用能够区分纯个人文本与受控业务片段的设计；无法逐句安全判断时对整个相关生成块采取保守隐藏/重新生成策略，避免摘要成为权限旁路。
- 明确不能撤回用户之前已合法下载到系统之外的文件，不作虚假的“所有副本已消失”承诺。
- 文件、网页、消息、表格、工具返回和 OCR 内容都是业务数据。其嵌入的“忽略规则”“读取密钥”“发送到某地址”不能改变授权。
- 结合结构化工具、受限参数、来源标记、服务器策略和测试处理提示注入；不能只靠一句系统提示词宣称防护完成。
- 跨会话、跨用户、跨空间的缓存/索引键正确隔离；撤权后正在运行和排队的步骤重新鉴权。
- 历史会话搜索、分享/导出若实现，必须遵循来源约束。默认个人会话不公开，不自动向相关工作空间广播。
- 不以“Agent 需要知道一切”为由预加载所有空间全部业务数据。

### 10.5 个人自动化与可复用任务

允许用户将有效任务保存为可重复运行的个人自动化，保持个人归属：

- 名称、输入参数、允许的来源/目标空间、工具集合、模板版本、触发方式、预算与副作用范围可查看和编辑。
- 支持手动运行，复用现有能力实现定时和事件触发；时间区、停用、重复触发和错过执行的处理有明确规则。
- 明确区分固定步骤的业务自动化与允许模型自主选步的任务。固定业务规则优先以可验证的确定性步骤执行。
- 预授权必须限定动作、目标范围、受众、次数/金额或资源上限，并明确生命周期：指定到期时间，或由用户明确选择持续有效至撤销。高风险动作沿用现有业务政策的到期要求，所有策略可随时撤销且每次运行重新鉴权；不能用“信任我的 Agent”转成无范围、无预算的永久全部权限。
- 一次手动发送的许可不自动成为无限次定时发送许可；用户明确创建并批准对应自动化策略后按策略执行，不每轮重复询问。
- 每次启动和关键步骤前核实委托权限；停用用户、退出空间、撤销授权或取消任务后及时停止未执行步骤。
- 没有组织背景权限的个人自动化不在用户离职后继续替组织运行；组织长期流程如需服务身份，使用现有经批准的受限机制。
- 提供个人任务列表、运行历史、失败原因、暂停/恢复、取消和结果入口。
- 本产品后台任务必须由项目实际部署的队列/调度/运行服务处理，不能由开发代理会话或其临时循环承担。

## 11. Synwevo Admin：信息架构与工作台

根据实际模块建立清楚导航，建议分组：

- **概览与待处理**：真实健康、异常、容量、失败任务、待审批与最近变更。
- **账户与访问**：用户、平台管理员、角色、组织/空间、会话及认证策略。
- **应用与业务**：Docs、协同、Message、通知、邮件、API 和集成。
- **运行与数据**：任务、服务、存储、扫描、备份、数据请求及恢复。
- **配置与治理**：全局设置、功能开放、域名、品牌、政策、安全规则和审计。

这是组织原则，不要求机械做成同样数量的菜单。避免同一对象出现多套互相矛盾的编辑入口，避免几十项菜单平铺。

必须实现：

- 全局搜索支持允许检索的用户、组织、空间、项目、任务、事件等管理对象。结果遵守字段级与对象权限，不索引全部私聊或文档正文来凑搜索能力。
- 命令面板只触发受权、明确定义的管理操作；高风险动作进入相应确认流程，不是任意 Shell/SQL 执行器。
- 清楚显示当前环境、全局/组织/空间范围。切换范围后列表、缓存、选中项、待保存表单、任务和导出同步更新；旧标签页不能误操作新范围。
- 对象详情具有概览、配置、关联对象、任务、活动/审计等适用视图，可从异常跳到对象，再跳到对应请求或任务。
- 高频列表支持服务端筛选/排序/分页、列显示、合理密度、保存视图、明确的多选与批量动作；保持刷新/返回后的筛选和滚动位置。
- 待处理中心能够真正解决失败任务、异常投递、待审批和风险事件；确认告警不等于修复根因，已读不等于业务已完成。

## 12. 平台权限、最高管理员与可靠恢复

### 12.1 管理员身份与委派

复用现有模型，建立明确的最高管理员以及可委派的运营、安全、运维、支持、审计等能力集合。角色名称可按项目精简，权限必须以真实操作和作用域描述，而非到处写一个不受约束的 `is_admin` 分支。

- 最高管理员能够管理全部平台管理能力、授予/撤销管理员角色、查看有效权限与来源、管理关键配置及恢复机制；新增敏感能力必须显式登记，不静默授给全部旧角色。
- 委派权限区分查看、配置、执行、导出、授权和敏感内容访问；覆盖全局、指定组织/空间/应用、资源、环境与适用时限。拥有某权限不等于能授予该权限。
- 服务端对每个管理请求和实际异步执行校验权限，前端可见性只辅助体验。REST、实时通道、下载、搜索、批量、旧端点和后台任务采用一致规则。
- 角色变更和撤权影响已有会话、缓存与待执行任务；不要只等下次登录。两名管理员并发修改授权时不得互相覆盖或通过竞态移除最后管理员。
- 提供权限解释和受控模拟检查，说明为什么允许/拒绝；模拟不能执行真实业务或泄露无权对象。
- 拥有组织管理权不自动拥有平台管理权；管理员切换租户范围不等于冒充该租户某个用户。

### 12.2 最高管理员初始化、交接与恢复

- 核实现有最高管理员，不按邮箱前缀、姓名、第一个注册用户或前端字段猜测任命。需要初始化时沿用安全的受控服务端流程，使用有时限且不可重放的领取方式，不生成永久通用密码。
- 管理员使用强认证；高风险操作按风险要求近期重新认证。沿用现有 Passkey/MFA 和恢复机制，保护首次设置与迁移，不能把唯一管理员锁在无法完成的 MFA 循环里。
- 最后一个有效最高管理员的停用、删除或降权必须保护；交接前验证接任者能够正常进入并完成必要强认证。
- 建立不依赖故障中的唯一登录/邮件组件的应急恢复路径，受控保管、明确步骤、时限、审计与后续轮换。它是可验证的恢复流程，不是公开接口、隐藏万能账户或关闭全部认证的开关。
- 普通可逆操作直接完成；高风险操作按已有政策使用重新认证、影响确认或双人审批。不要为小团队凭空强制一个永远无法满足的第二审批人，也不能绕过已要求的职责分离。

### 12.3 内容访问、支持与秘密

最高管理员能够治理账户、资源生命周期和系统状态，但管理接口不得回显明文密码、他人的 MFA 种子/恢复码或其他已保存且不应回传的秘密。账户持有人本人设置 MFA、领取一次性恢复码，以及受控初始化中的必要一次性展示，按真实认证流程完成。私聊正文、个人文档、敏感附件的访问需独立权限和明确目的。

确需支持访问时，实现或复用受控授权会话：限定对象、用途、期限和可执行动作，保留真实管理员身份，符合已有用户/组织授权政策，并能撤销和审计。不能静默“登录为任意用户”、代发私信、代签同意或以用户身份改变安全凭据。优先用权限解释、脱敏诊断和受权样本定位问题。

密钥支持设置、连接测试、轮换、撤销与健康查看；默认展示是否配置、指纹/末位、作用域和更新时间。生成型令牌按真实方案仅创建时展示一次，外部凭据安全存储，不能重新回显到前端、日志、审计差异、导出或异常堆栈中。

## 13. 统一管理操作机制

复用现有服务层，建立轻量的类型化操作目录或等效约定，集中权限、验证、执行与审计；不要为此发明通用工作流语言或庞大框架。

每个写操作都要具备：真实动作 ID、目标与环境/租户范围、输入校验、前置条件、权限、风险级别、执行状态、幂等策略、结果、错误恢复和审计关联。UI、API、异步执行使用同一业务规则，不能 UI 安全但直接请求绕过。

### 13.1 清楚且可信的执行过程

采用适合实际动作的状态，例如待确认、待审批、排队、执行中、成功、部分成功、失败、已取消；不要强迫简单同步动作经过无用流程。

- 提交被接受不等于执行完成，服务商接收不等于最终生效。后台应展示真实阶段、可复核结果与更新时间。
- 执行时检查当前权限、资源版本与前置条件。防止确认后资源、范围或权限变化仍按过期内容执行。
- 重复点击、请求超时、确认丢失、worker 重启和重投不重复产生业务副作用；幂等键绑定操作者、作用域和规范化请求，同键不同参数应报冲突。
- 操作结果与审计/事件具有可靠持久关系，采用现有事务/outbox 或等效机制，避免业务完成但永远丢记录。
- GET、预取和邮件安全扫描不触发写入；不能把敏感动作放在点开即执行的链接中。

### 13.2 高风险动作

全局停用、权限提升、大范围导出、永久删除、生产恢复、密钥轮换和大量外发等动作显示目标、影响、不可逆部分和实际恢复条件，按风险执行近期认证与必要审批。

确认和审批绑定操作者、目标集合、参数、环境、版本与有效期；不能只在前端弹一个对话框，或拿旧确认令牌执行另一项动作。预览本身不修改状态、不发信、不扣款。

停用、归档、软删除、永久删除分别定义。权限撤销、消息发送、删除及收费等并非总可撤销，不能一律放一个假的 Undo。

### 13.3 批量操作

明确“选中本页”“选中这些 ID”“选中全部筛选结果”的差别。执行前给出目标集合、数量、例外和影响；大集合使用服务端快照/稳定引用，不在提交时悄悄扩大范围。

支持适用的异步分批、并发限制、进度、逐项结果、失败项重试、可恢复执行与取消。取消默认停止尚未开始部分，已经生效的结果如需补偿必须另行说明并真实执行。部分成功不能标全部成功；重试不能重复邀请、发信、生成、删除或收费。

## 14. 配置中心：修改后必须真的生效

建立一份与实际读取方对应的配置清单。每个字段具有稳定 key、类型、单位、说明、约束、默认值、作用域、敏感性、来源、继承/覆盖规则、当前有效值、版本及生效方式。

- 区分数据库动态配置、环境变量、部署配置、外部服务配置和派生只读状态；不要让一个 UI 开关假装能覆盖部署系统的强制设置。
- 展示全局/组织/空间的继承与覆盖关系，支持恢复继承。列表和详情都能解释最终值来自哪里。
- 保存前校验范围、依赖、格式和冲突；变更支持草稿/差异/适用的预检/发布。简单低风险字段可以直接保存，不强迫所有设置走多层流程。
- 显示“已持久化、待应用、已应用、部分应用或失败”，区分目标配置与各实例实际生效版本。需要重启/重新部署的如实说明并接入受控动作，不写进数据库就宣称生效。
- 使用版本检查防止两名管理员覆盖配置；客户端收到冲突时展示差异并重新提交，不静默最后写入获胜。
- 保留有效历史，配置回滚产生新的受审计版本，不删除变更史；回滚前检查当前依赖和兼容性，不能复活失效密钥或撤销的授权。
- 外部控制台/环境配置与后台状态不一致时，展示漂移及权威来源，并提供有权限的同步路径；不不断覆写导致双方打架。
- 功能开放支持实际需要的全局/组织/空间范围、依赖与紧急停用；已有灰度基础时复用稳定分组。功能资格不等于对象授权，隐藏 UI 不等于禁用接口。
- 上传大小、并发、任务配额、邮件摘要间隔、注册策略等管理值必须有真正使用它们的服务端执行点，并纳入生效验收。

## 15. Synwevo Admin：必须覆盖的管理模块

以下逐项核实并补齐。后台覆盖现有及已要求的业务，不意味着重写所有应用；但管理依赖缺失时必须补齐必要真实服务，不能永久以只读页面代替。

### 15.1 全局概览与运行分析

提供真实用户/组织/空间与应用使用、任务成功/失败、资源容量、队列积压、投递异常、实时连接、风险事件和依赖健康等适用指标。显示定义、单位、时间范围、时区、数据更新时间及完整性。

数据不存在时显示无数据/未接入/暂不可用，不能随机填图、把超时显示为零或用模拟刷新冒充实时。指标可下钻到有权明细或任务；聚合查询限时、分页/预聚合按规模选择，不能拖慢主业务。成本展示区分真实账单和带假设的估算，不凭空显示收入。

### 15.2 用户、账户与登录

支持有权搜索/筛选、账号详情、邮箱验证与机构注册诊断、登录方式、会话、设备、风险、组织关系与管理事件。提供停用/恢复、会话撤销、邀请/安全恢复、必要的账号更正和删除请求处理。

不得显示用户密码或把身份验证状态任意点成已验证。安全恢复依照身份确认流程，验证邮件发送受限流和审计。机构/CUHK 注册排查要区分校验、风控、发信、投递、链接与激活阶段，不能只加域名白名单。

停用/撤权影响已有浏览器会话、实时连接、API 委托与待执行任务；恢复账号不自动复活已撤销的授权。批量停用保护最后有效最高管理员。修复/合并账户只有真实业务确需且关系迁移可验证时才开放，不能简单改外键吞数据。

### 15.3 组织、工作空间、角色与成员

管理组织/空间创建、状态、归档/恢复、所有权、成员、邀请、应用资格、容量和配额。提供自定义角色、有效权限来源、受控交接和批量导入任务。

平台管理、组织管理、空间管理与内容权利分别呈现；归档/恢复和所有权移交处理正在运行的任务、分享与成员关系。保护最后拥有者，角色组合、已分配角色编辑和导入/API 不能提权。

导入沿用真实多格式解析/OCR 流程，支持来源预览、角色映射、差异确认、逐行错误与重试；未知角色不按字符串自动赋权，不创建默认密码。取消任务不谎称撤销已经发出的邀请或生效授权。

### 15.4 应用目录、开放范围与功能策略

管理实际应用的启用状态、入口、展示排序、允许使用的组织/空间、依赖、配额和适用功能开关。主站、工作空间、应用切换器及直接接口遵守同一发布结果。

停用应用不删除业务数据；说明已有用户、进行中任务、已发链接和恢复后的行为。组织暂不开放应用，不应影响其其他应用。不能把可见应用卡片当作真实授权机制。

### 15.5 Docs 与生成引擎

提供项目/模板/来源/产物的受权元数据、生命周期、版本、分享、复制审批和任务管理；涉及正文查看或导出时使用独立内容权限。

管理解析/格式/OCR/渲染等实际能力状态、队列、并发、超时、容量、可用字体和失败原因。配置实际支持的溢出/分页策略，不偷偷改用户已选择的模板语义。

可以定位失败样本、取消/重试、处理卡住任务、检查引擎健康与输出版本；重试继续使用固定来源/模板/映射/公式快照，成功样本不重复生成，发布产物前校验完整性和当前授权。不能直接把数据库状态改成成功。

审批复制显示来源授权、目标、固定范围、状态及执行结果；重试不重复创建副本，不把私人凭据、协作房间或未批准内容带入组织。

### 15.6 Docs 实时协同

管理协同服务健康、协议/客户端兼容、房间连接、持久化延迟、积压与冲突错误等必要元数据。提供受控断开异常连接、维护与恢复动作，不默认展示用户每一次输入正文。

恢复历史/快照前明确影响与授权，固定版本并处理在线编辑；恢复作为新变更，不让旧离线队列覆盖恢复内容。服务排空/滚动重启不丢已确认修改，不能用关闭协同或强制全文覆盖来“修复”冲突。

### 15.7 Message 与沟通治理

管理服务状态、会话/群生命周期、群角色、历史规则、附件/语音限制、滥用举报与处置、投递异常、资源配额和已有保留策略。

提供符合真实规则的限制发送、隔离违规对象、群归档/恢复、成员处置及申诉/复核记录。举报可提供受权的必要证据，不把后台变成默认读取全部私信的浏览器。

退群/移除/停用后，活动连接、历史搜索、附件、待发消息与摘要按规则生效；修改历史策略前预览范围，不能扩大私密群旧历史可见性。不得伪造发送、已读、在线或以用户身份改消息。

### 15.8 通知、邮件与发信配置

管理真实事件目录、模板、语言、HTML/纯文本、主题/预览、Logo、变量契约、渠道、用户偏好策略、摘要预算、免打扰和队列。模板支持预览、变量检查、版本、测试、发布与回滚；模板执行不能允许任意服务端代码。

管理已授权的 SMTP/发信服务、多发件域名/地址及路由（存在或有实际配置条件时）、认证状态、TLS、凭据轮换、健康、退信/投诉、限额、失败与重试。域名验证以真实 DNS/服务商结果为准，不能点击即标记通过。

真实测试发信只面向明确授权的测试地址。批量补发排除过期验证码/令牌、重复事件、已撤回通知和无权收件人；外发预览显示受众、数量与内容版本。模板改版不能重发历史事件，SMTP 接收不能宣称收件人已收到。

严格保留私信邮件默认关闭和主动开启聚合摘要规则；发送前复核已读、静音、撤回、权限和偏好，无新未读不反复催发。

### 15.9 API、服务身份、自动化与集成

在平台管理员权限内管理服务身份、合法委托、密钥创建/轮换/撤销、作用域、有效期、配额、调用状态、任务计划、Webhook 端点、签名、投递和失败处理。密钥归属与可访问空间必须来自明确授权。

Webhook 重放和手工重试保持业务幂等，校验当前权限、端点与有效签名，限制 SSRF、重定向和资源使用。连接测试是有边界的真实协议检查，不是任意内网探测器。

提供真实文档与契约版本；轮换支持适用过渡，旧凭据到期/撤销后失效。机器调用不收到浏览器验证码 HTML。尚未接入的供应商明确显示配置缺项，不能显示绿色“已连接”。

### 15.10 文件、存储、扫描与数据请求

管理空间使用、容量、原件/产物/版本关联、隔离队列、扫描器及规则健康、重扫、误报复核、索引状态、保留策略、导出/删除请求和孤立资源核查。

扫描失败、超时、不完整或加密不可检查不能被管理员随手标为安全；复核通过明确策略和真实检查完成。隔离文件不能从原始链接、预览或签名下载旁路，内容安全不替代资源授权。

清理前做引用检查和影响预览，分清个人/组织归属、共享 blob 与缓存。安全导出有受众、范围、有效期、限流和审计；删除请求协调活动任务、索引、缓存与备份保留，不能承诺即时清除所有历史备份。

### 15.11 安全、反滥用、审计与事件处理

管理实际认证/MFA 策略、风险挑战、限流、上传限制、可信代理、已接入 WAF/边缘防护、规则版本、事件、告警及有理由和期限的例外。规则可预检/观察/分批应用，能发现误伤并恢复。

防护在应用服务端和实际多实例生效；不能只改变 UI 文案，不能通过永久绕过全部 API 解决误报。来源 IP 不信任任意转发头，合法 SDK、Webhook、OAuth 与健康检查保持各自协议。

事件处理关联对象、证据、动作、负责人和状态。告警关闭/静音有范围与期限，不删原始事实；后台的安全操作也受审计。

### 15.12 服务、队列、发布与域名

读取真实应用/实例/worker、依赖、版本、健康、资源、任务积压、失败与日志；区分应用健康、依赖故障、部分降级和指标过期。

提供适配已有设施的任务暂停/恢复、失败项重试、worker 排空、受控重启、特定缓存失效和维护模式；动作有对象边界、并发控制与结果复核。保护运行中的任务和实时数据，不给网页进程无限系统权限。

集成现有 CI/CD 的提交、构建、部署和回滚状态；实际支持且已授权时通过受限执行接口触发既有流程，保留分支保护与审批，不自建绕过流水线。

五个正式域名、证书、入口、代理/隧道、回调、Origin、公开资源与旧域兼容必须可诊断。涉及 DNS/云配置写入时采用真实已授权 API 和限制范围；没有凭据就明确只读/受阻，不伪造完成，也不擅改 DNS。

维护模式和全局开关不能切断管理员恢复、必要健康检查、受保护发布和已定义的应急路径。接入高权限运维时使用限定动作与参数的执行机制，不能暴露任意 Shell、SQL、Docker socket 或服务器文件编辑器作为默认后台。

### 15.13 备份、恢复与运维作业

管理实际备份计划、范围、版本、状态、加密/密钥引用、保留、失败与恢复演练；展示真实恢复点与覆盖范围。备份文件存在不等于可恢复。

恢复先选择环境与范围，检查依赖和版本，优先在隔离目标演练并校验数据/权限/产物一致性；生产恢复有写入协调和明确确认。配置回滚、代码回滚、数据恢复分别处理。不得未经确认丢弃恢复点之后的新数据；展示恢复点、预计数据损失和权限回退风险，正式切换按已授权恢复方案执行。恢复后核对/重建撤权状态，轮换必要凭据并撤销旧会话；无法证明安全核对完成时保持受控维护状态，不把旧备份宣传为必然无损恢复。

清理、重索引、重扫和迁移等管理作业具有参数验证、范围预览、幂等、进度与恢复说明；复用真实运维任务，不拼接任意用户输入为服务器命令。备份产物本身也属于高敏感数据。

### 15.14 主站、品牌、政策及其他真实模块

管理适合后台维护的主站文案、三语言内容、FAQ、公告、应用展示、正式 Logo 引用和隐私/服务页面版本。提供草稿、预览、发布、历史和回滚，防富文本/链接注入，验证前台、邮件与缓存实际更新。

保留法律主体、费用、同意记录、数据处理等实质约束；不能由代码自动编造政策或让普通文案角色改变身份/域名/安全配置。正式条款改变时遵守已有生效与同意机制。

仓库已有及本轮明确要求的账单、支付、商业额度与 DeepSeek 供应商必须纳入对应管理范围；已有订阅能力兼容保留。不得创建虚假收入、付款或发票，不擅自确定未获确认的正式零售价、购买无关服务或执行未获授权的真实扣款。

### 15.15 五个新应用、个人 Agent 与收费的管理覆盖

将 Forms 的模板/发布/请求/补件、DataPrep 的规则/输入/异常/运行、Approvals 的模板/路由/超时/决定、Extract 的模型/来源/复核、Tables 的 schema/关系/权限/事件纳入同一管理能力表。管理员恢复任务仍遵循各应用版本和权限，不能把复核结果改成真实提取、把审批状态直接改成批准，或绕过字段/内容权限。

Agent 的能力目录、授权委托、模型路线、队列、任务状态、资源上限与费用治理纳入 Admin；个人会话正文仍保持独立权限。新增付款、账本、价格、退款/争议与提供方治理按收费章节落地，不能只做可视化页面。

## 16. 审计系统必须能够解释实际发生了什么

审计记录至少涵盖可信操作者、适用的委派/支持身份、时间、环境与目标范围、动作、原因、脱敏前后差异、请求/任务/变更关联、执行与最终结果。拒绝、失败、部分成功、取消和异步完成同样有记录。

- 使用服务端产生的身份和时间，不信任前端传入“管理员姓名”。内容默认记录对象引用及必要元数据，秘密与用户正文不落入审计。
- 提供筛选、对象时间线、关联跳转和受限导出，搜索和导出本身同样鉴权并按风险审计。
- 普通管理 API 不得编辑或静默删除操作记录；保留策略通过受控流程管理，不能提供“一键清空我的日志”。
- 为真实审计存储建立与架构匹配的追加写、分权、保留与完整性保护。没有独立存储/校验支持时，不宣传“绝对不可篡改”。
- 审计写入/队列异常有明确策略：高风险动作在无法可靠记录时阻断或进入受控恢复流程，普通只读业务按风险处理；不能悄悄执行所有写入后丢记录，也不能因为监控服务故障锁死全部恢复能力。
- 基础设施级操作者可能超出应用日志的保护范围，说明真实边界；应急操作也应保留并在恢复后核对证据。

## 17. 工程质量与管理面自身的保护

- 后台复用业务服务及一致约束，不通过直接修改数据库字段跳过应用规则。新管理 API 保持类型、错误码、分页、作用域和版本契约。
- 正确处理会话、CSRF、CORS、CSP、点击劫持、输入验证、XSS、SSRF、注入和导出中的危险公式；后台也处理不可信用户名、文件名、日志和模板内容。
- 管理端 API 与敏感响应避免被公共缓存、service worker 或普通用户页面缓存；登出/降权清理前端状态，后端仍作权威判断。
- 控制查询/导出成本、任务并发、配额与有界重试。日志查看可暂停并保持阅读位置，实时连接不重复创建，不能为了监控反而拖垮生产。
- 为每个后台动作登记对业务的依赖；共享服务变化回归受影响应用。新旧客户端、迁移和运行中任务保持适用兼容。
- 不引入默认全权数据库账号、通配云凭据、明文环境文件展示或永久调试入口。后台自身被攻破时也不应自动获得整台宿主机的所有能力。
- 生产使用真实可用依赖和配置。禁止假数据、假 API、假登录、假图表、假扫描、假发送和固定成功；测试替身仅限明确隔离测试，不冒充外部验证。

## 18. API 平台：架构原则与标准选择

采用与当前工程相容的清晰分层：协议入口与契约验证、身份与授权、业务/管理服务、持久化与任务/事件，以及管理配置和可观测性。业务 API 与管理 API 应具有可验证的权限与调用边界，不一定需要两套服务器或数据库。

- 默认完善已有 HTTP API 和 REST 风格契约。GraphQL、gRPC、WebSocket、SSE、MCP 等仅在真实需求与已有能力支持时采用；不为追求“顶尖”同时建设所有协议。
- 网关可以复用已有反向代理和应用能力，只有实际流量、团队或策略需要时引入独立产品；不强制引入 Kubernetes、服务网格或付费 API 网关。
- 服务端和管理 UI 共用业务规则，机器调用不是绕开审批、文件扫描、配额或版本检查的捷径。
- 通过受限管理操作驱动实际组件。路由/上游配置有服务目录、目标白名单、协议校验、版本与影响范围，不能成为任意代理或 SSRF 通道。
- 使用当前工具链支持的稳定 OpenAPI 版本，核查官方规范、验证器和 SDK 生成器兼容性；选择明确版本，不只因规范更新就升级全栈。OpenAPI 版本、Synwevo API 版本、事件版本、SDK 版本和部署版本分别记录。
- 对错误格式可采用 RFC 9457，OAuth 设计核查 RFC 9700 和现有身份服务。采用标准时真实满足契约；保留旧客户端需要的兼容适配，不给旧格式换个名字就宣称合规。
- 研究 Stripe/GitHub 等成熟 API 的契约、幂等、事件和开发体验，只采用对本项目有价值的机制；引用实际资料与访问日期，不复制其产品、定价或基础设施假设。

每项关键选择留下简短理由、代价、兼容策略与验收方式，然后进入实现。不要停在架构报告，也不要每次修正重复开展完整竞品研究。

## 19. API 平台：身份、凭据与授权模型

### 19.1 三种调用身份必须分清

| 身份类型 | 应代表什么 | 必须落实的边界 |
| --- | --- | --- |
| 机器/服务身份 | 被明确授权的程序或集成 | 专用身份、作用域、资源范围、环境、期限、配额与可撤销委托，不能默认成为最高管理员 |
| 用户委托身份 | 某用户授予某客户端的具体能力 | 客户端授权与用户当前有效权限共同约束，保留真实主体和客户端归因，不能索取用户密码冒充委托 |
| 平台管理身份 | 被明确授予的管理员或管理服务身份 | 管理 scope、明确目标和风险策略；业务凭据不能调用管理端点，敏感内容权限独立检查 |

API Key 只是凭据形式，不是权限模型。角色、scope、租户关系、应用资格、对象 ACL、资源状态及委托条件按具体身份类型共同约束请求；不能只校验“存在有效 key”或相信请求中的 `workspace_id`、`role`、`owner_id`。

权限检查覆盖对象、功能和字段：请求不能批量写入角色/所有者等未授权字段，响应不泄露无权字段，搜索计数/预览/下载/错误信息也不旁路。机器字段和权限 ID 保持稳定，不随界面语言改变。

### 19.2 凭据全生命周期

- 复用并完善服务账户、客户端注册、API Key 与 OAuth 等真实机制。管理者选择身份、目标环境、资源范围、scope、有效期和限额，服务端防止越权签发。
- 高熵验证型 API Key 按适合方案保存不可逆校验材料，只在创建时交付完整秘密，后续显示安全标识、末位、创建/最近使用/失效状态。需要再次使用的外部签名或连接秘密采用现有安全加密/秘密存储，不能把“全部哈希”误用到无法工作的场景。
- 秘密不进入 Git、URL、文档截图、审计差异、错误堆栈或访问日志；浏览器调试器不永久保存高权限 key。凭据前缀方便识别，不能仅凭前缀判定环境或权限。
- 支持有明确期限的轮换过渡、撤销、暂停与失效；记录使用情况以识别旧凭据是否仍被调用，不能在轮换时悄悄生成永久重叠权限。
- 定义并验证撤销传播时限，覆盖多实例缓存、长连接、异步执行、下载、历史响应与待发事件。短期 token 不等于可以忽略已发生的撤权；敏感操作执行时再次校验。
- 停用服务身份、用户退组、管理员降权或授权撤回后，派生凭据和任务依照已定义的委托生命周期处理；不能冻结旧权限永久继续执行。

### 19.3 OAuth 与非交互授权

完成项目所需的真实用户委托与机器授权：浏览器/用户授权采用成熟的授权码与 PKCE 等适用机制；服务间认证采用受限服务身份及适合现有设施的标准机制，不自创 token 协议。

确认现有 Accounts 是否真实具备对集成客户端发放授权的能力。接入 Google/Microsoft 登录不自动等于已经拥有完整 OAuth 授权服务器；缺失部分使用成熟维护的实现补齐，并验证注册、授权、token 发放/更新与撤销全过程。

- 校验精确回调、适用的 state/nonce/PKCE、issuer/audience、签名算法、期限及授权范围。公共客户端不伪装成能保密的服务端，不使用隐式流或用户密码收集作为捷径。
- 登录账户与授权某集成访问数据是不同动作；授权页面如实展示客户端、scope 和资源范围，管理员注册客户端不替代用户/组织同意。
- token 更新不能扩大权限；适用的刷新凭据轮换/重放检测、退出与撤销策略按真实客户端风险实现。
- 自动化管理任务可以使用已明确批准、限范围和期限的管理服务身份；不能要求每个普通机器调用都交互式 MFA，也不能把人工高风险审批简单删除。需审批的操作返回可处理状态或使用绑定具体计划的授权。
- 保留最高管理员初始化、强认证、交接与恢复。普通开发权限模型已获本任务授权，不为每项实现反复请示；向真实生产身份新增高权限或扩大真实用户内容访问范围按已有明确授权执行。

## 20. API 平台：API 契约：稳定、一致、可实现

### 20.1 资源与请求/响应

每个对外端点明确用途、所属版本、身份类型、权限、参数、必填/可选/null、默认值、验证约束、结果、错误、副作用、配额和重试规则。资源使用稳定 ID，版本与租户关系准确，不直接暴露 ORM 对象或数据库结构。

- 统一命名、方法、资源状态、日期/时区、长整数/编号、金额/小数、编码和空值语义；保护前导零与精度。机器可读错误码、字段和枚举稳定，用户提示可本地化。
- 写入使用显式字段白名单，拒绝无效类型及不可接受字段；批量赋值不能改变权限、租户、系统状态。决定未知字段的兼容处理并写入契约。
- 避免深层 N+1 和任意字段展开；过滤、排序、搜索与扩展字段有允许集合和成本限制。只返回调用方可见内容。
- 文档声明的操作必须真实实现；实现暴露的稳定端点须纳入目录与相应文档。内部端点也要盘点和保护，但不能无差别导出为公开 API。

### 20.2 HTTP、错误与可追踪性

按行为使用状态码，创建、异步接纳、无内容、认证/授权、冲突、前置条件、校验、限流和服务故障区分清楚。业务失败不能全部返回 HTTP 200；机器接口不返回登录 HTML 或浏览器验证码。

结构化错误包含稳定类型/代码、简短说明、字段错误、可关联 request ID 及适用恢复信息；采用 RFC 9457 时真实匹配其字段语义。不要暴露 SQL、内部地址、秘密、堆栈或无权对象是否存在。

请求关联 ID 由可信入口校验/生成，贯穿服务、任务、事件、Webhook 与审计；客户端可检索自身有权诊断，不能凭 request ID 读取其他租户日志。

### 20.3 分页、一致性与并发

大列表采用稳定且有上限的分页/游标，排序具有确定的次级键。游标绑定必要的范围、过滤和版本，校验篡改、过期及跨租户复用；说明并发增删时是一致快照还是移动视图，不承诺无依据的绝对快照。

适合的可变资源提供版本号或 ETag/条件更新机制，旧版本修改返回明确冲突。PATCH、整体替换、字段清空和删除语义统一，两个客户端同时编辑不能静默覆盖。

Docs 的 REST/API 写入遵守协同编辑的同一版本和操作规则，不能绕过协同引擎直接写整个文档。历史恢复作为受权的新变更，不能让旧队列回写覆盖。

## 21. API 平台：可靠写入、任务与批量处理

### 21.1 幂等与不确定结果

对创建、发送、生成、审批执行等有副作用的写接口定义幂等要求。幂等命名空间使用稳定的环境、租户、客户端/调用方、实际主体与操作标识，并核对规范化请求；同键不同参数报冲突，同键并发只产生一个逻辑动作。不要将可变 token、密钥或当前 scope 集合作为命名空间，轮换凭据不能使同一次逻辑操作重新执行；当前授权独立复核。同一次 SDK 逻辑调用的全部重试保持相同幂等键与业务参数。

- 明确键保留时间、执行中响应、成功/失败响应保留规则、参数校验失败及过期后的行为，和允许的客户端重试窗口相匹配。
- 使用数据库约束/事务、可靠任务与现有锁机制处理竞态，不能只有单进程字典或先查后写。
- 超时意味着结果可能未知；提供稳定 operation/task ID 或有权查询路径，先确认再重试。SDK 不默认对所有 POST 无限重试。
- 返回历史结果前重新鉴权，避免撤权用户通过旧幂等响应拿回私有数据或失效下载链接。幂等不是授权替代品。
- 不把请求内容相同视为同一个用户意图，合法的两次独立操作可以不同；不会承诺网络“恰好一次投递”，应证明逻辑副作用不重复。
- 跨外部服务的副作用明确边界、去重和对账/补偿策略，不用本地事务包装成虚假的跨系统原子性。

### 21.2 异步任务

生成、导出、批量导入、重索引、扫描及长管理操作采用真实任务协议，返回稳定 ID、状态查询位置与可用操作。

明确排队、执行、成功、部分成功、失败、取消等合法转换，提供真实阶段/进度、结构化失败、结果、适用重试和取消；任务接纳不是完成，未知百分比不伪造进度。

任务固定来源/模板/映射/规则等内容版本；身份权限在执行、重试、产物发布和下载时按当前委托规则复核。worker 重启、租约到期和重复投递不会重复发布结果；先完整落盘/校验，再原子发布可用产物。

取消、超时与完成的竞争有明确行为，取消请求不等于已完成部分被撤销。断网后客户端可继续查询，不能依赖原 HTTP 连接持续存在。

### 21.3 批量与大文件

批量 API 明确全成全败还是逐项执行，目标集合固定、有上限且受权；每项有稳定关联 ID、结果/错误和重试规则。大集合异步分批处理，失败项重试不重复成功项，取消如实报告已完成部分。

上传支持与业务规模相称的流式、分片/续传或受控直传，限制接收位置、大小、类型、校验和与完成步骤。上传成功不等于通过扫描，未接纳文件不能进入预览、解析、生成、下载或索引。

下载、Range、导出和预签名 URL 遵守实际存储与授权语义。对要求及时撤权的资源，采用受控下载或等效即时校验路径；直接签名 URL 的有效窗口与撤销限制必须如实说明，不能承诺已发链接全部即时失效。URL 不含长期凭据。

## 23. API 平台：Webhook、事件与自动化联动

交付真实事件目录、受权订阅、端点注册/验证、事件版本、签名、投递历史、暂停/恢复、失败处理和人工重放，并在管理控制台可操作。

### 23.1 事件与交付语义

- 业务提交与事件持久化使用事务 outbox 或适合现有架构的等效机制。不可出现业务已成功却永久丢失完成事件。
- event ID 表示同一个业务事实，delivery/attempt ID 表示具体投递；明确事件类型、版本、时间、环境、租户/对象引用及必要内容。
- 按至少一次尝试、可能重复/乱序设计，明确重试窗口、最大次数、背压、死信和人工恢复。重试耗尽或窗口之外不保证送达，提供事件查询/补偿办法。
- 订阅可按实际业务类型和资源范围过滤；默认最小必要负载。发送、重放、变更目标时复核当前授权，避免退组后仍发出私有快照。
- 事件历史事实与当前资源状态分别表达；接收者可按权限查询现状。不能承诺收回已经交付给第三方的数据。
- 对删除、转移、成员移除等终结事件，在既有保留策略内保留最小事件/墓碑记录与授权关联，按仍有效的订阅、委托和事件接收资格决定投递；不能只因资源已不存在而永远丢失完成事件，也不能借事件恢复已撤销的私有内容访问。

### 23.2 真实性、安全与重试

- 使用成熟签名机制校验原始 payload，包含适用的时间戳、签名版本/key ID 与重放窗口；使用安全比较与真实密钥轮换策略，不自创密码算法。
- 重试与人工重放保留稳定业务 event ID，记录新尝试并使用符合协议的新签名/时间戳；消费者以稳定 ID 去重。说明乱序时的对象版本或重新读取策略。
- HTTPS、目标地址/重定向/DNS 变化校验、网络出口约束、超时、请求/响应大小限制与资源预算防止 SSRF 和任务耗尽；注册时检查一次地址不够。
- 地址验证必须约束实际连接目标及每次重定向，处理 DNS 重新解析/重绑定，不能先检查一个公网地址再连接未经验证的新地址。
- 对平台接收的回调，验签并可靠记录/入队后再确认接纳，后续业务异步处理；不能在尚未持久化前返回成功而静默丢事件。
- 对发出的回调，接收端 2xx 只表示已接受请求，不代表对方已完成业务。仪表盘区分入队、尝试、HTTP 接收与最终业务结果（如协议确实提供）。
- 测试使用已授权的隔离接收端和可识别事件；不向未知地址发送用户数据，不通过“测试回调”扫描内部网络。
- 人工重放不是绕过限流、权限或副作用规则的后门；客户端示例提供验签、幂等消费和故障处理。

## 24. API 平台：限流、配额、用量与可靠运行

区分请求速率、突发容量、并发任务、存储/上传量、文档页数、生成额度、外发数量与真实商业计量；它们不能合成一个含义不明的“API 次数”。

- 根据项目规模在平台、组织/空间、客户端/服务身份、凭据、接口类别和资源成本等实际需要的层级实施组合预算；换 key/IP 不应绕过所属主体总预算。
- 多实例/worker 一致执行，使用原子预留/消耗/释放与适用对账；失败、取消、重试、超时和幂等重放的计数规则明确，不能重复扣业务额度或因为失败不释放而永久锁死。
- 客户端超时、断网或 worker 暂时失联不证明任务未执行；结果未知时保持待核对状态，依据持久结果结算或释放。区分可释放预留、已实际消耗用量及每次请求可能占用的速率预算，避免错误返还或重试重复扣量。
- 速率超限返回适用的 429 和可解释重试信息；硬容量不足、业务额度不足及服务拥塞分别按契约处理，不能把所有配额问题都当作等几秒就能重试。
- 管理端可查看默认/继承/覆盖值、有效值、当前用量、窗口与原因，修改后真正影响入口和任务；不能只改变图表数字。
- 公平调度、队列上限、并发控制与背压按实际规模落实，避免一个租户耗尽所有资源；限流/配置组件故障有明确策略，不能统一无条件放行。
- 用量事件可追踪、去重并与业务任务核对；本轮必须结合 DeepSeek 收费章节交付真实计费业务，不编造价格、收入、付款或账单。
- 合法机器 API、OAuth/Webhook 回调和健康探针保持机器协议，不用浏览器人机验证代替身份与配额。
- 为请求延迟、任务完成、错误、可用性、积压和撤权传播设定适合当前环境的明确目标和测量方式。没有实际证据不宣称任意吞吐量、零故障或某个 SLA。

高权限 token 不进入共享 URL、浏览器长期存储或示例代码。服务端代理型调试器须固定允许的 Synwevo API 目标，不能携带凭据请求任意网址。普通集成者取得业务文档或 SDK，不因此获得管理控制台权限。

## 26. 文档、SDK、示例与版本演进

### 26.1 文档与契约一致

选择一份权威契约来源，代码优先或规范优先均可，但必须自动检测漂移。生成并校验 OpenAPI，补齐鉴权、对象/字段权限、限制、错误、幂等、异步、分页、文件和事件说明；不能靠人工维护多份互相矛盾的接口表。

提供集成快速开始、认证/轮换/撤销、Docs 完整流程、Webhook 验签与消费、常见故障、升级说明和真实限制。示例地址来自真实可配置 Base URL，凭据使用明确占位符/安全环境变量；占位凭据是保护秘密，不是允许虚构端点和业务结果。

机器契约字段保持稳定；简繁英说明自然易懂。管理员文档和内部能力按权限隔离，可共享给集成者的资料必须去掉秘密、生产用户数据和未授权管理细节。

### 26.2 SDK 与工具

优先交付与当前项目匹配的 **Python 与 TypeScript SDK**，已有 SDK 则升级，不新建重复包。它们至少覆盖身份配置、业务请求、分页、结构化错误、幂等、任务等待/取消、上传/下载及 Webhook 验签示例；按实际业务能力扩展。

- SDK 包含真实类型、超时、取消/中止、有限退避/抖动与适用的 `Retry-After`，写请求只有满足契约的幂等条件才自动重试。
- 可处理大文件与分页，避免默认全量载入内存；凭据与响应内容不默认打日志。
- 重定向不能把 Authorization、Cookie 等凭据自动转发到不同来源；上传/下载采用明确目标与凭据规则，不能为了兼容而关闭证书或签名校验。
- 生成代码需要包装实际使用体验并完成集成验证，不能只生成文件就宣称 SDK 可用。
- 提供可运行 cURL 和两种 SDK 的完整业务示例，至少一个真实事件接收示例。已有 CLI 则完善；新增 CLI 仅在明确操作需求下复用 SDK，不再实现另一套客户端规则。
- 在干净隔离环境安装/构建并连接真实后端验证。SDK 本地打包可自主完成，公开注册包名和发布到外部 registry 遵守真实发布权限；没有发布不能宣称可从公共仓库安装。

### 26.3 生命周期与兼容

兼容范围包含请求/响应、错误码、分页、权限、默认值、幂等、事件、任务结果和 SDK，不只比较 URL。

破坏性变化使用明确版本/迁移策略，维护变更记录、契约差异检查及旧客户端回归。根据真实调用识别旧版本消费者，显示弃用状态和已确认的退出窗口，不随意编造停用日期。

既有 API 与前端、脚本、worker 保持适用兼容，变更先发布可兼容服务/客户端再清退旧路径。代码回滚与数据库/事件格式回滚分别设计，不让旧版本读取新数据后覆盖或错误重放。

## 27. 可观测性、安全与审计

- 真实监控按端点/版本、环境、客户端和必要租户维度展示请求、错误、延迟、限流、任务、事件、用量与依赖；限制高基数字段，不能把 key、邮箱、文档名、全文 URL 塞进指标标签。

### 28.3 用户、付款方和资源空间分开

每次运行明确保存 actor、delegation、payer、resource workspace，以及对应授权来源。个人 Agent 默认使用当前用户个人钱包；一次会话访问多个空间不自动切换付款方，也不按空间数重复计费。

组织代付必须存在明确的支付授权、范围和预算；成为组织成员或空间管理员不自动获得组织消费权。运行启动固定付款方；更换付款方必须形成可审阅的新授权和预算，不能在用户余额不足时静默使用另一人或组织的钱包。

付款授权、工具权限和数据外发策略分别校验。余额充足、平台 Key 可用或本人付款都不授予空间数据权限。工作空间禁止向 DeepSeek 发送的数据不能因统一模型配置被绕过。撤权、账户停用和支付授权撤销后，未执行步骤重新检查。

### 28.4 钱包、交易账本及精度

以现有支持 ACID 的事务数据库作为资金事实来源，构建追加式、可核对的账本和预留记录。若已有可靠钱包则扩展；不能建立另一个与现有余额独立变化的系统。ClickHouse 等分析库只能用于异步报表，不能承担余额核验或最终扣款决策。

至少区分：支付订单/支付交易、充值入账、赠送额度、资金预留、实际消费、释放、退款、争议/拒付、调整/冲正及提供方成本记录。钱包分币种/单位；真实充值、促销赠送、测试交易和管理员补偿明确分开。赠送有效期、消费优先级及退款归属需有明确政策，不能用过期操作侵占正在有效预留的额度。

资金分录采用平衡的复式记录或已存在且可证明守恒的等效账务模型，同币种/同计量单位分别平衡；财务金额、credits 和跨币种转换不能直接相加。记录唯一业务凭证和关联对象；已入账分录禁止编辑/删除，纠错通过冲正和新分录。业务账本不冒充已获审计的会计财务报表。

金额与 credits 使用明确精度的整数最小单位或定点 Decimal，禁止浮点累加。支付金额最小单位与 token 计费精度分别设计。内部精度足够支持微小调用，累计/舍入位置和规则固定，避免每个小调用向上取整造成异常加价。

已入账余额、有效预留、可用余额分开。可用余额由可消费入账余额减去有效冻结/预留计算；预留不是最终收费。缓存余额必须与账本在同一事务内更新或有等效一致性保障，可由账本重建。Redis 不能成为唯一资金事实来源。

用户收费记录与平台 DeepSeek 成本分别建模。每次真实模型尝试保留必要原始 usage、标准化结果、来源可靠性、提供方 request ID、模型、价格快照、计量时间和关联分录，不存储密钥和非必要私密正文。余额调整不得由前端传入新 balance，也不向模型开放账本写入工具。

### 28.5 定价与用户知情

用户参考中的 1.5x–3x、1 元 = 1000 credits 只是例子，不是已批准的零售价、币种、税率或兑换关系。先核实现有商业配置；没有则实现完整定价配置及计算/预览/发布能力，准备明确的建议方案供用户决定，保持正式收费配置未启用。不要擅自发布任意价格，也不要因为缺商业决定而停止独立开发。

推荐首个正式版本采用一套清楚的预付费方案：内部保留 token 类别，用户可看到余额或 credits、估算范围、授权上限和实际消耗。明确充值货币与金额、到账单位、兑换比率、每类用量价格、精度、退款规则与适用期限，不制造无法解释的积分。

当销售价按每百万 token 定义时，用户费用基础为：

`费用 = (输入未命中量 × 对应售价 + 输入命中量 × 对应售价 + 输出量 × 对应售价) / 1_000_000`

这是一种选定计价方案的公式，不是上游账单凭据。其他真实可收费项目分别列明；缓存别名、总 token 和 reasoning 子项不可再次相加。上游成本按上游实际适用价格独立计算；峰谷时间的时区、节假日、计价时点及跨边界调用规则必须核实，不自行猜测。未能确定的上游成本标明估算，采用保守预算控制，不伪装成精确毛利。

固定运行授权的零售价格表快照或明确约定的有效报价；后续新增调用若超出有效报价条件应重新报价。实际调用绑定适用价格版本。上游价格变动不溯及用户已发生消费；对下一次运行需要变价时按正式规则生效和告知。

无独立定价规则时，普通应用工具操作不额外收取模型 token 费用。真实第三方 OCR、存储或外部工具收费必须另有价格、预算及用量依据。月度订阅赠额、预付费余额和超额收费如同时存在，明确消耗优先级并防重复收费。

### 28.6 调用前预留、运行预算与安全结算

在数据库事务中原子验证钱包可用额度、付款授权、单次/周期预算并创建预留；成功后才向 DeepSeek 发起请求。不能先读余额再让多个并发请求各自扣减，也不能等生成结束才检查能否付款。

每次请求显式限制输入规模、输出上限及适用推理上限。估算覆盖系统提示、会话历史、工具 schema、附件转换文本、检索内容和工具结果，不只计算用户输入。使用可验证的保守费用上界，预留不假定缓存命中；无法可靠确定上界时缩小输入/输出或拒绝启动，不能以“通常不会超支”代替控制。

区分 `run_id`、逻辑模型调用 ID、真实网络 `attempt_id`、业务工具 operation ID。一个 Agent 任务可包含多次真实模型调用和工具动作，每次实际尝试都记录平台成本；用户账单遵循公开规则。限制整个 run 的最大费用、调用/循环次数、并行度和期限，子任务共同计入父运行预算。

每次开始新模型调用、扩大并行或增加付费工具前重新核验并取得预算。父运行总额度与子调用预留使用一个可证明不重复冻结的模型；不足时在安全边界暂停，展示已发生费用和继续所需授权。人工填表/审批等待期间不持续占用模型连接；未发请求的可释放预留及时释放，恢复时重新鉴权和取预算。

数据库事务不得长时间包住外部网络调用。先持久化尝试与 dispatch 状态，再受控发送；使用 owner/lease/fencing 和恢复状态，处理“上游已接收、本地尚未记确认”的不确定窗口。提供方没有真实幂等保证时不能宣称外部调用恰好一次，不能仅因租约过期就再次发送。

收到可信 usage 后，在事务中校验计量、按绑定零售价格结算一次并释放余量。每个结算具备持久唯一约束；重复事件、页面重连、worker 重试和再次展示结果不再次扣费。若提供方实际用量异常超出已授权上限，记录与调查差异，由平台吸收未经授权的超额，不默默把用户钱包扣成负数。

前端可显示估算用量和已预留额度，但只有可信已落库的计量可显示为已结算。流式观察不能成为精确账本，更不能把字符数当提供方 token 数。

### 28.7 中断、未知用量、失败与重试

由持久化服务端运行管理模型连接与计费，浏览器只订阅状态。页面关闭/重连不创建新调用；用户停止时尝试取消上游，并停止后续步骤，但不能声称停止按钮保证上游立刻零费用。

SSE 中断、worker 崩溃、超时、缺失最后 usage 或上游结果不明，进入明确的 `usage_pending/unknown`。保留必要预留并恢复或对账，展示待核实原因；不得按最大预留最终扣费、把估算冒充真实 usage，或立即释放后容许同一模式无限消耗。

仅使用提供方真实存在且验证过的逐请求/汇总对账能力；不要发明“按 request ID 查询精确用量”的接口，也不能从共享账户余额变化推算某个用户的精确费用。提供方没有逐请求恢复能力时，明确技术限制。制定有限的对账期限、异常成本总额阈值和人工处理出口；最终仍缺可靠计量的部分由平台承担并释放相应预留，不无限冻结用户余额。已核实部分可按明确规则结算，已最终释放的未知部分不在未来秘密补扣。

前台重试、用户主动重跑、正常多步推理与平台基础设施故障重试分开。默认平台原因造成的重复成本不重复转嫁用户；用户明确重新执行是新的任务和预算。失败或取消是否对已核实消耗收费，应遵循正式披露政策，不能把失败标成成功来收费，也不能将任何失败都假定上游免费。

恢复计费不得重放已经成功的业务写入；重连、重试和模型切换前查询已落库产物与业务状态。文件生成、消息发送和审批的幂等与账务幂等分别验证。

### 28.8 真实充值、支付回调、退款及争议

优先复用已有支付渠道。没有时，按实际运营主体、支持币种和已有账户条件选择一个真实渠道并完成适配；不要同时做多个空壳渠道。支付商开户/资质、凭据和价格缺失不得伪造，测试模式与正式交易严格隔离。

服务端创建充值订单，固定 payer、环境、金额、币种、兑换版本、到账单位和关联支付对象。客户端只能选择允许的套餐/金额，不能决定到账数或支付状态。优先使用渠道托管支付流程，减少平台接触卡号等敏感资料。

用渠道官方机制验证原始 webhook 负载和签名/适用时间限制；通过验签后先持久化 inbox/事件再确认接纳，业务处理可以异步。依据已验证的支付成功状态，核对商户、环境、订单、币种、金额及实际交易，原子入账。前端跳转成功、截图或用户声称付款不能加余额。

事件去重与支付交易去重都要有持久唯一约束；同一事件重复到达及多个不同事件代表同一付款均只能入账一次。处理乱序、延迟、异步支付失败、重复查询及 worker 崩溃；收到旧成功事件不能复活已退款/争议状态。提供定期对账和可审计补偿，不手改 balance 救火。

退款使用独立订单/状态机、渠道幂等标识和账本冲正。发起退款前原子锁定/预留可退未消费资金，防止它同时被花掉；退款请求受理不等于成功，失败和结果不明分别恢复/对账，不能重复退款或无依据释放。部分退款、手续费和赠送额度分摊按明确政策和渠道能力处理。

拒付/支付撤销发生在余额已消费时仍需保留完整账务差额，使用欠额/争议账户及受限状态阻断新消费；不能把余额截为零抹掉损失，也不能破坏“新消费不超可用资金”的不变量。争议胜诉或撤销通过新的记录纠正。

用户可查看充值、到账、冻结、实际消费、退款和争议状态，下载真实可提供的交易凭证。普通收据不冒充具备税务资质的发票。自动充值默认不启用；已有且用户明确授权时遵守扣款协议、额度及撤销规则。

### 28.9 限流、容量、预算与熔断

将请求速率 RPM、token 速率 TPM、同时在途模型连接数、队列容量、业务额度和资金预算分别建模；它们不是同一个“并发”数字。按用户/付款主体、组织授权预算、模型、平台总成本等必要维度组合控制，换 Key/IP 不绕过主体预算。

突发数千至数万任务应通过有界排队、准入、公平调度和背压处理，不能理解为无条件建立同等数量上游连接。核实实际 DeepSeek 账户级模型配额；多个 Key 不意味着多个独立账户配额，不用轮换账户规避提供方限制。使用受控扩容申请或调整容量。

若沿用此前约 5 分钟最长等待目标，先明确它是入队到开始执行/可见响应的等待预算，而非保证任意多步任务和人工审批在 5 分钟完成。可把队列超时配置为 300 秒的目标起点，按已核实需求调整；到期不再偷偷发送新模型请求，正确释放未使用预留。报告排队、首响应、生成与总完成时间各自指标。

准入应考虑剩余等待时间、在途请求和队列长度；不能明知容量不足仍无限接受。具体容量、P95/P99 和 SLA 以代表性输入/输出、实例数、数据库和上游限制的实际测量为准。应用层替身压测只能证明被测层，不宣称真实模型已经支撑同样吞吐。真实上游压测须有明确费用预算和适用许可，不在生产无上限打流量。

处理提供方 429、超时、429 后重试、连接保活和服务故障。限制重试次数、退避和总费用；SSE keep-alive 不代表已经生成内容。资金数据库不可用时停止新的有费用调用，不能因缓存还有余额就放行；既有结果及必要安全恢复按实际持久状态处理。

设置单次/日周月预算、平台成本总额、异常增长、未知用量敞口、上游余额水位及支付异常熔断。周期使用明确时区和边界，不能通过改时区反复重置。提供方余额只用于账户健康和容量预警，不能冒充用户钱包。

熔断必须真的停止新增有费用操作，同时保留已有调用收尾、用量接收、账务结算、退款/对账、查看与恢复路径。停止新销售、停止新模型调用和停止某提供方路由是不同开关，不能一键切断资金闭环。

### 28.10 模型选择和自动降级

仅在用户/自动化已允许的模型、费用和数据策略内选择可用路线，验证工具调用、上下文、格式、隐私及任务能力。不要把两个指向同一实际模型的别名伪装成两档质量/价格。

余额不足不等于降级后一定有钱；便宜模型仍须成功预留额度。零余额、授权撤销或空间禁止外发时正确暂停。不能为了继续执行自动换付款人、扩大信用或转向未经授权的新提供方。

切换记录请求模型、实际已确认路线、原因和适用售价；在安全步骤边界继续，不重复已成功的副作用，不把旧调用的结果不明简单丢弃。用户未允许变化或能力无法满足时，展示可以选择的真实方案，而不是暗中换模型。

### 28.11 面向用户与管理员的完整计费体验

用户侧至少包含：个人钱包、真实充值/到账状态、已用/预留/可用额度、费用明细、按会话/运行查看调用成本、价格说明、预算上限、低余额处理、暂停/续跑、退款进度与交易凭证。待核实不能显示为已结算，充值未确认不能提前放行。

聊天输入区简洁展示当前付款方、模型选择、必要费用估算和任务上限；普通已授权低风险调用不强制每次弹窗。高额或扩大授权的动作呈现具体预算和范围。长期自动化使用有范围、可撤销的持续授权，触达上限暂停，不每分钟打断用户重新审批。

执行卡片可以展开查看真实阶段、调用、模型及费用，不要求展示隐藏推理。用户已经阅读历史时更新不抢滚动位置。错误、付款取消、支付处理中、网络断开、额度不足、限流和退款失败都有可操作恢复路径。

Admin 新增真实的模型/提供方、价格版本、钱包流水、支付订单、退款/争议、未知用量、平台成本、用户收费、预算/熔断与对账模块。与现有 API 控制中心共用配置/操作/审计能力，不维护第二套全局限额和凭据。

管理员查看消费归因不自动获得个人聊天正文。成本与收入报表区分充值资金流、服务消费、退款、赠送、未结算成本与估算，避免把充值全额叫作已实现利润。未配置指标如实展示，拒绝假毛利、假实时图表。

界面沿用白蓝设计、正式 Logo、简繁英、移动端、键盘与减少动态效果。金额数字对齐、单位明确、舍入可解释；支付和资金结果以服务端为准，不用乐观动画提前宣布到账。必要账务通知与私信摘要分别设计，保留私信邮件默认关闭规则。

### 28.12 条款、数据处理与上线条件

将产品定位为 Synwevo 的付费 Agent 服务。核对实际账户、运营主体和经营地区适用的 DeepSeek 开放平台专项协议、总条款及隐私文件，记录来源/版本/日期和实际适用结论。官方专项协议明确描述下游集成服务；不能一概宣称收费 SaaS 必须另获经销商资格，也不能据此宣称所有裸 API 转售、分发和转许可均已获授权。

本轮不自动扩张为对外出售通用模型代理的经销商平台。若确需该能力，单独核实合同许可边界。不得宣称“官方合作/授权代理”，不得未经允许使用对方品牌背书。只有真实且适用的外部授权缺口阻塞相关上线，不用泛化法律猜测阻止已授权的普通开发。

用户数据会按实际任务流向 DeepSeek及其他已获授权的处理服务；在 Synwevo 政策和产品需要的位置如实说明处理目的、数据类别、提供方、保留、权利处理及实际可用控制。不能把 DeepSeek 面向自身用户的隐私政策当作 Synwevo 的政策，也不能根据聊天产品开关承诺 API 零留存或不训练。核实专属 API 设置/合同后才宣传相应保证。

如接口支持终端用户隔离标识，使用无明文个人信息、范围明确的伪匿名标识，结合个人与空间数据策略设计缓存隔离；它不能替代 Synwevo 自身鉴权。支付/账务保留和聊天删除规则分别明确，不因删除会话而删掉法定或合同要求保留的交易事实，也不为计费长期保留不必要正文。

币种、税务处理、退款、余额有效期和消费者条款以真实主体及目标地区为依据，不根据开发者语言或时区猜测。由有权人员确认实质商业/法律决定，Codex 完成实现、清晰草案和最小决策清单，不编造公司资料、证照、税率或法律结论。

正式启用收费与发布代码分离：缺生产密钥、真实支付能力、有效价格/政策或必要验证时，可以完成其他代码与隔离验证，但正式收费入口明确受控关闭，并报告具体阻塞。官方支付测试环境是验证工具，不是生产假充值；仅测试模式通过不能称正式收款已验证。

### 28.13 计费必须通过的专项验收

建立 BILL-* 验收及证据，至少覆盖：

1. 真实小额模型调用与工具执行，脱敏 usage、价格快照、用户扣费、平台成本和产物可以关联核对；运行中所有调用完整归因。
2. 同一用户跨 A/B 两空间，个人付款方一致，A 可写/B 只读仍生效；组织代付无授权时不能发生。
3. 多 worker 并发争用最后余额，预留不透支；额度争抢与取消/完成竞争结果正确，父子预算不重复冻结。
4. 缓存类别、别名、输出/推理包含关系、峰谷成本记录、价格变更、微小金额累计与舍入无重复计算。
5. 在预留后、发送边界、收到响应后、usage 持久化后、结算提交前后逐点中断；恢复不会重复收费或盲目重复副作用。
6. SSE 保活、断流、缺 usage、客户端重连/取消、worker 重启均进入正确状态；未知用量有限期对账，不能永久冻结或伪造结算。
7. 真实支付渠道端到端测试：金额/币种/环境被篡改、无签名回调、重复/乱序事件及同付款不同事件，不能错误/重复到账；浏览器成功页不加余额。
8. 退款与消费竞争、部分退款、退款结果不明、已消费后拒付、赠送到期及补偿，账本守恒且结果可解释。
9. 单次/周期/平台预算、真实限流、排队过期、熔断和恢复有效；停止新调用不阻断既有结算及退款。
10. 模型降级能力/价格/数据策略正确，别名不产生虚假价格档；余额不足不会换付款方或偷偷赊账。
11. 用户账单、可用/预留余额、账本重建、支付交易与上游用量/成本能对账；差异有状态、负责人和修正流程。
12. 浏览器资源、网络响应、日志、追踪、审计、SDK、下载和错误不泄露上游 Key；越权读取他人钱包/聊天/账单被拒绝。

对账务不变量采用有独立期望的单元/集成及并发故障测试；支付签名测试使用渠道支持机制，真实外部连通和生产冒烟另行记录。测试交易不污染正式指标，不通过屏蔽失败或手改余额制造验收成功。

## 29. UI、操作、动画与产品完整性

每个应用必须有专业且一致的界面，不是把同一张空 Dashboard 换六次标题。优先保证信息层级、编辑效率、可读性和真实反馈。

### 29.1 统一设计基础

- 复用或完善设计令牌：字体、字号、间距、颜色、边框、阴影、圆角、状态色、层级与动效。
- 共享导航、面包屑、应用切换、工作空间识别、搜索、命令面板、筛选、表格、编辑器、确认、空态和错误组件。
- 与现有白蓝品牌及正式 Logo 一致；避免大面积无意义渐变、玻璃效果、装饰图表和过度卡片化。
- 普通产品界面使用业务语言；数据库、队列、工具 schema 等实现细节放在适当诊断或技术文档中。
- 个人 Agent 清楚标为个人应用；业务操作卡片标出实际目标空间。
- 简繁英术语、布局、复数/日期/时间/数值格式适配，用户输入保持原样。

### 29.2 完整交互

- 设计正常、加载、无数据、无权限、未配置、验证失败、部分成功、失败、超时、取消和断线恢复状态。
- 编辑器自动保存状态真实；适合的编辑支持撤销/重做。真实发送或外部写入不伪装成可撤销。
- 支持关键快捷键、合理焦点、键盘导航、输入法、触控、长文本与大数据。
- 拖拽提供等价的非拖拽操作；批量行为显示范围和逐项失败。
- 只对确实可撤销且风险低的操作采用合适乐观更新，失败可恢复；审批、权限变化和不可逆副作用依据真实确认结果。
- 能一屏完成的事情不强迫用户经过多层无意义弹窗；必要范围与数据去向提示不能为了“简洁”删除。

### 29.3 动效与性能

- 动效表达状态、空间关系和操作反馈；统一曲线、时长与打断行为，不用定时器伪造任务进度。
- 一般交互可从约 120–240ms 的短动效起步，根据真实体验调整；这不是硬性等待时间。
- 支持 prefers-reduced-motion，避免遮挡焦点、滚动劫持、闪烁、长时间阻止交互和昂贵布局抖动。
- 长列表、流式对话、数据网格按需要虚拟化/分页；加载真实内容，避免全页重绘和每个 token 触发昂贵布局。
- 设定并测量当前环境下的关键页面、API、首个响应、批处理与长任务性能预算；记录数据规模、并发和设备条件，不捏造“毫秒级”指标。
- 以 WCAG 2.2 AA 相关要求检查关键流程：对比度、焦点、键盘、标签、错误提示与操作目标；自动检查之外做人工操作验证。

### 29.4 必须在浏览器中验收

启动真实服务，完成用户操作并检查网络、控制台、页面截图和必要录屏。至少覆盖桌面、窄屏和真实长内容；对关键流程检查键盘与减少动态效果。

截图验证布局，操作验证行为；不能只读 JSX/CSS 就宣称 UI 已完成。保存适量前后证据，修复溢出、遮挡、跳动、不可点击、焦点丢失和状态误导。

### 29.5 管理与计费页面的细节验收

后台保持专业数据密度、范围/环境标识、配置继承与生效反馈；实时列表不得挪走正在点击的行，日志可暂停跟随。关键结果保留在对象/任务详情，不能只存在短暂 toast。密钥复制、充值、退款、预算更改和配置发布都展示准确结果，不提前报成功。

手机必须能完成聊天、充值、查账、确认、审批和重要管理排障，不能仅压缩桌面表格。图表说明口径、单位、时区、样本量及更新时间；尚无数据、采集延迟和服务失败分别呈现。应用界面用业务语言，管理员必要诊断可呈现技术细节。已有深色主题则沿用验证，不为本轮另造无关视觉系统。

## 30. 数据、运行与维护要求

- 使用兼容迁移，保护现有用户、空间、Docs、Message 和运行中任务。迁移可重复性、历史数据回填、旧代码兼容和失败恢复真实验证。
- 区分个人拥有对象与工作空间业务对象；所有后台索引、导出、任务、事件、文件路径及缓存都遵循同一隔离模型。
- 严格服务器输入校验；文件名、路径、模板、CSV/Excel、HTML/Markdown、用户公式和 URL 均按对应威胁处理。
- 密钥、口令、访问令牌、个人模型凭据和敏感正文不进入 Git、错误回显或普通日志。
- 对异步任务提供结构化日志、关联 ID、耗时、错误分类与必要指标；用户只看到与解决当前问题相关的信息。
- 对存储增长、失败任务、死信、模型费用和通知量设置可用的限额与维护机制；长期运行不能无限堆积临时文件。
- 备份与恢复使用现有机制；重要结构变更前确认可恢复路径，不把“有备份脚本”当成“恢复已经验证”。
- 自动重试、补偿、管理员重跑和用户重新执行分别审计，不能使用“修复任务”绕过普通权限。

## 31. 应用、个人 Agent 与跨空间验收矩阵

为以下场景建立稳定编号和证据。测试用隔离用户、空间与合法测试材料；外部消息发给已授权测试收件人，不能向真实客户随意发送。

### 31.1 A. 独立与复用

A1. 六个新应用分别可直接进入；用户无需先设置流程即可完成其核心任务。
A2. 同一已发布 Forms 模板用于三个不同流程，产生独立请求、数据、权限与结果。
A3. 模板更新到新版本后，旧运行保持原版本；已发布配置的导入/复制不夹带凭据或业务数据。
A4. UI、API、自动化、Agent 调用同一操作时，权限与结果语义一致。
A5. 旧 Docs/Message/登录/空间切换的关键路径无回归。

### 31.2 B. 真实跨应用链路

B1. Forms 提交真实测试附件；Extract 提取并核实来源；DataPrep 处理并产出异常信息；Tables 保存待审记录；Approvals 作出真实决定；通过后 Docs 生成实际文件，Message 发送到指定测试会话。
B2. 必填缺失、提取不确定、校验失败或审批拒绝时，流程进入对应状态，不继续伪造成功。
B3. 一项审批等待期间重启服务；恢复后正确继续。同一审批事件重复投递不重复生成或发送。
B4. 中途步骤失败后从安全恢复点继续，能够区分已经完成的副作用与尚未执行步骤。
B5. 并发、重复请求、乱序事件和网络超时不能导致多份意外业务结果；结果不明进入核实状态。
B6. 所有输出可以打开、查询或下载，界面的统计与数据库/业务记录一致。

### 31.3 C. 个人 Agent 与跨空间

C1. 同一用户在 A 可编辑、B 只读，Agent 可以授权读取并比较两边数据，只向有权目标写入。
C2. 用户明确要求将 A 中可合法转移的数据用于 B 的文档；Agent 正确执行，显示来源、目标和真实产物。
C3. 两个空间有同名表或模板时，正确确定身份；存在写错风险而信息不足时才澄清。
C4. 执行中撤销 B 权限，后续 B 操作停止；A 已完成部分如实保留，仍依赖来源权限的缓存/历史内容按新权限处理；合法转移的独立产物按既定目标策略管理。
C5. 个人会话不会因为关联一个空间而向其管理员或成员自动开放。
C6. 附件、消息或单元格包含恶意指令时，不能扩大工具范围、读取密钥或向未授权目标传数据。
C7. 用户重新生成回答、刷新或重连不会重复发送消息、生成文件或提交审批。
C8. 有效预授权的个人自动化可重复运行，超范围动作被阻止；撤销后不再执行未开始步骤。
C9. 模型断线、工具超时、额度不足和提供方不可用显示真实状态，能恢复的恢复，不能恢复的明确失败。
C10. 平台管理员与普通用户的工具权限不同；Agent 不向普通用户暴露管理密钥或提供管理级 API 权限。

### 31.4 D. 应用专项

D1. DataPrep 金额精度、前导零、日期时区、多对多合并、空值和异常行符合声明规则。
D2. Extract 每个关键字段有证据或明确“无可靠来源”状态；人工修正与机器结果可追溯。
D3. Approvals 并发批准/撤回、多审批人、内容修订和无审批人场景得到一致结果。
D4. Tables 字段/记录权限不能被搜索、聚合、导出或关联查询绕过；并发写入不会静默丢失更改。
D5. Forms 公开链接、专属预填、撤销、到期与补件不会泄露其他请求。

### 31.5 E. 工程、体验与发布

E1. 适用的构建、类型、静态检查、单元、契约、集成和端到端检查通过。
E2. 关键流程的浏览器视觉、操作、键盘、窄屏、长文本、加载/错误状态检查通过。
E3. 代表性规模下的性能、配额、取消与超限行为有实际测量。
E4. 测试准确绑定本轮提交，部署产物对应同一已验证版本；上线健康和最小业务冒烟验证通过。
E5. 没有已知未解决的越权、数据损坏、关键业务失败或本轮回归被藏在“完成”状态下。

本轮“无错误”落实为：适用门槛通过、已知问题修复、真实关键路径验证和剩余限制如实记录。不能承诺数学意义的绝对零未知缺陷，也不能通过删测试、禁检查、吞异常、改断言、降低标准或隐藏日志制造全绿。

生产产品禁止 demo、mock、硬编码成功、假数据、假模型、假发送、假审批、假进度、空按钮和不可运行功能。测试可以使用明确隔离的测试数据及故障注入/测试替身，但不得作为生产 fallback，也不能替代真实集成与发布验收。

测试聚焦实际风险和契约，不追求虚假的测试数量；不为低影响文案改动机械编写冗余测试。测试失败时修根因，不用“再跑一次碰巧通过”代替处理。

## 33. API、SDK 与联动端到端验收

准备隔离但真实的数据库、存储、队列和接收端，以及最高管理员、受限管理员、普通用户、两组织/空间、业务服务身份和管理服务身份。UI、API 和 SDK 均验证，不能仅在前端或单元测试中模拟结果。

### 33.1 场景 A：外部脚本完成真实文档生产

创建限定空间/动作凭据 → 上传真实授权样本 → 查询安全接纳 → 创建/复用版本化模板、区域与映射 → 预检 → 提交批量生成 → 查询状态并接收签名事件 → 下载产物 → 读回数据、数量与版式。

注入并发同键提交、短时断网、确认丢失、worker 重启、回调失败/重复/乱序；验证一个逻辑提交不会重复生成业务结果，任务可恢复、成功项不重复执行、失败项可重试。Python 和 TypeScript SDK 都实际走通其覆盖链路，不依赖浏览器人工补步骤。

### 33.2 场景 B：管理员操作真实改变调用行为

在后台创建限定客户端和凭据 → 成功调用允许的业务 → 跨空间、超 scope、写保护字段、调用管理 API 均被正确拒绝 → 修改配额并观察真实限额 → 轮换凭据 → 撤销旧凭据与委托 → 验证缓存、活动连接、排队操作、幂等重放及结果下载按明确规则生效。

后台能够按 request ID 查到脱敏调用、配额原因、任务与审计；新的有效凭据和其他合法租户仍正常工作，不能用全站停机证明“撤销有效”。

### 33.3 场景 C：审批复制、消息与事件联动

来源所有者通过 API 申请固定项目快照复制到目标组织 → 目标有权者审批 → 执行前重新检查 → 生成独立副本 → 使用获批或独立授权输入生成 → 产生真实对象卡片/通知与受权事件。

未批准、已撤回、目标变化或审批人撤权不能继续复制；副本不带私人凭据或原协作房间，重复回调不重复执行。发送连续私信仍不逐条发邮件，收到卡片不自动获得文档权限。

### 33.4 场景 D：受控管理自动化与恢复

限定管理服务身份提交真实低风险配置变更 → 根据契约预检/审批 → 发布并查询生效 → 两客户端并发修改触发版本冲突 → 按适用规则回滚 → 核查业务与审计。

业务身份不能执行该动作，过期批准不能改参复用；管理服务降权后旧任务不越权执行。全局开关/维护不锁死最高管理员恢复。高风险破坏性恢复在隔离目标演练，不拿真实用户数据作演示。

## 36. 推送、CI/CD、部署与恢复

正常推送和必要部署已经授权。按以下方式完成：

1. 读取实际 workflow、分支保护、环境配置、部署与迁移机制，确认哪些 push/PR 会触发发布。
2. 保留并整理当前工作；只提交本任务合理范围内的文件，审查 diff、敏感信息与生成物。不得为“干净工作区”删用户文件或重置他人修改。
3. 运行适用本地门槛，建立可用恢复点；数据库采用兼容迁移，确认新旧应用、worker 与事件版本在发布窗口内可共存。
4. 按既有流程建立分支、提交、推送、PR/集成。已有 PR 和分支可复用；不擅自关闭保护或强推。
5. 跟踪实际提交 SHA 对应的 CI，而不是看旧提交绿色状态。CI 失败读取日志、修复根因、更新提交并重新核对。
6. 走已经配置好的正式 CI/CD 发布；若它自动发布，不重复手工部署。不要另起竞争性的 SSH/容器更新路径。
7. 将目标提交、最终合并提交、构建产物/镜像标识、部署记录与运行版本关联。实际发布对象变化后重新检查对应门槛。
8. 发布后验证健康、静态资源、身份回跳、关键页面/API、worker、迁移和最小真实业务；使用隔离验收数据与受控通知目标。
9. 验证失败暂停后续发布，按现有恢复机制安全回滚或修复，再次验证。数据库不可逆变化不能盲目向后执行迁移或覆盖业务数据。
10. 报告真实 CI/部署链接、提交或版本、已检查路径及未检查原因。没有访问权限确认线上时写“尚未完成上线验证”，不能冒充已上线。

## 37. 资金系统特有的发布与恢复要求

以下要求与统一 CI/CD 章节共同执行：

- 模型路由、零售价、支付渠道、正式收费开关和账务 schema 的变更分别留有版本与审计；不能把 push 成功等同于正式收款可以启用。
- 对迁移、worker 排空、旧运行/预留、待支付 webhook、使用中的价格版本、账本幂等键和 outbox/inbox 做兼容验证。新旧代码共存时不能双重结算，旧进程不能覆盖新状态。
- 代码回滚不回滚已经发生的真实资金事实。恢复数据库备份前，先暂停新消费和受恢复影响的资金写入，隔离旧 worker，保护恢复窗口。恢复期间将已验签支付事件可靠暂存在不会被本次恢复覆盖的位置，或返回可重试失败让渠道重试；未可靠持久化不能确认接纳成功。恢复后先与外部支付交易、已有结算和业务产物对账，恢复最新可靠账务及撤权状态，再分阶段恢复事件处理与消费。不能因恢复旧余额让同一资金再花一次或再次充值入账。
- 恢复试验优先使用隔离环境。不得为了演示恢复覆盖真实用户新数据；正式切换遵循既有授权、写入协调及可复核恢复计划。
- 上线后在已有授权和明确费用范围内完成最小真实 DeepSeek 调用、计量、工具产物和账务复查。支付生产小额收款/退款由有权测试付款方按明确金额和范围完成；未经实际收款不能称生产支付验证通过，不能替用户擅自使用未授权支付方式。
- 观测调用错误、队列、未结算预留、未知 usage、账本差异、充值/退款状态、上游余额、成本异常和新版本回归。出现资金异常优先停止新增风险，保留结算与对账能力。
