# 模型价格版本治理

本模块管理成本价和销售价的草稿、精确试算、发布及历史复制。`billing_prices` 仍是账本和网关读取的唯一价格事实；没有预置售价、币种、余额、兑换率或生产商户。

## 管理操作

Accounts 的「模型价格」使用现有平台管理角色。`platform.config.view` 可读和试算；`platform.config.manage` 可编辑。发布另外复用当前管理操作的近期认证、五分钟签名预览、理由、幂等结果和事务审计。组织/空间角色不授予这些权限。

部署通过 `SYNWEVO_BILLING_ENVIRONMENT=test|live` 明确选择环境；未设置或无效时返回未配置，禁止写入。环境在进程启动时固定，前端不能切换。设置这个变量**不会开启付费模型调用或充值**。测试和正式交易不可混用；单位代码的精度是全局固定的定义，两个环境不能给同名单位赋予不同精度。

| 接口（前缀 `/api/admin/billing/prices`） | 行为 |
| --- | --- |
| `GET /` | 草稿/已发布版本列表，`before` 游标和 1–100 条分页 |
| `GET /drafts/{id}` | 当前环境的版本详情 |
| `POST /drafts` | 保存完整 `spec`，创建幂等键绑定原始输入；同键改参冲突 |
| `PATCH /drafts/{id}` | `expected_revision` 检查并发；已发布版本拒绝编辑 |
| `POST /drafts/{id}/calculate` | 指定三个用量分类，返回精确金额；不发送模型请求、不入账 |
| `POST /drafts/{id}/preview` | 只读预览，绑定当前草稿、操作者、源站、环境与期限 |
| `POST /drafts/{id}/publish` | 原子写入不可变价格、发布来源、审计和唯一操作结果 |

这些是当前管理会话接口，仍需 CSRF 和管理权限；不是已开放给普通 API Key 的管理能力。双 SDK 的受限管理调用尚待统一管理机器身份契约。

`spec` 包含名称、用途、提供方、已确认路线标识、单位/精度、三类费率、政策或证据引用、生效时间及可选的历史价格引用。名称是操作者输入，不自动翻译。引用不接受 URL 查询参数或凭据。填入路线名称/引用不构成提供方路线验证证据，也不会自动把路线加入运行配置。

## 金额和历史

三类费率均为**每百万 token 的主要单位金额**，通过十进制字符串提交。单位精度 `scale` 定义钱包整数一单位的实际价值：`10^-scale` 主要单位。费率转换为最小单位的精确分数；试算同时返回分子/分母字符串，避免浏览器大整数精度丢失。

试算的 `charge_units_if_no_prior_remainder` 只是无历史小数余量时的整数部分。真实消费在同一付款账户、价格版本下累计小数余量，不对每个微小调用单独向上取整。缓存别名、总 token 和输出内部 reasoning 不再次收费。成本和销售各自固定价格、单位，不直接相减冒充利润。

已发布价格和来源记录禁止更新、删除或替换。复制历史价格创建新草稿，以新价格 ID 和生效时间再次发布；旧运行继续读取其固定 ID。过去生效日期只是元数据，不授权追溯修改账单。价格生效不表示已应用到某个节点：运行仍须经已确认路线、当前数据权限、明确用户预算、钱包预留与平台成本控制。

发布中的审计失败会一起回滚价格、单位登记、来源及操作结果。相同请求重试返回既有结果；权限或认证被撤销后，即使重试也重新拒绝。不同操作者/源站/环境/草稿/修订不能复用预览。

## 分时价格（高峰 / 低谷）

DeepSeek 的人民币价目表分高峰与低谷两档（低谷为高峰的一半）。价格 `spec` 可带可选的 `off_peak`
（三类低谷费率，均不得高于同类高峰费率）；此时三项基础费率就是**高峰**费率。没有 `off_peak` 的价格是
统一费率（flat），存储形状与之前完全一致，已有运行授权（含旧报价与旧同意）照常比较。冻结金额和平台成本准入始终按基础
（最高）费率计算，因此分时价格不会让冻结不足。

**档位只在派发时决定一次。** 账本 `dispatch` 在写入派发围栏的同一事务里，用写入 `dispatched_at` 的同一
时刻（UTC）按当前已发布日历判定档位，并钉在该次尝试上：

| `billing_attempts` 列 | 含义 |
| --- | --- |
| `band` | `peak` / `off_peak` / `flat`（两侧都是统一费率时为 `flat`）；迁移前派发的旧行为 NULL |
| `band_schedule_revision` | 判定所用的日历版本（`flat` 为 NULL） |
| `dispatched_at` | 派发围栏提交时刻（已有列），档位由它决定 |
| `completed_at` | 提供方交换结束时刻：结算时为观测时刻，用量待定时为标记时刻；之后的迟到结算不改写 |

结算按钉住的档位计算成本与售价，与结算时刻无关；之后发布的日历只影响之后派发的调用。触发器禁止改写已钉
的档位、日历版本和 `completed_at`。分时价格若找不到已发布日历，派发在发送前被拒绝（`price_band_schedule_unavailable`），
不猜测档位。官方未说明按开始还是完成计档，因此两个时间戳都保存，对账时可比较。

## 高峰时段与节假日日历

高峰时段和中国法定节假日是**数据**，不是代码常量（`billing/bands.py`，表 `billing_band_schedules`）：

- 高峰时段：星期（ISO 1–7）+ UTC 时间窗 `[start, end)`，最多 14 个；DeepSeek 2026-10-05 公布的周一至周五
  01:00–04:00、06:00–10:00 UTC 只是编辑器的起始值，**数据库不预置任何日历**，须由管理员发布后才生效。
- 节假日：按 UTC+8 的日期登记（中国不实行夏令时），全天为低谷；调休上班日不登记，按星期判断。最多 1000 天。
- 版本只能追加：修订号连续，触发器禁止更新、删除或替换；每次发布带理由、操作者、幂等操作结果和审计，
  预览列出新增/移除/改名的节假日以及时段是否变化。
- 使用分时价格的路线，其路线版本附带日历修订号（`…:bands:<revision>`）。日历一变，绑定旧版本的运行授权在下一次
  模型调用前停止（`billing_model_configuration_changed` / `model_changed`），已完成的调用按原价格结算；之后开始的回答
  自动按新日历计价，聊天页提示价格已更新，用户无需重新确认（2026-10-23 起）；统一费率路线不受影响。

| 接口（前缀 `/api/admin/billing/prices/schedule`） | 行为 |
| --- | --- |
| `GET /` | 当前版本（未发布时 `revision=0, spec=null`）及编辑器起始值 `defaults` |
| `GET /history` | 历史版本，`before_revision` 游标，1–100 条 |
| `POST /preview` | `expected_revision` + `spec`，返回变更摘要和五分钟签名预览 |
| `POST /publish` | 预览令牌、幂等键、理由（8–500 字）；近期认证；与审计同事务追加新版本 |

发布分时价格前必须先有已发布日历（`price_band_schedule_required`）。

## 售价 = 成本价 × 倍率

所有者决定售价由管理员设定的倍率从成本价生成。`PriceMarkups` 以一个**已发布的成本价**为基础，按倍率
（1–100，最多四位小数，不允许低于成本）生成一个新的、不可修改的销售价版本（写入 `billing_prices`，来源写入
`model_price_markups`，快照内记录 `basis`）。分时成本价可另设低谷倍率（省略则同高峰倍率），低谷售价不得高于高峰售价。

| 接口（前缀 `/api/admin/billing/prices/markups`） | 行为 |
| --- | --- |
| `GET /` | 已发布的加价售价，含各档售价表 |
| `POST /preview` | 返回成本价与售价的各档费率表、每 1000 token 的示例成本与售价，以及该模型上一次加价售价 |
| `POST /publish` | 与价格发布相同的签名预览、理由、幂等和审计 |

发布加价**不改变任何路线**。路线在「模型提供方」中采用新售价（`sale_price_id`）时，路线版本变化：之后开始的回答
按新售价计费，正在进行的回答在下一次模型调用前停止，聊天页提示价格已更新，用户无需重新确认；同一路线只能把加价售价配在它自己的成本基础上（`model_price_markup_basis`）。
“按路线”的倍率即按路线所用的成本价/模型发布；不同档位可用不同倍率。

报价（`agent.billing.offer`、`agent.billing.status`）以及兼容保留的单次运行报价和持续同意在 `rates`（高峰/统一）之外返回
`off_peak_rates`（统一费率时为 `null`），Agent 输入框旁与 Agent 设置中显示两档价格与每条回答的最高金额。

## Admin 界面

「模型价格」页：价格草稿可选择“统一费率 / 分时（高峰与低谷）”，记录、详情和示例试算同时显示两档；下方是
高峰时段与节假日日历编辑器（星期与 UTC 时段、对应的 UTC+8 时间、按日期范围添加节假日、预览变更、填写理由发布、
历史）和售价加价面板（选择已发布成本价、倍率、可选低谷倍率、预览示例费用、填写理由发布、已发布列表）。三种语言，
窄屏下表格在自身容器内滚动，页面不横向溢出。

## 发布状态

代码与隔离测试不等于正式收费已启用。真实商业主体、收费币种、退款/税务政策、已批准零售价及支付商户尚待确认；路线/成本适用条件与钱包报价授权仍待接通。此模块没有更改任何生产价格或运行中的用户账单。

## 契约与当前验证

输入与输出由 Accounts 路由的严格类型生成 OpenAPI schema，费率始终为十进制字符串；版本和用量不接受布尔或字符串隐式转换。校验错误仅返回固定拒绝信息，不回显请求体。业务仍通过 PriceCatalogue 和同一账本价格事实执行。

隔离后端36项价格测试通过，包含并发、撤权竞争、审计回滚、精确小数、公开类型与恶意输入脱敏。Accounts类型检查、23项前端测试与构建通过。2026-09-30隔离页面服务健康正常，但内置浏览器返回ERR_BLOCKED_BY_CLIENT，价格页面的实际视觉、键盘与窄屏操作尚未验收；不能据此宣称UI交付或正式收费通过。
