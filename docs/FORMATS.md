# 格式能力矩阵（逐项验证）

本表只把**有自动化测试覆盖**的能力标为「✅ 已验证」。经 LibreOffice 转换才能处理的格式标为「🔁 转换」并在界面上提示可能的损失；有限支持标为「⚠️ 部分」；未实现标为「❌」并给出原因和替代路径。界面中的「格式能力」页面（`/capabilities`）由服务端按当前环境实时生成（例如未安装 LibreOffice 时相关项会显示「缺依赖」）。

测试位置：`backend/tests/`（引擎单元测试、验收场景 1–14、格式覆盖测试）与 `scripts/ui_e2e*.py`（真实浏览器操作）。验证环境：macOS 27 / Apple Silicon，Python 3.14，LibreOffice 26.8，Tesseract 5.5。

## 2. 各格式的规则与限制

### CSV
* 只有记录和字段。界面把它显示为网格、可框选，但 **CSV 输出不会保留任何排版**。需要排版请使用 XLSX 模板或文档模板。
* 编码：BOM → UTF-8 → GB18030 → charset-normalizer 猜测；出现无法解码字符时在文件上提示；可在「CSV 设置」中改编码与分隔符后重新解析（生成新的来源版本，旧预览失效）。

### XLSX
* **公式（内置公式引擎，`backend/docweave/engine/formula.py`）**：
  * 读取来源时优先取文件中保存的计算结果（与 Excel 最后一次计算一致）；没有保存结果的公式（例如脚本生成的文件）由内置引擎计算后使用，并在文件上注明。
  * 生成输出时，引擎在服务器上计算工作簿中**全部公式**并把结果写入文件（`<v>` 缓存值），因此 WPS、预览器、CSV 导出、其他程序读取时都能看到正确值；同时删除 `calcChain.xml` 并设置 `fullCalcOnLoad`，Excel 打开时仍会按自己的规则重算。
  * 支持 97 个常用函数：数学（SUM/SUMIF(S)/SUMPRODUCT/ROUND 系列/INT/MOD/ABS/POWER/SQRT/PRODUCT/CEILING/FLOOR…）、统计（AVERAGE(IF/IFS)/COUNT(A/BLANK/IF/IFS)/MAX/MIN/MEDIAN/LARGE/SMALL）、逻辑（IF/IFS/IFERROR/IFNA/AND/OR/NOT/XOR/SWITCH/CHOOSE）、查找（VLOOKUP/HLOOKUP/XLOOKUP/INDEX/MATCH/ROWS/COLUMNS）、文本（TEXT/CONCAT(ENATE)/TEXTJOIN/LEFT/RIGHT/MID/LEN/FIND/SEARCH/SUBSTITUTE/REPLACE/TRIM/UPPER/LOWER/PROPER/REPT/EXACT/VALUE/T/N）、日期（DATE/YEAR/MONTH/DAY/EDATE/EOMONTH/DATEDIF/DAYS/WEEKDAY/HOUR/MINUTE/SECOND/TODAY/NOW）、信息（IS* 系列、NA）；运算符含 `& = <> < <= > >= + - * / ^ %`、跨工作表引用、整列引用、定义名称；错误值（`#DIV/0!`、`#N/A`、`#VALUE!`、`#REF!`、`#NUM!`、`#NAME?`）按 Excel 规则传播。
  * **不支持时不猜测**：遇到不支持的函数、数组公式、循环引用、外部工作簿引用、INDIRECT/OFFSET 等易失函数时，该公式不写入结果；已安装 LibreOffice 时自动改用 LibreOffice 计算并**只把结果写回**我们的输出文件，未安装时由 Excel 打开时计算。任务结果清单会写明计算了多少公式、哪些改用 LibreOffice、哪些未计算、哪些结果是错误值。
  * 与 LibreOffice 的交叉核对：`backend/tests/test_formula.py` 用同一批公式分别由内置引擎和 LibreOffice 计算并逐一比较。
* **插入明细行**（有 n 条明细时在模板行下方插入 n−1 行）：
  * 本表及其他表中指向下方行的引用、合并单元格、条件格式、数据验证、超链接、自动筛选、表格（ListObject）范围、打印区域等定义名称、图表数据引用、批注与图形锚点全部平移；
  * **末行等于模板行的区域会扩展到全部明细行**（如 `SUM(E5:E5)` → `SUM(E5:E14)`）；条件格式、数据验证和**图表数据系列**中指向模板行的单个单元格也视为明细区域一起扩展；普通公式中的单个单元格引用（如 `=E5`）不扩展；模板行内的公式按相对引用复制到每一行；模板行内的横向合并会复制到每一行；
  * 与**纵向合并单元格相交**的行不能作为明细行（创建字段时即拒绝）；
  * 0 条明细且选择「删除明细行」时，只引用该行的公式会变成 `#REF!` 并给出警告，建议改为「保留一行空白」。
* **写入值**：数字仍为数字、日期仍为日期（目标单元格为日期格式时写序列值，否则写显示文本）、文本仍为文本；来源显示为 `000123`（数字格式补零）而目标为常规格式时给出警告，可在映射里选「写入来源显示文本」。单元格文本超过 32 767 字符时该样本失败并说明原因。
* openpyxl 只用于**读取**和**预览渲染**，填充不经过 openpyxl 保存，所以 openpyxl 不支持的对象（图表、形状、切片器等）不会因填充而丢失。

### DOCX
* 字段是内容控件（`w:sdt`，tag 为 `dw:<字段ID>`），高亮只是界面状态，不依赖文件中的底纹。
* 选中文字跨越多个 run 时先按字符偏移拆分 run，再把连续 run 放入内容控件；与超链接、修订等结构部分相交的选区会被拒绝并提示。
* 填充时新值沿用**字段起始字符**的样式；换行写成 `w:br`，制表符写成 `w:tab`；默认移除内容控件外壳（可选保留）。
* 重复表格行：每条明细复制模板行（保留行样式）；模板行上方的表头行设置「跨页重复」，生成的行设置「不跨页拆分」；0 条明细可选：删除该行 / 保留空行 / 显示占位文字 / 删除整张表格 / 视为错误。
* 批注、脚注、图表、图片等未修改部件原样保留；数字签名在任何修改后都会失效（上传时提示）。
* 字体：模板使用了服务器未安装的字体时上传即提示——DOCX 本身不受影响，但服务器端导出 PDF 时会被替换。

### PDF
* 坐标：界面使用「渲染后页面的归一化坐标（0–1）」，服务端换算为未旋转页面坐标保存；与缩放比例、屏幕尺寸无关，旋转 0/90/180/270 均经测试。
* 模板字段：创建时读取框内原文字（显示「原内容」），生成工作副本时用 PyMuPDF 的 redaction 真正删除（`apply_redactions`，不删除线条图形）；只部分落在框内的文字不会被删除并给出提示。
* 写入：嵌入 Droid Sans Fallback（Apache-2.0，PyMuPDF 自带）并做子集化；字号从设定值逐步缩小到最小字号（默认 6），仍放不下 → 报错 `overflow`，不截断。
* 表单字段：填写后扁平化（保证中文显示一致），输出中不再是可编辑字段。
* 扫描页模板：框选时清除像素（填白）后写入，相当于修改了图像。

### 扫描件 / 图片（OCR）
* 仅在本机运行 Tesseract（`chi_sim+eng`，tessdata_fast 模型），不调用任何外部 OCR 服务。
* 识别结果（词、坐标、置信度）与原始图像分开保存；界面始终显示原始像素。
* 取值区域内任一词的置信度低于映射设置的阈值（默认 80）→ 该样本进入「待确认」并阻止生成，直到在「校验」面板中确认或修正；修正值随来源文件保存（生成新版本，旧预览失效）。

### PPTX
* 定位：幻灯片序号 → 形状 ID（`cNvPr/@id`，不同文件不一致时回退到唯一的形状名称）→ 段落 → 字符偏移。
* 填充时核对字段位置的原文，模板被外部修改导致不一致时报错，不静默写入附近位置。
* 重复表格行会增加表格高度；超出幻灯片底部时给出警告（演示文稿不会自动分页）。

### 旧格式与复杂对象
* DOC/XLS/PPT/ODT/ODS/ODP/RTF 通过 LibreOffice（无头模式、私有配置目录、超时 180 秒、CPU 时间限制）转换为 OOXML 后处理，界面与文件说明中都会标注「经 LibreOffice 转换，可能有损」。
* 宏（VBA）、ActiveX、外部链接、PDF JavaScript 都**不会被执行**；上传时检测并提示。

## 3. 暂未实现 / 缺口

| 缺口 | 原因 | 影响 | 下一步 |
|---|---|---|---|
| 图片模板（输出 PNG/JPEG） | 需要图片专用的排版/字体渲染与像素级清除策略 | 不能把一张图片当模板直接输出图片 | 先转为 PDF 使用扫描型 PDF 模板；后续可增加「PDF 模板 → 渲染为图片」导出 |
| DOCX → XLSX / CSV 导出 | 文档没有行列结构 | 选择时界面标为不可用并说明原因 | 使用表格型模板（内置或上传 XLSX） |
| PDF → DOCX 转换 | PDF 没有可编辑结构，无法无损恢复 | 不提供 | 上传 DOCX 模板或用内置编辑器重建 |
| 单个文件内重复出现的不规则表单块自动切分 | 属于扩展的样本切分能力，需要块识别规则 | 当前不能自动识别，**不会**假装识别 | 用「每文件一份」+ 明细表，或先拆分文件 |
| DOCX 段落块（非表格）的重复 | 内置编辑器与上传模板目前只支持重复**表格行** | 列表型明细需放在表格中 | 增加「重复内容块」字段类型 |
| Microsoft Office 实机打开检查 | 自动化测试使用 LibreOffice 打开/渲染；Word/Excel 需人工或桌面自动化 | 见 `docs/ACCEPTANCE.md` 第 13 项 | — |
