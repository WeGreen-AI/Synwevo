# 模型调用流量：速率、在途、有界等待与公平调度

适用范围：经平台账户（`GovernedDeepSeek`）发出的有费用模型调用。个人自带密钥不经过本服务。
需求出处：MASTER_PROMPT §24、§28.9。本文件说明已实现的模型与它的边界，不宣称任何吞吐量。

## 1. 分开建模的六个数

| 数 | 含义 | 维度 | 来源 |
|---|---|---|---|
| RPM | 60 秒内被准许发送的调用次数 | 平台账户、付款人 | 成本策略 `traffic.platform_rpm` / `payer_rpm` |
| TPM | 60 秒内被准许调用的 token 数（发送前按路线输入+输出上限估算，可信用量到达后换成实际值） | 平台账户、付款人 | `traffic.platform_tpm` / `payer_tpm` |
| 在途 | 已准许、尚未得到结果的调用 | 平台账户（既有 `max_inflight`）、付款人 | `max_inflight` / `traffic.payer_inflight` |
| 等待容量 | 正在排队、尚未准许的调用 | 平台账户、付款人 | `traffic.max_waiting` / `max_waiting_per_payer` |
| 业务额度 | 每次运行的报价预算、调用次数、期限；持续同意的次数 | 运行 | 报价/同意（不在本服务） |
| 资金预算 | 钱包、个人日/周/月、平台成本日/周/月/未知 | 付款人、平台 | Ledger / PayerBudgets / CostAdmission |

它们不能合成一个“并发”数字：一个调用必须同时满足全部约束才会被发送。换密钥或命名空间不改变
平台账户（`account_ref`）与付款人维度，因此不能绕过。

## 2. 流程

1. **入队**（发送前、预留资金前）：写一条 `waiting` 记录（付款人、估算 token、等待截止）。
   等待容量已满时立即拒绝（`traffic_queue_full` / `traffic_payer_queue_full`），不接受明知无法服务的工作。
   Agent 发起回答时也先检查同一容量，满时直接返回 429 和重试时间（背压）。
2. **授予**：任何等待者在一个写事务里过期旧记录并按公平顺序授予容量（见 §3）。授予有 30 秒有效期，
   过期未使用的授予释放容量。
3. **准许发送**：与 Ledger 的一次性发送围栏、平台成本准入在**同一事务**里核对授予仍有效并标记为
   `admitted`。被拒绝时什么也不会发送。
4. **结束**：得到可信用量时记入实际 token；用量未知时按估算值继续计入 TPM，并在成本准入的同一过期时间前计入在途。
5. **等待截止**：默认 300 秒，且不晚于运行期限。到期仍未授予则以 `traffic_wait_timeout` 结束，
   不发送新请求；资金预留尚未发生，无需释放。本人停止回答时等待立即放弃。

## 3. 公平顺序

按付款人轮转：最久未被授予的付款人优先，同一付款人内先到先得。某付款人的自身上限
（RPM/TPM/在途）不足时只跳过该付款人，不阻塞其他人；平台上限不足时停止本轮授予，
以免小请求长期插队、让大请求饿死。

## 4. 配置与故障策略

- 未配置 `traffic` 的成本策略版本：只执行既有的平台在途与成本上限（兼容旧版本）。
- 策略、计数或存储不可读：拒绝新调用（不放行）；已有调用的收尾、用量接收与结算照常。
- 平台 RPM/TPM 必须按已核实的提供方账户额度填写；多个密钥不代表多个账户额度。
- 配置在 Account 管理端「模型成本策略」页：与成本上限同一版本、同一预览/理由/审计流程；编辑旧版本
  时显式选择“启用/不设置”，表单不会悄悄丢弃已有的速率设置。同页的「当前模型调用流量」只显示平台合计
  （最近 60 秒放行数与 token、进行中、排队数与最久等待），不显示付款人或会话。
- 记录保留：已结束的排队记录（完成/过期/放弃）在一天后按批清理；用量未知且仍占用在途名额的记录不清理。
  这些记录是排队状态，用量与成本事实仍在账本里。

## 5. 未实现（明确的后续工作）

- 提供方 429 的自动重试与退避：目前 429 按“已发送、用量未知”保守处理（预留保留到截止）。
  在核实提供方对 429 不计费的契约前不自动重试，以免累积未知敞口。
- 跨进程唤醒：等待者以短间隔轮询共享状态；没有推送通知。
