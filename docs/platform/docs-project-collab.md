# Docs 项目页协同：在场、按映射合并、实时变更与归属（CI-46）

9.13 的第二部分：文档型模板的共同编辑（CI-45）之外，「一份工作」的其余可编辑对象——字段映射、来源文件、样本规则、项目设置、模板版本——
按稳定对象同步：谁在项目里、正在看哪个对象、谁刚改了什么，映射不再整份 JSON 最后写入覆盖。

## 1. 决策记录

| 项目 | 结论 |
|---|---|
| 问题与基线 | 项目页 `Workspace` 的映射列表整份保存（`PUT /api/projects/{pid}/mappings` + `base_rev`）：两个人从同一版出发各改一条映射，第二个人的保存被 409 `stale` 整体拒绝，界面提示「已刷新」后其修改丢失——即使两人改的是不同映射。页面看不到别人在项目里，别人的保存要等自己下次操作才发现；修改没有归属。 |
| 成熟参考 | **Figma「How Figma's multiplayer technology works」**（2026-09-26 读取）：结构化对象不用 OT/CRDT，服务端为权威，按「对象的属性」做最后写入优先，创建/删除是显式动作，在场（光标）走独立通道；文中明言同一文本值的同时编辑在该模型下不可行——所以文本走 CI-45 的 CRDT，结构化对象走本方案。**Yjs Awareness**（同日）：临时在场状态与文档分离。**OWASP WebSocket 安全**：握手鉴权之外每条动作仍要授权——本方案里项目房间只承载在场与变更帧，所有写入仍走带授权的 HTTP。 |
| 对比与选择 | (a) 把映射列表放进共享 CRDT 文档：映射有业务不变量（目标字段存在、来源可解析、编号唯一），CRDT 收敛不等于业务有效，且 SDK/CLI/机器 API 仍按修订版写入，两套权威会打架；(b) 只加「有人在编辑」提示：不满足 9.13；(c) **本方案**：写入仍是修订版（一个权威），但服务端在 `base_rev` 落后时**按映射 id 做三方合并**（基线版 / 当前版 / 提交版）：只有一方改的映射直接通过，双方改同一条才 409 并列出 id 与原因，用户选「以我的为准」时带 `force_ids` 重发；每次变更写入归属活动表并通过项目房间推给在场的人；在场与「正在看哪个对象」用稳定对象 id 走 awareness。保留：修订版撤销/重做、机器 API 契约（无 id 的整份定义仍按原规则 409）、`authz.py` 路由策略、CI-45 的房间基础设施。 |
| 预期变化 | 项目页顶栏：「实时更新中」、在线成员（姓名首字 + 稳定配色；提示「X 正在看字段「客户名称」」，点击即定位到该对象）、「活动记录」。别人保存后本页自动刷新并提示「X 新增映射 #2→金额（第 5 版）」。从旧版出发的保存自动合并（响应带 `merged_with`；内容与已保存的完全一致时不再产生空修订）；真冲突弹出对话框列出映射与原因，可选以我的为准或以对方为准。活动记录抽屉：按人、按时间列出映射新增/删除/修改（含来源→来源、启停）、文件增删/顺序/选项、样本规则/设置、模板版本。 |
| 边界与风险 | **权限**：项目房间沿用会话门与 Origin 检查，查看者可加入（只看在场与变更帧），项目不可见即 4404；房间不接受文档更新帧（静默忽略），所有写入走 HTTP 授权。**归属**：操作者来自核心包新的 `context.actor()`（会话用户或委托令牌背后的人；服务账户为 None → 显示「系统」），不信任客户端字段。**合并**：只对带 id 的列表合并；无 id 的整份定义（机器提交）与空列表仍按旧规则 409，避免重复创建；`updated_at` 不算改动；冲突只在同一映射双方都动、或一方删一方改时出现。**数据**：`project_activity` 每项目保留最近 500 条；模板版本变化按使用该模板的项目扇出。**多进程**：与 CI-45 相同（房间在进程内，多 worker 需粘性路由）。**手机**：在场条换行，成员芯片只显示首字，活动抽屉全宽无横向滚动。**三语言**：新增 39 条。 |
| 验收 | `apps/docs/tests/test_project_collab.py`（合并算法：不相交修改/同样修改/双方新增/删除与冲突/强制保留/时间戳不算改动；HTTP：两人从同一版各改一条都落地且活动归属正确；同一映射冲突 409 带 id 与原因、`force_ids` 解决、不存在的基线仍 409、`force_ids` 类型校验；项目房间：在场与 focus 传递、HTTP 保存/字段修改/加文件即时到达查看者的页面并带操作者、文档帧静默忽略；外人 4404/无会话 4401/活动接口 404）；`test_services_templates.py` 并发保存用例改为「六次相同保存只产生一个修订」；浏览器 `ui_e2e_project_collab.py`（Chromium + WebKit，两账户，编辑者在手机：互见、定位、他人保存即时提示、旧版保存自动合并、同映射冲突 409、活动记录归属、离开后名单清空）。 |
| 发布与恢复 | schema v21 一张表（增量）；核心包新增 actor 上下文（只用于归属）。回滚到 v20 代码：表闲置，保存回到整份 409 语义，无数据风险。 |

## 2. 接口

| 接口 | 权限 | 说明 |
|---|---|---|
| `WS /api/collab/projects/{pid}?workspace=` | 空间成员 | 同 CI-45 的帧格式：`hello`（`kind: project`）、`joined/left`、`role/closed`，以及 `change`（`kind`、`detail`、`by{id,name,color}`、`at`）；awareness 状态 `{user, focus:{kind: slot|mapping|source, id}}` |
| `PUT /api/projects/{pid}/mappings` | 编辑者 | 新增 `force_ids: [id]`；`base_rev` 落后时按映射合并，成功响应多 `merged_with`（及 `unchanged`），冲突 409 `stale` 的 `detail.conflicts: [{id, no, reason}]`，reason ∈ both_changed / deleted_by_other / deleted_by_you / both_added |
| `GET /api/projects/{pid}/activity?limit=` | 空间成员 | `{items:[{id, kind, detail, by, at}], online}`；kind ∈ mappings.save/undo/redo、source.add/remove/order/representative/options、project.update、template.save/restore/undo/redo |
