# 嵌套明细（设计，分批实现）

持续迭代 §8.1 要求模板覆盖「表格与非表格重复块、嵌套/跨页明细」。典型场景：**每位客户一份**（每组一份），
里面**每个订单一段**（重复内容块：订单号、日期、小计），每段里是**该订单的明细表**（按行重复：品名、数量、单价、金额）。
设计由独立规划代理读代码起草（2026-09-28），这里是决定下来的版本。

## 0. 先修的错误（CI-103，已实现）

DOCX 里先建重复内容块、再在块内表格上设重复行，原来不拒绝，生成时静默写错（第一份副本拿走全部行，其余留着模板行）。
现在建时拒绝、旧模板填充时报错 `nested_repeat`。嵌套明细实现后，这个拒绝改为「按下面的规则填充」。

## 1. 数据模型（不迁移已存映射）

映射是自由 JSON，新增键都是可选的，缺省即现状。

* **内容块的映射**（`type: "repeat"`，目标是块）新增 `group_by`：`{"keys": [{"header": "订单号"}], "empty_key": "error" | "skip"}`；
  每列可选 `agg`（`unique` 缺省，不一致时报 `group_conflict`；`first`、`sum`、`count` 等沿用 `transforms.aggregate`）。
* **子组**：取映射已经得到的行（每组一份时就是该组的行），按键分组（不要求相邻，与 `records.py` 分组相同），
  顺序按每个子组第一行出现的顺序（样本规则里的排序先生效：`[下单日期, 订单号, 行号]` 一次排好）。
* **键为空**：`error`（缺省）列出至多 5 个单元格；`skip` 丢弃这些行并给出警告。
* **块内的明细表**：字段带只读的 `parent: <块 id>`（由模板结构推出，每次存版本重算）；它的映射形状不变，
  每份块副本只写入**该子组**的行。

## 2. 模板

* `wrap_blocks` 允许块内含有带重复行的表格；仍只支持一层（块套块、重复行里的块继续拒绝）。
* 新增 `docx_blocks.nesting(pkg) -> {子字段: 块}`，`new_version` 时对 DOCX 重算 `parent`，两种创建顺序都成立，删掉块就清掉 `parent`。
* 标签语法不变（`dw:<块>`、`dw:<块>#cN`、`dw:<表>#cN`）；内置编辑器的 `repeatBlock` 暂不含表格。

## 3. 解析与计划（`engine/plan.py`）

* 块映射有 `group_by` 时算出分段（行下标列表）与各段的键，每段一行块数据；块列取值 = 聚合后再走列的变换。
* 子表映射另记「全空行」（所有非常量列为空），只在嵌套时丢弃。
* 后处理 `_nest()`：按父块的分段切子表的行，行数对不上报 `nested_source_mismatch`。
* 静态检查：`group_by_unsupported`（目标不是 Word 内容块：Excel/PPT/PDF 模板与 Word 表格行暂不支持）、
  `nested_needs_group_by`（子表已映射而块没有分段）、`nested_source_mismatch`（非分组模式下子表与块的来源不一致）。
* 0 行：块用自己的 `empty_policy`；子表 `empty_policy=error` 按段检查（「订单「B-1」没有明细行」）；块为占位时子表按自己的策略。

## 4. 生成

* DOCX：`_fill_repeat_row`/`_keep_container_valid` 移到 `docx_blocks`；`fill_block` 对第 i 份副本找到子表的行，写入第 i 段的行；
  图片的 `docPr` 在子表填完后重编号；保留字段外壳时内层控件 id 唯一。
* 跨页：每份副本是自己的表格，表头行已设「跨页重复」；Word 只重复表格开头的表头行（标题行在表头之上时不成立，写进说明）。
* XLSX / PPTX / PDF：本批明确不支持，`group_by` 在这些模板上被拒并说明。

## 5. 界面

映射对话框里，内容块多一个「分段字段」（缺省不分段；块内有明细表时必填），分段后列表多一列「段内取值」；
块内的明细表显示「此表在内容块「X」内：每份只写入该段的行」；三语言。

## 6. 验收（`apps/docs/tests/test_docx_nested.py`）

合成工作簿（客户 × 订单 × 明细，含公式与 TEXT），每组一份按客户、按订单号与行号排序：
客户 A 两单（2 行、1 行）的段落与两张表逐格核对；公式与 TEXT 进子表；段内 `sum` 小计；0 明细的三种策略；
0 订单；键为空的两种策略；缺列；段内值冲突与 `first`；120 行长表（有 LibreOffice 时核对分页与表头重复）；
模板规则（两种创建顺序、块套块、重复行里的块、删块清 `parent`）；XLSX/PPTX/表格行上的 `group_by` 被拒；
保留外壳时控件 id 唯一；`test_docx_blocks.py` 原样通过。

## 7. 分批

1. CI-103：静默写错的形状先拒绝（已完成）。
2. 引擎：数据模型、计划、DOCX 生成与测试（约两天工作量）。
3. 界面：映射对话框与提示、三语言、浏览器证明。
4. 以后：XLSX/PPTX/PDF 的嵌套、内置编辑器表格进块、多层嵌套、子组单独排序、合并单元格的键向下填充。
