## 1. 依据的规则（逐条套用）

1. 标题、导语、卡片正文重复同一个意思 → 只留最清楚的一条。
2. 按钮已经说明白的动作，后面跟着「点击…即可…」式的教程 → 删除，除非有前提或后果要交代。
3. 解释内部机制的话 → 移出产品界面。
4. 挡在高频操作前面的长教程 → 压成一句必要的话。
5. 空态欢迎语、重复的引言、没有信息量的成功语 → 合并或删除，只留真实状态 + 下一步。
6. 权限范围、数据去向、限制（大小 / 格式 / 数量 / 时限）、不可逆操作 → **保留**，写短写准。
7. 失败 → 说清发生了什么、接下来怎么做。

## 4. 保留不动的（和为什么）

* 限制、时限与后果：口令至少 15 个字符；验证邮件每小时 3 封、链接 24 小时；验证码 10 分钟；重置链接
  2 小时、只能用一次；邀请每次最多 100 个邮箱、每个工作空间 24 小时 50 个；批量导入单次行数上限、只显示
  前 300 行；头像 PNG ≤ 256 KB、512 × 512；「保持登录」最长 14 天；组织删除七天可恢复；注销七天可取消；
  恢复码只显示一次；密钥只显示一次；撤回授权不可恢复；移除成员 / 退出工作空间 / 冻结 / 删除的后果清单。
  规则 6 要求保留，只做了缩短与术语统一。
* 数据去向与权限边界：「平台管理权限不会授予工作空间文档的读取权限」（改为只对平台管理员显示）、
  「只显示数量，不显示内容」、API 管理的「管理权限不授予文档数据访问」、审批人「不是对方的个人工作空间」、
  举报处理「不显示整段会话」、导出「不包含组织文档、他人的信息或登录密钥」。
* 服务端产生的文案：`auth-flow` / `organization` / `account` 目录里 50 条只被服务端错误消息引用的键
  （通过 `hasMessage(originalMessage)` 翻译），例如「请填写引导令牌、邮箱与口令」「该工作空间已属于一个
  组织」「新口令不能与当前口令相同」——它们属于服务层，本批次不动 Python。
* 浏览器证明匹配的字符串原样保留：「邮箱」「口令」「登录」「验证此邮箱」「设置新口令并验证邮箱」
  「验证完成」（新状态行仍以它开头）「安全网关」「最多发送 3 封」「换一个邮箱注册」「创建账户并继续」

  「查看权限」「编辑组织设置」「验证并确认」「确认操作」「操作原因」「删除消息」「已删除消息」
