# Agent 中显式选择业务资源

本切片为 AG-ATTACH 的资源上下文入口：表单定义（草稿和已发布版本信息），数据表字段与已保存视图。
它不包含填写提交或数据表全部记录。个人文件是另一条有独立归属与生命周期的入口，见
[Agent 个人文件](agent-files.md)，不得借文件入口绕过工作空间资源的权限。

页面先选择工作空间，再搜索资源。每次选择都会读取当前真实应用服务；发送时再次读取并比对内容指纹。
已经变化或失去权限的资源必须移除后重新选择，不自动将新的正文套入旧报价。

## 接口与上限

所有接口经现有 `/api/suite/ops/{operation}`、登录会话和 CSRF 门槛进入；个人 Agent 操作不向模型开放。
资源读取调用注册表中的 `forms.form.list/get` 和 `tables.table.list/get`，执行原应用服务器鉴权。

- `agent.context.list`：输入 `workspace_id`、`kind`（`form` / `table`）、可选 `q`（100字符）与 `offset`。
  输出 `items`、`next_offset`、`limited`。每页50项；Forms沿用原服务最多500项的限制，达到该范围明确提示缩小搜索。
- `agent.context.resolve`：输入 `workspace_id`、`kind`、`resource_id`；输出 `reference`、标题、空间名与原应用深链接。
  `reference` 包含相同三个标识与64位内容指纹 `snapshot`，没有正文。
- `agent.turn.quote`、`agent.turn.start`：可选 `context_refs`，均为上述 `reference`，与 `file_refs` 合计最多5项。
  不接受客户端自行提供的正文、标题、操作名或权限。重复资源被拒绝。

每项实际资源完整JSON最多24,000字符，单次选中上下文合计最多60,000字符；超过限制明确拒绝，不静默截断。
上下文还计入既有会话600,000字符限制与模型请求预算。选择/核对不调用模型、不冻结钱包。
表单/表格名称中的用户内容原样显示；选择器提供简体中文、繁体中文与英文界面。

## 固定输入与持续授权

新用户消息把经验证的完整快照保存到 `api_json` 的 `business_context_v1`，来源证明保存到 `sources_json`。
业务资源选择无需新迁移、第二数据库或文件副本；个人文件使用单独的新增表。
该结构与助手私有重放数组按角色区分；旧消息和空上下文报价兼容。

报价指纹绑定所选资源标识与版本；单次授权、持续付款授权、消息与任务仍在同一现有事务内绑定。
绑定失败不留下用户消息或任务，不发起模型调用。已接受的运行使用快照而非浏览器当前空间。
重新生成复用原用户消息，禁止替换上下文，沿用既有只读分支规则。

每次模型调用前核对来源资源访问与空间模型政策。工具写入仍受实际操作权限、人工确认及来源导出政策约束；
显式选中的资源与工具读取的来源同等参与跨空间传输检查。模型收到标注为不可信数据的结构化正文，内容中的命令
不能提供新的工具权限、确认或付款授权。
同一会话曾合法复制的资源即使回执隐藏或来自另一分支，再次选择仍携带原始来源的导出约束；
目标独立副本的读取和模型处理则按目标权限检查，不因此依赖原空间的持续读取权。

来源内容、字段权限、成员资格或应用资格变化时，保守隐藏整个相关消息块和后续生成块、来源卡片与流式文字；
会话不再继续发送旧内容。表的字段过滤由原服务完成，选择表定义不预加载业务记录。
个人账户删除沿用 `agent_records.erase` 清除消息、私有重放与 Agent 操作缓存；账务凭据不保存资源正文。

## 验证边界

自动化验证在隔离 Store 上运行真实应用服务、权限、报价和账本；模型/支付协议替身仅存在于测试。
浏览器验收使用隔离用户与合成资源。它们不能代替真实提供方产物与真实付款验收；线上推送、CI及部署证据另记
`docs/agent-work/EVIDENCE.md`，不能从本说明推断已上线。
