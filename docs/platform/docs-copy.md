# Synwevo Docs 外壳文案审查（第九轮 §4 全站文案 / §10 界面标准）

范围：`apps/docs/web/src/**`——项目列表、工作台四个面板（文件 / 来源 / 目标 / 映射）、模板选择器、
生成对话框、任务页、内置文档与表格编辑器、版本对话框、评论与活动记录抽屉、在线状态、复制到组织
对话框、脱敏与回归对话框、能力矩阵、关于页，以及空态、错误态、成功态、提示、工具提示与读屏名称。
目录 `messages.ts`（界面）与 `messages.server.ts`（服务端文案的呈现）随之整理。

## 1. 依据的规则

每一条用户看得到的文字只保留一种作用：告诉人**在哪**、**现在是什么状态**、**可以决定什么**、
**下一步做什么**，或者**出了什么事、怎么恢复**。审查时逐条套用：

1. 标题、说明、卡片正文重复同一个意思 → 只留最清楚的一条。
2. 按钮已经说明白的动作，后面跟着「点击…即可…」式的教程 → 删除，除非有前提或后果要交代。
3. 解释内部机制的话（数据库、队列、引擎名、组件名、标准编号、仓库文件路径、命令行）→ 从产品界面移除，
   需要的留在 `docs/`。
4. 挡在高频操作前面的长教程 → 压缩成一句必要的话，细节按需（工具提示、帮助对话框）。
5. 空态欢迎语、重复的引言、没有信息量的成功语 → 合并或删除，只留真实状态 + 下一步。
6. 权限范围、数据去向、限制（大小 / 格式 / 数量）、不可逆操作 → **保留**，写短写准。
7. 失败 → 说清发生了什么、接下来怎么做；不出现光秃秃的「发生错误 / 未知错误」。

术语统一：工作空间（不再简写成「空间」）、组织、文档、模板、映射、样本、任务、产物、消息、通知、
已读、撤回、删除；产品名 Synwevo / Synwevo Docs；界面不写第三方组件名（`check_component_names.py`
守卫）。标签、帮助、焦点与读屏名称保留；破坏性、权限与公开共享动作的确认保留；用户内容
（文件名、模板名、评论、消息、映射历史备注）不动。

## 4. 保留不动的（和为什么）

* 权限说明 `READ_ONLY_TEXT` / `NO_EXPORT_TEXT`：权限范围与找谁改，两句已是最短；`browser_roles.py` 与
  单元测试按其中的「只能查看，不能修改」/ “viewer in this workspace” 断言。
* 限制与后果类文案（上传格式清单、命名规则「非法字符会被替换…重名自动加序号」、取消任务时「进行中的
  一份完成后停止并保留结果」、脱敏「替换对照表不会保存」、回归「请只保存测试数据或已脱敏的文件」、
  删除 / 移除 / 弃用 / 恢复版本的确认）：规则 6 要求保留，只做了缩短。
* 键盘快捷键对话框：它本身就是按需展开的帮助（规则 4 的「细节按需」）。
* 复制到组织对话框的「切换到目标空间并打开副本」「我也是目标空间的审批人…」：`ui_e2e_project_copy.py`
  与 `ui_e2e_phone_copy.py`（账户服务的浏览器证明）按原文匹配；对话框标题与字段已写「工作空间」，
  这两处的短写留待那两条证明一起改。
* 服务端产生的文案（`messages.server.ts` 的其余条目、Python 里的说明与错误）：属于服务层，本批次只动
  外壳；`内置公式引擎已计算公式并写入结果。` 一类是能力名，且被 `browser_i18n_artifacts.py` 匹配。
* 「每块一份」等样本模式名、`MAP_TYPE` / `SLOT_KIND`、任务状态：已是短标签。
