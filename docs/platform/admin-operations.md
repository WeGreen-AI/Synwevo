# Synwevo Admin 使用与恢复说明

本说明随现有实现维护。确切提交、验证与发布状态以 [交付断点](../agent-work/STATE.md) 和 [验证证据](../agent-work/EVIDENCE.md) 为准；覆盖状态与后续缺口见 [管理能力覆盖表](admin-coverage.md)。账户数据、秘密和生产身份不用于演示；下列命令只能由获授权的主机操作者在确认环境后执行。

## 入口与权限

沿用 `https://accounts.synwevo.com/admin`。API 管理在 `/admin/api-platform`，旧 `?tab=` 深链接继续可用。页首显示服务端实例标记、当前源站和平台作用范围；导航只显示当前角色可用的能力。切换浏览器账户后重新读取权限。

平台角色与组织、空间角色分别管理。最高管理员拥有已登记的平台能力；账户与访问管理、支持、API 管理、审计等委派角色只拥有目录中明确列出的权限。通过「平台管理员」或账户行的「平台权限」查看有效权限、来源、期限及不能授予/撤销的原因。实际请求还会重新检查当前身份和权限；页面仍显示按钮不代表旧授权仍有效。

平台治理权不授予文档、私聊或附件访问权。禁止用指派历史数据或任意改成员来代替内容授权。应用身份不按普通人员执行停用/恢复。

## 初始化、交接与强认证

部署主机先使用项目锁定环境检查是否已有可用最高管理员：

```sh
.venv/bin/python -m synwevo_identity.cli --data /path/to/authorized-data bootstrap status
```

只有尚无可用最高管理员时，才生成短时、单次领取令牌：

```sh
.venv/bin/python -m synwevo_identity.cli --data /path/to/authorized-data bootstrap token --ttl 900
```

令牌在受控终端只展示一次；通过可信通道交给指定初始化者，在登录页完成领取。不要放入工单、截图、日志或版本库。令牌有效期限定为60–3600秒，默认900秒；无效期限不会替换已有令牌。新令牌作废旧令牌；存在可用最高管理员后领取接口拒绝初始化。公开注册不会获得平台权限。领取时账户、个人空间、令牌消费、最高管理员授予和成功审计在同一事务内提交；并发领取只有一个成功，失败不留下半成品账户。

正常交接使用「发起最高管理员接任」，不能直接在角色选择器或旧接口授予最高角色：

1. 当前最高管理员在目标账户的「平台权限」发起接任。核对账户与影响，填写理由并按要求重新认证；提议有效期24小时，尚未接受时不增加任何权限。
2. 指定接任者用自己的账户进入 `/account#admin-handover`，核对发起人、理由和职责，再用具备用户验证的安全密钥接受。没有可用密钥时先在「登录与安全」登记。发起人不能代为接受；本功能不自动发送邮件。
3. 接受后进入管理员中心，完成第二次独立的安全密钥验证。只有就绪后，新授权才计入最后可用最高管理员的保护判断；仅接受不能让唯一旧管理员退出。
4. 核对名册及接任状态，再按需要单独撤销旧授权。旧管理员不会自动失去权限；撤权仍须自己的近期管理认证及理由。

两次接任验证均只适用于该提议和该阶段，不能使用口令或提前完成的普通身份验证代替；成功也不会刷新普通管理操作的认证时限。接受后确实拥有平台管理权限，但不因此拥有组织、空间或用户内容访问权。尚未接受的提议可以由最高管理员取消，或由接任人拒绝；已经接受的角色必须按撤权处理。提议过期、发起授权失效或恢复导致作废时，重新发起，不复用旧证明。

提交结果未知时，在同一确认框选择重试，会核对同一操作编号；关闭或刷新后先核对提议列表及审计。取消尚未完成的设备验证不会提交接受。最后一名可用最高管理员的撤权、停用、删除和唯一认证方式移除受保护；未就绪接任者不计入可用数量。既有、初始化和主机来源的授予保留原有资格规则，不冒充已经完成两次接任验证。详见 [接任协议](admin-handover.md)。

高风险操作可以使用账户口令，或已登记安全密钥的指纹、面容/PIN用户验证。页面从服务端读取当前可用方式；没有口令的账户不会被要求输入口令。验证用途分为管理操作和登录方式管理，不能互相代替；挑战绑定当前账户、中央会话和源站，短时且单次使用。离开确认页面会取消尚未完成的密钥验证，旧弹框不再提交业务。

账户页的身份确认只解锁后续操作，添加/删除登录方式还需本人明确选择。最后可用最高管理员的唯一有效验证方式不能删除。TOTP单独输入尚不能完成这类严格重认证；“管理员必须启用MFA”的策略和完整应急流程仍待完成；正常最高管理员接任已要求专用安全密钥验证。

主机目前保留 `bootstrap admin --email … --force` 的新建管理员能力；它是主机权限下的既有工具，不是有时限、已验证的应急恢复协议。它不能修复已有邮箱账户。真实生产身份的新增高权限授予须有具体授权；不要为演示运行它，也不要把口令写在命令参数或操作记录里。

## 停用与恢复账户

1. 在账户列表确认邮箱和当前状态，打开行菜单，选择停用或恢复。
2. 阅读服务器生成的影响预览：目标、状态变化、会话与应用令牌数量，以及不能恢复的访问凭据。预览本身不修改业务。
3. 填写 8–500 字理由，确认影响；按服务端要求完成近期口令或安全密钥验证。
4. 提交后保留页面显示的操作编号，并刷新账户列表核对状态。审计中的 `admin.user.status` 关联同一操作编号和脱敏前后状态。

停用仅适用于正常或待验证账户；持有平台角色者先撤销平台角色。不能停用自己或最后可用最高管理员。恢复仅适用于已停用账户；原邮箱未验证时恢复到待验证，不能借此跳过邮箱确认，也不能取消删除流程。

停用撤销已有会话、应用委托令牌和未完成认证证明。恢复不会复活它们；用户需重新登录，应用需重新授权。账户状态控制不删除文档、消息或组织。组织的唯一有效所有者，以及共享空间的唯一有效所有者/管理员，须先交接才能停用；冻结或仍可恢复的组织/空间也受保护，单人个人空间例外。预览与执行在写锁内重新核对继任者，成员资格变化后须重新预览。此检查不向平台管理员返回组织成员名单或业务内容，也不会阻止恢复已停用账户。

预览在 5 分钟内有效，并绑定操作者、源站、目标、参数及资源版本。账户或凭据集合在确认期间变化会要求重新预览。保留同一弹窗重试会使用原幂等键，已经成功的请求返回原结果；同键改参数会拒绝。不要用新键重复执行状态变化来判断上次是否成功，先查操作编号与审计。

## 会话、角色和审计故障

「撤销全部会话」同时作废登录/授权中的证明；有效用户可以重新登录。授予平台角色会收紧既有会话的管理员时限，撤权在后续请求重新鉴权时生效。高风险写操作在取得写锁后再校验会话、重认证和权限，避免排队中的旧授权继续提交。

账户状态、结果与成功审计在同一事务内保存；会话撤销与平台撤权还先写持久撤销日志。可靠审计或撤销日志不可用时，高风险写入不能报告成功。失败事务的拒绝记录单独保存。文件日志写入后数据库未提交可能留下保守撤销意图；恢复时可能再次收紧权限，这是故障保护，不应手工删除日志“修复”。

常见提示：

| 提示 | 处理 |
|---|---|
| 需要重新验证身份 | 在当前操作内完成口令或安全密钥验证后重试 |
| 预览过期或账户变化 | 重新获取影响预览，核对变化后确认 |
| 权限已失效 | 刷新管理权限；联系仍有效的授权者，不能靠重新发请求绕过 |
| 安全记录暂不可用 | 本次未提交；检查磁盘、文件权限和服务错误，再用原请求核对/重试 |
| 操作编号与参数冲突 | 保留原请求和结果；新意图重新预览并产生新编号 |

审计不包含口令、种子、令牌或用户正文。当前还没有独立不可篡改审计存储；拥有主机权限的人超出应用 API 的保护边界。

API 管理的本地业务变更与成功审计共用事务；审计写入失败时不保留半完成的凭据、授权或任务状态，任务事件仅在事务提交后发布。请求调试不持数据库写锁等待网络调用，并继续使用独立业务凭据及返回前权限复核。

服务客户端重新启用仍要求审批当前有效，不恢复已撤销的访问令牌。恢复备份时，安全日志可能保守重放停用记录，使已重新启用的客户端再次停用；核验当前审批后通过正常管理流程重新启用，不删除日志或直接改库。

Webhook 签名密钥轮换可在确认中选择重叠期，默认沿用服务端24小时；也可明确选择10分钟、1小时、24小时或立即使旧密钥失效。重叠期同时签发新旧签名，便于接收端完成切换；新密钥只展示一次。轮换不是幂等缓存操作，响应丢失时先核对状态，不能盲目再次轮换。

Webhook 重投确认显示准确目标与影响。同一确认框内的重认证和网络重试复用一个操作键；服务端已受理但响应中断时，重试得到同一投递收据。关闭确认后重新发起表示新意图，会创建另一条投递；遇到结果不明先核对投递记录。每次仍检查管理员会话和独立机器凭据的当前权限，管理权不授予业务数据读取权。受限调试器只允许指定重投路径传入类型化幂等键，不接受任意请求头或外部URL。

举报创建、成功审计及审核待办一起提交；审核决定、相关举报终态、消息删除、成功审计及结果通知记录也一起提交。持久化失败时整体回滚，再次核对状态后重试；外部通知仍由队列派发，记录创建不代表邮件送达。排队请求在锁内复核当前身份、成员资格和消息状态，已删除消息不能被迟到举报重新打开。

## 备份、演练与恢复

使用既有根目录入口，先在隔离目标验证：

```sh
python scripts/platform.py backup --out /path/to/authorized-backups
python scripts/platform.py verify-restore /path/to/backup.tar.gz
python scripts/platform.py restore /path/to/backup.tar.gz --into /path/to/isolated-restore
```

备份包含敏感数据，应由获授权的操作者保管。不要将产物加入版本库或公开链接。归档校验通过只说明该演练结果，不代表生产切换无损；正式恢复还需确认恢复点之后的数据损失、停止/协调写入、原数据保留和回退步骤。不得为本任务覆盖真实 `data/`。

恢复需使用当前安全日志核对备份之后的撤权。账户停用、会话撤销和平台角色撤销以事务收据避免仅按时间截断漏掉尚未提交的撤销；已在备份中生效的收据避免无故重放。角色撤销绑定实际授予记录，合法后续重新授予不被一律抹除。重放开始时已有可用最高管理员、但重放使其降为零时，恢复会拒绝并回滚，交由受控恢复流程处理。开始时即为零（例如尚未初始化）的备份允许恢复；恢复不会凭空补授管理员。

所有恢复（包括 `--no-journal`）都会作废尚未接受的接任提议及认证挑战。已经接受的授权继续按精确 grant ID 核对撤销历史；接受但未就绪的接任者不能成为恢复时保留最后可用管理员的替代者。

**版本兼容：**本批新增安全日志种类 `platform_grant_revoked`。旧版本恢复工具会拒绝不认识的种类。代码回滚不等于恢复工具也可以回滚；保留能读取新日志的工具与依赖，并在切换前演练。不要删除新记录使旧恢复工具勉强通过。旧代码还不理解接任上下文和就绪状态；直接降级会失去这些约束。降级前应停止新提议、处理未就绪授权，并在隔离环境核对恢复工具与权限。

**撤销日志丢失：**现有 `--no-journal` 会撤销会话/令牌等机器凭据，但不能重建账户、成员、资格和平台角色的撤销历史，备份里的平台授权可能仍存在。它不是已完成的安全恢复方案；未经逐项核对和受控隔离，不能将这类恢复结果开放服务。该缺口会在应急恢复批次处理。禁止把“用户需要重新登录”当作授权已安全核对的证明。

## 配置与发布边界

管理员中心的「平台配置」已接入两项非秘密动态配置；注册策略保留原有执行入口。

| 配置 | 默认值 | 允许范围 | 实际执行方 |
|---|---|---|---|
| `notifications.conversation_digest_interval_s` | 1800秒 | 60–86400整数秒 | 每收件人入邮件队列前的预算检查 |
| `notifications.conversation_digest_daily_cap` | 8封 | 1–100整数封 | 滚动最近86400秒内的不同outbox邮件计数 |

查看需要`platform.config.view`，发布需要`platform.config.manage`和近期`admin`身份确认。输入覆盖值或选择内置默认值，先预览差异，再填写理由、确认影响并发布。发布返回持久版本和操作编号；超时后用原确认重试得到原结果。两名管理员基于同一版本提交时，后者得到冲突，界面保留输入并显示当前版本；比较后明确选择基于最新版本重新预览。历史恢复和恢复默认值都创建新版本，不删除记录。

后续派发在写锁内读取当前配置，未发送摘要重新检查预算。放宽预算可以提前复核旧预算等待，但不能跳过首次30分钟聚合、免打扰、失败退避或历史未分类等待。收紧每日上限会等待足够数量的既有邮件退出滚动窗口。配置不打开用户的邮件偏好，也不恢复逐条私信邮件。已经寄出的邮件无法收回。

“已发布”表示配置和审计已经持久化；`notification_deliveries.policy_revision`只证明对应入队或预算等待使用了该版本，不等于所有实例已确认应用，更不等于SMTP送达。逐实例应用状态尚未实现。账户通知页读取同一配置的安全预算摘要，不提供历史、操作者或修改权限。

环境变量、部署参数或外部服务状态不因页面保存而自动生效。其他配置与完整实例生效视图尚在实施。旧程序忽略新增配置记录并继续使用原有常量；代码回滚前须核对预算差异，不能把代码回滚当作保留动态策略的保证。
