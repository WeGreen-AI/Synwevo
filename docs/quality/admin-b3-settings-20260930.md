# Admin B3：实际消息摘要配置（2026-09-30，本地专项验收通过）

问题：摘要间隔与滚动每日上限是常量，无法通过管理员入口受控调整；只保存配置无法证明执行方改变行为。本批复用已有管理操作、身份确认、Store、审计及邮件outbox，不新增平行账户或任务框架。沿用[已核查的操作确认设计](../platform/admin-references.md)，普通实现不重新开展竞品研究。

两项稳定key由`PlatformSettings`定义类型、单位、默认、范围和全局来源。Store新增`platform_settings_versions`，每次发布、重置或回滚追加完整覆盖快照；新增投递等待原因和观察版本两列，原记录等待时间保留、版本未知。`admin.settings.publish`登记管理权限和风险，签名预览绑定操作者/全局目标/源站/输入/版本/有效期；写锁内复核权限和近期身份证明，版本、审计、操作结果同事务。相同请求的幂等键重试返回原结果，版本重新变回相同值也不能复用旧确认。

真实消费者在收件人写事务内读取新预算；只允许旧预算等待因新版本而提前复核，保留首次聚合、免打扰、重试及历史未知原因等待。收紧上限按足够多邮件退出滚动窗口计算。冻结/删除组织后停止其待发摘要。普通用户只得到安全有效预算，不能写回该字段；其主动开启偏好保持权威。配置版本不是实例应用确认；邮件入队不是SMTP送达。

界面提供有效值/默认与覆盖来源、单位和上下界、差异确认、理由及近期认证、持久结果、并发冲突保留输入与明确重基、历史分页、恢复默认和回滚。重新预览生成新确认，身份验证期间不能替换差异；关闭或卸载旧确认取消其待完成证明。刷新离开有草稿时使用已有浏览器保护。注册策略仍是原有面板，其模式语义和版本缺口未被此批宣称修复。
