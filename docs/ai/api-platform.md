## 3. 架构原则与标准选择

采用与当前工程相容的清晰分层：协议入口与契约验证、身份与授权、业务/管理服务、持久化与任务/事件，以及管理配置和可观测性。业务 API 与管理 API 应具有可验证的权限与调用边界，不一定需要两套服务器或数据库。

- 默认完善已有 HTTP API 和 REST 风格契约。GraphQL、gRPC、WebSocket、SSE、MCP 等仅在真实需求与已有能力支持时采用；不为追求“顶尖”同时建设所有协议。
- 网关可以复用已有反向代理和应用能力，只有实际流量、团队或策略需要时引入独立产品；不强制引入 Kubernetes、服务网格或付费 API 网关。
- 服务端和管理 UI 共用业务规则，机器调用不是绕开审批、文件扫描、配额或版本检查的捷径。
- 通过受限管理操作驱动实际组件。路由/上游配置有服务目录、目标白名单、协议校验、版本与影响范围，不能成为任意代理或 SSRF 通道。
- 使用当前工具链支持的稳定 OpenAPI 版本，核查官方规范、验证器和 SDK 生成器兼容性；选择明确版本，不只因规范更新就升级全栈。OpenAPI 版本、Synwevo API 版本、事件版本、SDK 版本和部署版本分别记录。
- 对错误格式可采用 RFC 9457，OAuth 设计核查 RFC 9700 和现有身份服务。采用标准时真实满足契约；保留旧客户端需要的兼容适配，不给旧格式换个名字就宣称合规。
- 研究 Stripe/GitHub 等成熟 API 的契约、幂等、事件和开发体验，只采用对本项目有价值的机制；引用实际资料与访问日期，不复制其产品、定价或基础设施假设。

每项关键选择留下简短理由、代价、兼容策略与验收方式，然后进入实现。不要停在架构报告，也不要每次修正重复开展完整竞品研究。

## 4. 身份、凭据与授权模型

### 4.1 三种调用身份必须分清

| 身份类型 | 应代表什么 | 必须落实的边界 |
| --- | --- | --- |
| 机器/服务身份 | 被明确授权的程序或集成 | 专用身份、作用域、资源范围、环境、期限、配额与可撤销委托，不能默认成为最高管理员 |
| 用户委托身份 | 某用户授予某客户端的具体能力 | 客户端授权与用户当前有效权限共同约束，保留真实主体和客户端归因，不能索取用户密码冒充委托 |
| 平台管理身份 | 被明确授予的管理员或管理服务身份 | 管理 scope、明确目标和风险策略；业务凭据不能调用管理端点，敏感内容权限独立检查 |

API Key 只是凭据形式，不是权限模型。角色、scope、租户关系、应用资格、对象 ACL、资源状态及委托条件按具体身份类型共同约束请求；不能只校验“存在有效 key”或相信请求中的 `workspace_id`、`role`、`owner_id`。

权限检查覆盖对象、功能和字段：请求不能批量写入角色/所有者等未授权字段，响应不泄露无权字段，搜索计数/预览/下载/错误信息也不旁路。机器字段和权限 ID 保持稳定，不随界面语言改变。

### 4.2 凭据全生命周期

- 复用并完善服务账户、客户端注册、API Key 与 OAuth 等真实机制。管理者选择身份、目标环境、资源范围、scope、有效期和限额，服务端防止越权签发。
- 高熵验证型 API Key 按适合方案保存不可逆校验材料，只在创建时交付完整秘密，后续显示安全标识、末位、创建/最近使用/失效状态。需要再次使用的外部签名或连接秘密采用现有安全加密/秘密存储，不能把“全部哈希”误用到无法工作的场景。
- 秘密不进入 Git、URL、文档截图、审计差异、错误堆栈或访问日志；浏览器调试器不永久保存高权限 key。凭据前缀方便识别，不能仅凭前缀判定环境或权限。
- 支持有明确期限的轮换过渡、撤销、暂停与失效；记录使用情况以识别旧凭据是否仍被调用，不能在轮换时悄悄生成永久重叠权限。
- 定义并验证撤销传播时限，覆盖多实例缓存、长连接、异步执行、下载、历史响应与待发事件。短期 token 不等于可以忽略已发生的撤权；敏感操作执行时再次校验。
- 停用服务身份、用户退组、管理员降权或授权撤回后，派生凭据和任务依照已定义的委托生命周期处理；不能冻结旧权限永久继续执行。

### 4.3 OAuth 与非交互授权

完成项目所需的真实用户委托与机器授权：浏览器/用户授权采用成熟的授权码与 PKCE 等适用机制；服务间认证采用受限服务身份及适合现有设施的标准机制，不自创 token 协议。

确认现有 Accounts 是否真实具备对集成客户端发放授权的能力。接入 Google/Microsoft 登录不自动等于已经拥有完整 OAuth 授权服务器；缺失部分使用成熟维护的实现补齐，并验证注册、授权、token 发放/更新与撤销全过程。

- 校验精确回调、适用的 state/nonce/PKCE、issuer/audience、签名算法、期限及授权范围。公共客户端不伪装成能保密的服务端，不使用隐式流或用户密码收集作为捷径。
- 登录账户与授权某集成访问数据是不同动作；授权页面如实展示客户端、scope 和资源范围，管理员注册客户端不替代用户/组织同意。
- token 更新不能扩大权限；适用的刷新凭据轮换/重放检测、退出与撤销策略按真实客户端风险实现。
- 自动化管理任务可以使用已明确批准、限范围和期限的管理服务身份；不能要求每个普通机器调用都交互式 MFA，也不能把人工高风险审批简单删除。需审批的操作返回可处理状态或使用绑定具体计划的授权。
- 保留最高管理员初始化、强认证、交接与恢复。普通开发权限模型已获本任务授权，不为每项实现反复请示；向真实生产身份新增高权限或扩大真实用户内容访问范围按已有明确授权执行。

## 5. API 契约：稳定、一致、可实现

### 5.1 资源与请求/响应

每个对外端点明确用途、所属版本、身份类型、权限、参数、必填/可选/null、默认值、验证约束、结果、错误、副作用、配额和重试规则。资源使用稳定 ID，版本与租户关系准确，不直接暴露 ORM 对象或数据库结构。

- 统一命名、方法、资源状态、日期/时区、长整数/编号、金额/小数、编码和空值语义；保护前导零与精度。机器可读错误码、字段和枚举稳定，用户提示可本地化。
- 写入使用显式字段白名单，拒绝无效类型及不可接受字段；批量赋值不能改变权限、租户、系统状态。决定未知字段的兼容处理并写入契约。
- 避免深层 N+1 和任意字段展开；过滤、排序、搜索与扩展字段有允许集合和成本限制。只返回调用方可见内容。
- 文档声明的操作必须真实实现；实现暴露的稳定端点须纳入目录与相应文档。内部端点也要盘点和保护，但不能无差别导出为公开 API。

### 5.2 HTTP、错误与可追踪性

按行为使用状态码，创建、异步接纳、无内容、认证/授权、冲突、前置条件、校验、限流和服务故障区分清楚。业务失败不能全部返回 HTTP 200；机器接口不返回登录 HTML 或浏览器验证码。

结构化错误包含稳定类型/代码、简短说明、字段错误、可关联 request ID 及适用恢复信息；采用 RFC 9457 时真实匹配其字段语义。不要暴露 SQL、内部地址、秘密、堆栈或无权对象是否存在。

请求关联 ID 由可信入口校验/生成，贯穿服务、任务、事件、Webhook 与审计；客户端可检索自身有权诊断，不能凭 request ID 读取其他租户日志。

### 5.3 分页、一致性与并发

大列表采用稳定且有上限的分页/游标，排序具有确定的次级键。游标绑定必要的范围、过滤和版本，校验篡改、过期及跨租户复用；说明并发增删时是一致快照还是移动视图，不承诺无依据的绝对快照。

适合的可变资源提供版本号或 ETag/条件更新机制，旧版本修改返回明确冲突。PATCH、整体替换、字段清空和删除语义统一，两个客户端同时编辑不能静默覆盖。

Docs 的 REST/API 写入遵守协同编辑的同一版本和操作规则，不能绕过协同引擎直接写整个文档。历史恢复作为受权的新变更，不能让旧队列回写覆盖。

## 6. 可靠写入、任务与批量处理

### 6.1 幂等与不确定结果

对创建、发送、生成、审批执行等有副作用的写接口定义幂等要求。幂等命名空间使用稳定的环境、租户、客户端/调用方、实际主体与操作标识，并核对规范化请求；同键不同参数报冲突，同键并发只产生一个逻辑动作。不要将可变 token、密钥或当前 scope 集合作为命名空间，轮换凭据不能使同一次逻辑操作重新执行；当前授权独立复核。同一次 SDK 逻辑调用的全部重试保持相同幂等键与业务参数。

- 明确键保留时间、执行中响应、成功/失败响应保留规则、参数校验失败及过期后的行为，和允许的客户端重试窗口相匹配。
- 使用数据库约束/事务、可靠任务与现有锁机制处理竞态，不能只有单进程字典或先查后写。
- 超时意味着结果可能未知；提供稳定 operation/task ID 或有权查询路径，先确认再重试。SDK 不默认对所有 POST 无限重试。
- 返回历史结果前重新鉴权，避免撤权用户通过旧幂等响应拿回私有数据或失效下载链接。幂等不是授权替代品。
- 不把请求内容相同视为同一个用户意图，合法的两次独立操作可以不同；不会承诺网络“恰好一次投递”，应证明逻辑副作用不重复。
- 跨外部服务的副作用明确边界、去重和对账/补偿策略，不用本地事务包装成虚假的跨系统原子性。

### 6.2 异步任务

生成、导出、批量导入、重索引、扫描及长管理操作采用真实任务协议，返回稳定 ID、状态查询位置与可用操作。

明确排队、执行、成功、部分成功、失败、取消等合法转换，提供真实阶段/进度、结构化失败、结果、适用重试和取消；任务接纳不是完成，未知百分比不伪造进度。

任务固定来源/模板/映射/规则等内容版本；身份权限在执行、重试、产物发布和下载时按当前委托规则复核。worker 重启、租约到期和重复投递不会重复发布结果；先完整落盘/校验，再原子发布可用产物。

取消、超时与完成的竞争有明确行为，取消请求不等于已完成部分被撤销。断网后客户端可继续查询，不能依赖原 HTTP 连接持续存在。

### 6.3 批量与大文件

批量 API 明确全成全败还是逐项执行，目标集合固定、有上限且受权；每项有稳定关联 ID、结果/错误和重试规则。大集合异步分批处理，失败项重试不重复成功项，取消如实报告已完成部分。

上传支持与业务规模相称的流式、分片/续传或受控直传，限制接收位置、大小、类型、校验和与完成步骤。上传成功不等于通过扫描，未接纳文件不能进入预览、解析、生成、下载或索引。

下载、Range、导出和预签名 URL 遵守实际存储与授权语义。对要求及时撤权的资源，采用受控下载或等效即时校验路径；直接签名 URL 的有效窗口与撤销限制必须如实说明，不能承诺已发链接全部即时失效。URL 不含长期凭据。

## 8. Webhook、事件与自动化联动

交付真实事件目录、受权订阅、端点注册/验证、事件版本、签名、投递历史、暂停/恢复、失败处理和人工重放，并在管理控制台可操作。

### 8.1 事件与交付语义

- 业务提交与事件持久化使用事务 outbox 或适合现有架构的等效机制。不可出现业务已成功却永久丢失完成事件。
- event ID 表示同一个业务事实，delivery/attempt ID 表示具体投递；明确事件类型、版本、时间、环境、租户/对象引用及必要内容。
- 按至少一次尝试、可能重复/乱序设计，明确重试窗口、最大次数、背压、死信和人工恢复。重试耗尽或窗口之外不保证送达，提供事件查询/补偿办法。
- 订阅可按实际业务类型和资源范围过滤；默认最小必要负载。发送、重放、变更目标时复核当前授权，避免退组后仍发出私有快照。
- 事件历史事实与当前资源状态分别表达；接收者可按权限查询现状。不能承诺收回已经交付给第三方的数据。
- 对删除、转移、成员移除等终结事件，在既有保留策略内保留最小事件/墓碑记录与授权关联，按仍有效的订阅、委托和事件接收资格决定投递；不能只因资源已不存在而永远丢失完成事件，也不能借事件恢复已撤销的私有内容访问。

### 8.2 真实性、安全与重试

- 使用成熟签名机制校验原始 payload，包含适用的时间戳、签名版本/key ID 与重放窗口；使用安全比较与真实密钥轮换策略，不自创密码算法。
- 重试与人工重放保留稳定业务 event ID，记录新尝试并使用符合协议的新签名/时间戳；消费者以稳定 ID 去重。说明乱序时的对象版本或重新读取策略。
- HTTPS、目标地址/重定向/DNS 变化校验、网络出口约束、超时、请求/响应大小限制与资源预算防止 SSRF 和任务耗尽；注册时检查一次地址不够。
- 地址验证必须约束实际连接目标及每次重定向，处理 DNS 重新解析/重绑定，不能先检查一个公网地址再连接未经验证的新地址。
- 对平台接收的回调，验签并可靠记录/入队后再确认接纳，后续业务异步处理；不能在尚未持久化前返回成功而静默丢事件。
- 对发出的回调，接收端 2xx 只表示已接受请求，不代表对方已完成业务。仪表盘区分入队、尝试、HTTP 接收与最终业务结果（如协议确实提供）。
- 测试使用已授权的隔离接收端和可识别事件；不向未知地址发送用户数据，不通过“测试回调”扫描内部网络。
- 人工重放不是绕过限流、权限或副作用规则的后门；客户端示例提供验签、幂等消费和故障处理。

## 9. 限流、配额、用量与可靠运行

区分请求速率、突发容量、并发任务、存储/上传量、文档页数、生成额度、外发数量与真实商业计量；它们不能合成一个含义不明的“API 次数”。

- 根据项目规模在平台、组织/空间、客户端/服务身份、凭据、接口类别和资源成本等实际需要的层级实施组合预算；换 key/IP 不应绕过所属主体总预算。
- 多实例/worker 一致执行，使用原子预留/消耗/释放与适用对账；失败、取消、重试、超时和幂等重放的计数规则明确，不能重复扣业务额度或因为失败不释放而永久锁死。
- 客户端超时、断网或 worker 暂时失联不证明任务未执行；结果未知时保持待核对状态，依据持久结果结算或释放。区分可释放预留、已实际消耗用量及每次请求可能占用的速率预算，避免错误返还或重试重复扣量。
- 速率超限返回适用的 429 和可解释重试信息；硬容量不足、业务额度不足及服务拥塞分别按契约处理，不能把所有配额问题都当作等几秒就能重试。
- 管理端可查看默认/继承/覆盖值、有效值、当前用量、窗口与原因，修改后真正影响入口和任务；不能只改变图表数字。
- 公平调度、队列上限、并发控制与背压按实际规模落实，避免一个租户耗尽所有资源；限流/配置组件故障有明确策略，不能统一无条件放行。
- 用量事件可追踪、去重并与业务任务核对；没有真实计费业务时只交付用量和额度管理，不编造价格、收入、付款或账单。
- 合法机器 API、OAuth/Webhook 回调和健康探针保持机器协议，不用浏览器人机验证代替身份与配额。
- 为请求延迟、任务完成、错误、可用性、积压和撤权传播设定适合当前环境的明确目标和测量方式。没有实际证据不宣称任意吞吐量、零故障或某个 SLA。

### 10.2 配置和操作必须形成闭环

每个配置有类型、范围、默认值、来源、继承/覆盖、版本、敏感性、读取方与生效方式。显示已保存、待应用、已应用、部分失败和实际节点状态；需要部署/重启时准确提示并接入既有流程。

并发修改检查版本，冲突展示差异；回滚生成新的审计版本并核查依赖，不能恢复已经泄露的旧 key 或复活撤销的授权。外部/环境配置漂移显示权威来源，不盲目互相覆盖。

批量停用、权限提升、大规模重放/导出、生产配置切换等显示真实目标、数量、副作用与恢复条件，按照风险执行近期认证或既有审批。审批绑定计划、参数、目标、环境、版本与时限，旧批准不能改参复用。

普通低风险可逆操作及时完成，不为每个按钮堆确认。全局停用不能切断管理员恢复、必要探针和已定义的应急路径。最高管理员恢复与最后有效管理员保护继续生效。

### 10.3 调试台与文档权限

调试台明确显示环境、操作者/客户端、资源范围及授权能力，不隐式以超级管理员替所有请求执行。默认选择隔离测试环境/受控空间；生产写入不因点击“Try it”绕过正常保护。

支持真实参数表单、请求预览、结果状态/headers/耗时/request ID、结构化错误、分页、任务追踪和脱敏代码片段。文档示例不能后台偷偷命中固定响应；副作用请求不能自动预取或自动重复发送。

高权限 token 不进入共享 URL、浏览器长期存储或示例代码。服务端代理型调试器须固定允许的 Synwevo API 目标，不能携带凭据请求任意网址。普通集成者取得业务文档或 SDK，不因此获得管理控制台权限。

## 11. 顶级 UI、操作、动画与可访问性

管理员需要快速发现问题、理解原因、完成处理并确认结果。设计围绕这一条路径展开。

- 统一白蓝视觉、字体/间距/图标/边框、表格、表单与状态 token。信息密度适合技术运营，不做只有大数字和装饰图表的页面。
- 提供全局搜索、合理导航、面包屑、环境/范围标识、关联对象详情和键盘快捷操作；命令面板只调用受权业务动作，不执行任意代码。
- 列表具有服务端筛选/排序/分页、列配置、保存视图与清楚选择语义；“当前页”和“全部筛选结果”有明确差别，大操作目标固定。
- 密钥创建、权限范围选择、配额编辑、回调失败排查与版本迁移使用完整任务流程；敏感值掩码并有准确的一次性展示说明，不能把复制失败误报成功。
- 图表说明指标口径、时间窗口、单位、样本量与更新时间；p95 等指标要有真实数据。无数据、采集延迟和服务故障不能一律显示零。
- 实时日志支持暂停跟随与保持阅读位置，新事件不抢焦点，长连接不因切页不断重复建立。
- 提供加载、无数据、无结果、无权、只读、过期、限流、超时、离线、排队、部分失败和恢复状态。重要执行结果保留在任务页，不只显示短暂 toast。
- 动画解释层级与状态，输入和调用及时响应；不伪造进度、不人为延时、不闪屏、不阻挡点击，尊重减少动态效果。
- 简繁英、键盘、焦点、读屏、对比度、缩放、触摸目标和中文输入法可用；手机具有可完成的密钥/诊断/审批流程，不能仅压缩桌面表格。
- 真实浏览器验证页面、完整操作与截图；发现裁切、遮挡、错位、焦点丢失和失效链接就修复。API 调用验证与视觉验收分别进行。

## 12. 文档、SDK、示例与版本演进

### 12.1 文档与契约一致

选择一份权威契约来源，代码优先或规范优先均可，但必须自动检测漂移。生成并校验 OpenAPI，补齐鉴权、对象/字段权限、限制、错误、幂等、异步、分页、文件和事件说明；不能靠人工维护多份互相矛盾的接口表。

提供集成快速开始、认证/轮换/撤销、Docs 完整流程、Webhook 验签与消费、常见故障、升级说明和真实限制。示例地址来自真实可配置 Base URL，凭据使用明确占位符/安全环境变量；占位凭据是保护秘密，不是允许虚构端点和业务结果。

机器契约字段保持稳定；简繁英说明自然易懂。管理员文档和内部能力按权限隔离，可共享给集成者的资料必须去掉秘密、生产用户数据和未授权管理细节。

### 12.2 SDK 与工具

优先交付与当前项目匹配的 **Python 与 TypeScript SDK**，已有 SDK 则升级，不新建重复包。它们至少覆盖身份配置、业务请求、分页、结构化错误、幂等、任务等待/取消、上传/下载及 Webhook 验签示例；按实际业务能力扩展。

- SDK 包含真实类型、超时、取消/中止、有限退避/抖动与适用的 `Retry-After`，写请求只有满足契约的幂等条件才自动重试。
- 可处理大文件与分页，避免默认全量载入内存；凭据与响应内容不默认打日志。
- 重定向不能把 Authorization、Cookie 等凭据自动转发到不同来源；上传/下载采用明确目标与凭据规则，不能为了兼容而关闭证书或签名校验。
- 生成代码需要包装实际使用体验并完成集成验证，不能只生成文件就宣称 SDK 可用。
- 提供可运行 cURL 和两种 SDK 的完整业务示例，至少一个真实事件接收示例。已有 CLI 则完善；新增 CLI 仅在明确操作需求下复用 SDK，不再实现另一套客户端规则。
- 在干净隔离环境安装/构建并连接真实后端验证。SDK 本地打包可自主完成，公开注册包名和发布到外部 registry 遵守真实发布权限；没有发布不能宣称可从公共仓库安装。

### 12.3 生命周期与兼容

兼容范围包含请求/响应、错误码、分页、权限、默认值、幂等、事件、任务结果和 SDK，不只比较 URL。

破坏性变化使用明确版本/迁移策略，维护变更记录、契约差异检查及旧客户端回归。根据真实调用识别旧版本消费者，显示弃用状态和已确认的退出窗口，不随意编造停用日期。

既有 API 与前端、脚本、worker 保持适用兼容，变更先发布可兼容服务/客户端再清退旧路径。代码回滚与数据库/事件格式回滚分别设计，不让旧版本读取新数据后覆盖或错误重放。

## 13. 可观测性、安全与审计

- 真实监控按端点/版本、环境、客户端和必要租户维度展示请求、错误、延迟、限流、任务、事件、用量与依赖；限制高基数字段，不能把 key、邮箱、文档名、全文 URL 塞进指标标签。
- 访问日志默认记录必要元数据，脱敏 Authorization、Cookie、token、签名、查询参数及敏感负载。请求正文/响应正文不全量默认录制；确有诊断需要时提供受控字段白名单、期限、权限和容量限制。
- 区分调用日志、分布式追踪、用量账本与管理审计，它们的用途、保留和访问权限不同。trace header 不能作为身份或权限证明。
- 管理审计记录真实操作者/客户端/委托、环境/范围、动作、原因、脱敏差异、请求/任务/事件关联及最终结果，覆盖拒绝、失败、部分成功、取消和重放。
- 管理接口不能静默修改/删除自身审计；敏感操作在审计无法可靠落地时按明确策略阻断/进入受控处理，保留应急恢复。未有实际存储/校验保障时不宣传绝对不可篡改。
- 逐项检查对象/属性/功能越权、认证错误、资源耗尽、敏感流程滥用、SSRF、误配置、旧接口、第三方响应信任和文件风险。输入 schema、网关、WAF 与 scope 都不能单独替代对象授权。
- 新旧端点、直连路径、协议别名、批量、导出、下载、缓存、长连接和事件不能成为旁路；管理员控制面同样受 CSRF、XSS、点击劫持和秘密保护。
- 不为 SDK/机器调用关闭全站安全，不通过通配 CORS、禁用 TLS/签名验证或公网暴露内部服务让联调“成功”。
- 外部供应商连接和响应进行相称的 schema/状态/时间/重定向校验，不因来自第三方就信任其全部内容。未授权不将用户数据发送给新供应商。

## 14. 必须跑通的完整验收场景

准备隔离但真实的数据库、存储、队列和接收端，以及最高管理员、受限管理员、普通用户、两组织/空间、业务服务身份和管理服务身份。UI、API 和 SDK 均验证，不能仅在前端或单元测试中模拟结果。

### 场景 A：外部脚本完成真实文档生产

创建限定空间/动作凭据 → 上传真实授权样本 → 查询安全接纳 → 创建/复用版本化模板、区域与映射 → 预检 → 提交批量生成 → 查询状态并接收签名事件 → 下载产物 → 读回数据、数量与版式。

注入并发同键提交、短时断网、确认丢失、worker 重启、回调失败/重复/乱序；验证一个逻辑提交不会重复生成业务结果，任务可恢复、成功项不重复执行、失败项可重试。Python 和 TypeScript SDK 都实际走通其覆盖链路，不依赖浏览器人工补步骤。

### 场景 B：管理员操作真实改变调用行为

在后台创建限定客户端和凭据 → 成功调用允许的业务 → 跨空间、超 scope、写保护字段、调用管理 API 均被正确拒绝 → 修改配额并观察真实限额 → 轮换凭据 → 撤销旧凭据与委托 → 验证缓存、活动连接、排队操作、幂等重放及结果下载按明确规则生效。

后台能够按 request ID 查到脱敏调用、配额原因、任务与审计；新的有效凭据和其他合法租户仍正常工作，不能用全站停机证明“撤销有效”。

### 场景 C：审批复制、消息与事件联动

来源所有者通过 API 申请固定项目快照复制到目标组织 → 目标有权者审批 → 执行前重新检查 → 生成独立副本 → 使用获批或独立授权输入生成 → 产生真实对象卡片/通知与受权事件。

未批准、已撤回、目标变化或审批人撤权不能继续复制；副本不带私人凭据或原协作房间，重复回调不重复执行。发送连续私信仍不逐条发邮件，收到卡片不自动获得文档权限。

### 场景 D：受控管理自动化与恢复

限定管理服务身份提交真实低风险配置变更 → 根据契约预检/审批 → 发布并查询生效 → 两客户端并发修改触发版本冲突 → 按适用规则回滚 → 核查业务与审计。

业务身份不能执行该动作，过期批准不能改参复用；管理服务降权后旧任务不越权执行。全局开关/维护不锁死最高管理员恢复。高风险破坏性恢复在隔离目标演练，不拿真实用户数据作演示。

### 其余风险与质量门槛

| 验收方向 | 必须证明 |
| --- | --- |
| 契约一致 | OpenAPI 可验证，实际成功/错误响应及 schema、权限与文档一致，SDK 可构建安装并实际调用 |
| 身份与委派 | scope/受众/租户/资源/字段共同生效，用户授权、服务授权和管理授权不混淆 |
| 幂等与并发 | 同键并发、不同参数、过期、未知结果与撤权重放按规则处理，没有重复业务副作用 |
| 异步与批量 | 接纳/成功区分，状态合法，取消竞争、部分失败、重试及 worker 中断可恢复 |

| 配额与隔离 | 多实例计数、并发预算、释放与对账正确，单租户异常不会耗尽全部资源 |
| Webhook | 原始负载签名、重放窗口、轮换、重复/乱序、退避、死信、人工重放和撤权有效 |
| 下载与缓存 | 私有响应不进公共缓存，长连接/签名 URL/历史结果的实际撤销边界与声明一致 |

| 隐私与诊断 | 页面、日志、追踪、示例、导出和审计不泄露秘密/私聊/文档内容；调试器不成为任意代理 |

执行适用静态检查、类型、生产构建、契约、真实集成、安全反向、故障与浏览器验收。测试应有独立期望，不能从实现输出复制“标准答案”。测试替身只用于隔离的确定性验证，不能代替上述真实链路。

记录真实命令、环境、提交或 diff、结果和证据。禁止删断言、隐藏错误、关闭安全或滥用 skip/xfail 制造全绿；区分通过、失败、未运行和受阻。未解决的阻断性越权、丢数据、错数、重复执行和关键接口错误不能标完成或带入正式发布。

验收与现有强制门槛通过后，除新证据或具体剩余风险，不追加无限测试和研究；立即交付并继续下一批。

## 参考与事实边界

本文件依据 Synwevo 最新持续迭代与管理员平台约束定制。其内容是建设要求，不能当作当前代码已实现的证明。

可核查的官方资料：

- [OpenAPI Specification](https://spec.openapis.org/oas/latest.html)：HTTP API 描述规范，执行时选择实际工具链支持的明确版本。
- [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)：OAuth 2.0 安全实践。
- [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)：HTTP API 结构化问题详情。
- [OWASP API Security](https://owasp.org/API-Security/editions/2023/en/0x11-t10/)：API 权限、资源、业务流程、服务端请求与接口资产风险。
- [Stripe Idempotent requests](https://docs.stripe.com/api/idempotent_requests)：成熟 API 幂等处理案例。
- [Stripe Webhooks](https://docs.stripe.com/webhooks)：事件签名与投递处理案例。

参考不等于复制供应商策略，也不要求接入 Stripe、购买服务或采用特定网关。实际实现以项目需求、现有架构、当前官方资料及验证结果为准。
