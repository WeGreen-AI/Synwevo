## 2. 对标研究与可衡量的产品目标

查看成熟管理产品的官方资料和可合法体验的流程，可参考 Google Workspace Admin、Microsoft 管理中心、Cloudflare Dashboard、Stripe Dashboard、GitHub 管理设置，以及 Carbon/Fluent 等设计系统。参考信息架构、对象详情、批量处理、配置发布、权限解释和故障排查，形成 Synwevo 自己的一致设计。

每项关键设计记录简短的“实际问题 → 参考行为与来源日期 → 适用理由 → 实现方案 → 验收”。不复制完整视觉、不猜测竞品内部实现、不引入无用功能。基础方案明确后立即实现，普通小修复不重复开展大规模竞品研究。

用以下目标评估后台质量：

1. 管理员能发现问题，并沿着状态、对象、任务和审计定位原因、完成处理。
2. 常用管理路径步骤清楚，高风险动作不会因范围含糊造成误操作。
3. 配置和操作真实生效，刷新、重启、多实例、失败重试后行为仍一致。
4. 权限委派和撤销可靠，普通用户、无权管理员和跨租户路径无法绕过。
5. 界面有专业的信息密度、统一视觉、清楚反馈和流畅交互，手机与键盘能完成关键任务。
6. 管理动作可恢复、可追踪；状态和指标可解释，没有虚假的实时性、成功率和安全保证。

先建立真实基线，再选择与项目规模相符的响应时间、分页、查询量、并发和操作完成时间目标。性能改善必须有同条件证据，不预先编造数字。

## 3. 信息架构与管理员工作台

根据实际模块建立清楚导航，建议分组：

- **概览与待处理**：真实健康、异常、容量、失败任务、待审批与最近变更。
- **账户与访问**：用户、平台管理员、角色、组织/空间、会话及认证策略。
- **应用与业务**：Docs、协同、Message、通知、邮件、API 和集成。
- **运行与数据**：任务、服务、存储、扫描、备份、数据请求及恢复。
- **配置与治理**：全局设置、功能开放、域名、品牌、政策、安全规则和审计。

这是组织原则，不要求机械做成同样数量的菜单。避免同一对象出现多套互相矛盾的编辑入口，避免几十项菜单平铺。

必须实现：

- 全局搜索支持允许检索的用户、组织、空间、项目、任务、事件等管理对象。结果遵守字段级与对象权限，不索引全部私聊或文档正文来凑搜索能力。
- 命令面板只触发受权、明确定义的管理操作；高风险动作进入相应确认流程，不是任意 Shell/SQL 执行器。
- 清楚显示当前环境、全局/组织/空间范围。切换范围后列表、缓存、选中项、待保存表单、任务和导出同步更新；旧标签页不能误操作新范围。
- 对象详情具有概览、配置、关联对象、任务、活动/审计等适用视图，可从异常跳到对象，再跳到对应请求或任务。
- 高频列表支持服务端筛选/排序/分页、列显示、合理密度、保存视图、明确的多选与批量动作；保持刷新/返回后的筛选和滚动位置。
- 待处理中心能够真正解决失败任务、异常投递、待审批和风险事件；确认告警不等于修复根因，已读不等于业务已完成。

## 4. 平台权限、最高管理员与可靠恢复

### 4.1 管理员身份与委派

复用现有模型，建立明确的最高管理员以及可委派的运营、安全、运维、支持、审计等能力集合。角色名称可按项目精简，权限必须以真实操作和作用域描述，而非到处写一个不受约束的 `is_admin` 分支。

- 最高管理员能够管理全部平台管理能力、授予/撤销管理员角色、查看有效权限与来源、管理关键配置及恢复机制；新增敏感能力必须显式登记，不静默授给全部旧角色。
- 委派权限区分查看、配置、执行、导出、授权和敏感内容访问；覆盖全局、指定组织/空间/应用、资源、环境与适用时限。拥有某权限不等于能授予该权限。
- 服务端对每个管理请求和实际异步执行校验权限，前端可见性只辅助体验。REST、实时通道、下载、搜索、批量、旧端点和后台任务采用一致规则。
- 角色变更和撤权影响已有会话、缓存与待执行任务；不要只等下次登录。两名管理员并发修改授权时不得互相覆盖或通过竞态移除最后管理员。
- 提供权限解释和受控模拟检查，说明为什么允许/拒绝；模拟不能执行真实业务或泄露无权对象。
- 拥有组织管理权不自动拥有平台管理权；管理员切换租户范围不等于冒充该租户某个用户。

### 4.2 最高管理员初始化、交接与恢复

- 核实现有最高管理员，不按邮箱前缀、姓名、第一个注册用户或前端字段猜测任命。需要初始化时沿用安全的受控服务端流程，使用有时限且不可重放的领取方式，不生成永久通用密码。
- 管理员使用强认证；高风险操作按风险要求近期重新认证。沿用现有 Passkey/MFA 和恢复机制，保护首次设置与迁移，不能把唯一管理员锁在无法完成的 MFA 循环里。
- 最后一个有效最高管理员的停用、删除或降权必须保护；交接前验证接任者能够正常进入并完成必要强认证。
- 建立不依赖故障中的唯一登录/邮件组件的应急恢复路径，受控保管、明确步骤、时限、审计与后续轮换。它是可验证的恢复流程，不是公开接口、隐藏万能账户或关闭全部认证的开关。
- 普通可逆操作直接完成；高风险操作按已有政策使用重新认证、影响确认或双人审批。不要为小团队凭空强制一个永远无法满足的第二审批人，也不能绕过已要求的职责分离。

### 4.3 内容访问、支持与秘密

最高管理员能够治理账户、资源生命周期和系统状态，但管理接口不得回显明文密码、他人的 MFA 种子/恢复码或其他已保存且不应回传的秘密。账户持有人本人设置 MFA、领取一次性恢复码，以及受控初始化中的必要一次性展示，按真实认证流程完成。私聊正文、个人文档、敏感附件的访问需独立权限和明确目的。

确需支持访问时，实现或复用受控授权会话：限定对象、用途、期限和可执行动作，保留真实管理员身份，符合已有用户/组织授权政策，并能撤销和审计。不能静默“登录为任意用户”、代发私信、代签同意或以用户身份改变安全凭据。优先用权限解释、脱敏诊断和受权样本定位问题。

密钥支持设置、连接测试、轮换、撤销与健康查看；默认展示是否配置、指纹/末位、作用域和更新时间。生成型令牌按真实方案仅创建时展示一次，外部凭据安全存储，不能重新回显到前端、日志、审计差异、导出或异常堆栈中。

## 5. 统一管理操作机制

复用现有服务层，建立轻量的类型化操作目录或等效约定，集中权限、验证、执行与审计；不要为此发明通用工作流语言或庞大框架。

每个写操作都要具备：真实动作 ID、目标与环境/租户范围、输入校验、前置条件、权限、风险级别、执行状态、幂等策略、结果、错误恢复和审计关联。UI、API、异步执行使用同一业务规则，不能 UI 安全但直接请求绕过。

### 5.1 清楚且可信的执行过程

采用适合实际动作的状态，例如待确认、待审批、排队、执行中、成功、部分成功、失败、已取消；不要强迫简单同步动作经过无用流程。

- 提交被接受不等于执行完成，服务商接收不等于最终生效。后台应展示真实阶段、可复核结果与更新时间。
- 执行时检查当前权限、资源版本与前置条件。防止确认后资源、范围或权限变化仍按过期内容执行。
- 重复点击、请求超时、确认丢失、worker 重启和重投不重复产生业务副作用；幂等键绑定操作者、作用域和规范化请求，同键不同参数应报冲突。
- 操作结果与审计/事件具有可靠持久关系，采用现有事务/outbox 或等效机制，避免业务完成但永远丢记录。
- GET、预取和邮件安全扫描不触发写入；不能把敏感动作放在点开即执行的链接中。

### 5.2 高风险动作

全局停用、权限提升、大范围导出、永久删除、生产恢复、密钥轮换和大量外发等动作显示目标、影响、不可逆部分和实际恢复条件，按风险执行近期认证与必要审批。

确认和审批绑定操作者、目标集合、参数、环境、版本与有效期；不能只在前端弹一个对话框，或拿旧确认令牌执行另一项动作。预览本身不修改状态、不发信、不扣款。

停用、归档、软删除、永久删除分别定义。权限撤销、消息发送、删除及收费等并非总可撤销，不能一律放一个假的 Undo。

### 5.3 批量操作

明确“选中本页”“选中这些 ID”“选中全部筛选结果”的差别。执行前给出目标集合、数量、例外和影响；大集合使用服务端快照/稳定引用，不在提交时悄悄扩大范围。

支持适用的异步分批、并发限制、进度、逐项结果、失败项重试、可恢复执行与取消。取消默认停止尚未开始部分，已经生效的结果如需补偿必须另行说明并真实执行。部分成功不能标全部成功；重试不能重复邀请、发信、生成、删除或收费。

## 6. 配置中心：修改后必须真的生效

建立一份与实际读取方对应的配置清单。每个字段具有稳定 key、类型、单位、说明、约束、默认值、作用域、敏感性、来源、继承/覆盖规则、当前有效值、版本及生效方式。

- 区分数据库动态配置、环境变量、部署配置、外部服务配置和派生只读状态；不要让一个 UI 开关假装能覆盖部署系统的强制设置。
- 展示全局/组织/空间的继承与覆盖关系，支持恢复继承。列表和详情都能解释最终值来自哪里。
- 保存前校验范围、依赖、格式和冲突；变更支持草稿/差异/适用的预检/发布。简单低风险字段可以直接保存，不强迫所有设置走多层流程。
- 显示“已持久化、待应用、已应用、部分应用或失败”，区分目标配置与各实例实际生效版本。需要重启/重新部署的如实说明并接入受控动作，不写进数据库就宣称生效。
- 使用版本检查防止两名管理员覆盖配置；客户端收到冲突时展示差异并重新提交，不静默最后写入获胜。
- 保留有效历史，配置回滚产生新的受审计版本，不删除变更史；回滚前检查当前依赖和兼容性，不能复活失效密钥或撤销的授权。
- 外部控制台/环境配置与后台状态不一致时，展示漂移及权威来源，并提供有权限的同步路径；不不断覆写导致双方打架。
- 功能开放支持实际需要的全局/组织/空间范围、依赖与紧急停用；已有灰度基础时复用稳定分组。功能资格不等于对象授权，隐藏 UI 不等于禁用接口。
- 上传大小、并发、任务配额、邮件摘要间隔、注册策略等管理值必须有真正使用它们的服务端执行点，并纳入生效验收。

## 7. 必须覆盖的管理模块

以下逐项核实并补齐。后台覆盖现有及已要求的业务，不意味着重写所有应用；但管理依赖缺失时必须补齐必要真实服务，不能永久以只读页面代替。

### 7.1 全局概览与运行分析

提供真实用户/组织/空间与应用使用、任务成功/失败、资源容量、队列积压、投递异常、实时连接、风险事件和依赖健康等适用指标。显示定义、单位、时间范围、时区、数据更新时间及完整性。

数据不存在时显示无数据/未接入/暂不可用，不能随机填图、把超时显示为零或用模拟刷新冒充实时。指标可下钻到有权明细或任务；聚合查询限时、分页/预聚合按规模选择，不能拖慢主业务。成本展示区分真实账单和带假设的估算，不凭空显示收入。

### 7.2 用户、账户与登录

支持有权搜索/筛选、账号详情、邮箱验证与机构注册诊断、登录方式、会话、设备、风险、组织关系与管理事件。提供停用/恢复、会话撤销、邀请/安全恢复、必要的账号更正和删除请求处理。

不得显示用户密码或把身份验证状态任意点成已验证。安全恢复依照身份确认流程，验证邮件发送受限流和审计。机构/CUHK 注册排查要区分校验、风控、发信、投递、链接与激活阶段，不能只加域名白名单。

停用/撤权影响已有浏览器会话、实时连接、API 委托与待执行任务；恢复账号不自动复活已撤销的授权。批量停用保护最后有效最高管理员。修复/合并账户只有真实业务确需且关系迁移可验证时才开放，不能简单改外键吞数据。

### 7.3 组织、工作空间、角色与成员

管理组织/空间创建、状态、归档/恢复、所有权、成员、邀请、应用资格、容量和配额。提供自定义角色、有效权限来源、受控交接和批量导入任务。

平台管理、组织管理、空间管理与内容权利分别呈现；归档/恢复和所有权移交处理正在运行的任务、分享与成员关系。保护最后拥有者，角色组合、已分配角色编辑和导入/API 不能提权。

导入沿用真实多格式解析/OCR 流程，支持来源预览、角色映射、差异确认、逐行错误与重试；未知角色不按字符串自动赋权，不创建默认密码。取消任务不谎称撤销已经发出的邀请或生效授权。

### 7.4 应用目录、开放范围与功能策略

管理实际应用的启用状态、入口、展示排序、允许使用的组织/空间、依赖、配额和适用功能开关。主站、工作空间、应用切换器及直接接口遵守同一发布结果。

停用应用不删除业务数据；说明已有用户、进行中任务、已发链接和恢复后的行为。组织暂不开放应用，不应影响其其他应用。不能把可见应用卡片当作真实授权机制。

### 7.5 Docs 与生成引擎

提供项目/模板/来源/产物的受权元数据、生命周期、版本、分享、复制审批和任务管理；涉及正文查看或导出时使用独立内容权限。

管理解析/格式/OCR/渲染等实际能力状态、队列、并发、超时、容量、可用字体和失败原因。配置实际支持的溢出/分页策略，不偷偷改用户已选择的模板语义。

可以定位失败样本、取消/重试、处理卡住任务、检查引擎健康与输出版本；重试继续使用固定来源/模板/映射/公式快照，成功样本不重复生成，发布产物前校验完整性和当前授权。不能直接把数据库状态改成成功。

审批复制显示来源授权、目标、固定范围、状态及执行结果；重试不重复创建副本，不把私人凭据、协作房间或未批准内容带入组织。

### 7.6 Docs 实时协同

管理协同服务健康、协议/客户端兼容、房间连接、持久化延迟、积压与冲突错误等必要元数据。提供受控断开异常连接、维护与恢复动作，不默认展示用户每一次输入正文。

恢复历史/快照前明确影响与授权，固定版本并处理在线编辑；恢复作为新变更，不让旧离线队列覆盖恢复内容。服务排空/滚动重启不丢已确认修改，不能用关闭协同或强制全文覆盖来“修复”冲突。

### 7.7 Message 与沟通治理

管理服务状态、会话/群生命周期、群角色、历史规则、附件/语音限制、滥用举报与处置、投递异常、资源配额和已有保留策略。

提供符合真实规则的限制发送、隔离违规对象、群归档/恢复、成员处置及申诉/复核记录。举报可提供受权的必要证据，不把后台变成默认读取全部私信的浏览器。

退群/移除/停用后，活动连接、历史搜索、附件、待发消息与摘要按规则生效；修改历史策略前预览范围，不能扩大私密群旧历史可见性。不得伪造发送、已读、在线或以用户身份改消息。

### 7.8 通知、邮件与发信配置

管理真实事件目录、模板、语言、HTML/纯文本、主题/预览、Logo、变量契约、渠道、用户偏好策略、摘要预算、免打扰和队列。模板支持预览、变量检查、版本、测试、发布与回滚；模板执行不能允许任意服务端代码。

管理已授权的 SMTP/发信服务、多发件域名/地址及路由（存在或有实际配置条件时）、认证状态、TLS、凭据轮换、健康、退信/投诉、限额、失败与重试。域名验证以真实 DNS/服务商结果为准，不能点击即标记通过。

真实测试发信只面向明确授权的测试地址。批量补发排除过期验证码/令牌、重复事件、已撤回通知和无权收件人；外发预览显示受众、数量与内容版本。模板改版不能重发历史事件，SMTP 接收不能宣称收件人已收到。

严格保留私信邮件默认关闭和主动开启聚合摘要规则；发送前复核已读、静音、撤回、权限和偏好，无新未读不反复催发。

### 7.9 API、服务身份、自动化与集成

在平台管理员权限内管理服务身份、合法委托、密钥创建/轮换/撤销、作用域、有效期、配额、调用状态、任务计划、Webhook 端点、签名、投递和失败处理。秘钥归属与可访问空间必须来自明确授权。

Webhook 重放和手工重试保持业务幂等，校验当前权限、端点与有效签名，限制 SSRF、重定向和资源使用。连接测试是有边界的真实协议检查，不是任意内网探测器。

提供真实文档与契约版本；轮换支持适用过渡，旧凭据到期/撤销后失效。机器调用不收到浏览器验证码 HTML。尚未接入的供应商明确显示配置缺项，不能显示绿色“已连接”。

### 7.10 文件、存储、扫描与数据请求

管理空间使用、容量、原件/产物/版本关联、隔离队列、扫描器及规则健康、重扫、误报复核、索引状态、保留策略、导出/删除请求和孤立资源核查。

扫描失败、超时、不完整或加密不可检查不能被管理员随手标为安全；复核通过明确策略和真实检查完成。隔离文件不能从原始链接、预览或签名下载旁路，内容安全不替代资源授权。

清理前做引用检查和影响预览，分清个人/组织归属、共享 blob 与缓存。安全导出有受众、范围、有效期、限流和审计；删除请求协调活动任务、索引、缓存与备份保留，不能承诺即时清除所有历史备份。

### 7.11 安全、反滥用、审计与事件处理

管理实际认证/MFA 策略、风险挑战、限流、上传限制、可信代理、已接入 WAF/边缘防护、规则版本、事件、告警及有理由和期限的例外。规则可预检/观察/分批应用，能发现误伤并恢复。

防护在应用服务端和实际多实例生效；不能只改变 UI 文案，不能通过永久绕过全部 API 解决误报。来源 IP 不信任任意转发头，合法 SDK、Webhook、OAuth 与健康检查保持各自协议。

事件处理关联对象、证据、动作、负责人和状态。告警关闭/静音有范围与期限，不删原始事实；后台的安全操作也受审计。

### 7.12 服务、队列、发布与域名

读取真实应用/实例/worker、依赖、版本、健康、资源、任务积压、失败与日志；区分应用健康、依赖故障、部分降级和指标过期。

提供适配已有设施的任务暂停/恢复、失败项重试、worker 排空、受控重启、特定缓存失效和维护模式；动作有对象边界、并发控制与结果复核。保护运行中的任务和实时数据，不给网页进程无限系统权限。

集成现有 CI/CD 的提交、构建、部署和回滚状态；实际支持且已授权时通过受限执行接口触发既有流程，保留分支保护与审批，不自建绕过流水线。

五个正式域名、证书、入口、代理/隧道、回调、Origin、公开资源与旧域兼容必须可诊断。涉及 DNS/云配置写入时采用真实已授权 API 和限制范围；没有凭据就明确只读/受阻，不伪造完成，也不擅改 DNS。

维护模式和全局开关不能切断管理员恢复、必要健康检查、受保护发布和已定义的应急路径。接入高权限运维时使用限定动作与参数的执行机制，不能暴露任意 Shell、SQL、Docker socket 或服务器文件编辑器作为默认后台。

### 7.13 备份、恢复与运维作业

管理实际备份计划、范围、版本、状态、加密/密钥引用、保留、失败与恢复演练；展示真实恢复点与覆盖范围。备份文件存在不等于可恢复。

恢复先选择环境与范围，检查依赖和版本，优先在隔离目标演练并校验数据/权限/产物一致性；生产恢复有写入协调和明确确认。配置回滚、代码回滚、数据恢复分别处理。不得未经确认丢弃恢复点之后的新数据；展示恢复点、预计数据损失和权限回退风险，正式切换按已授权恢复方案执行。恢复后核对/重建撤权状态，轮换必要凭据并撤销旧会话；无法证明安全核对完成时保持受控维护状态，不把旧备份宣传为必然无损恢复。

清理、重索引、重扫和迁移等管理作业具有参数验证、范围预览、幂等、进度与恢复说明；复用真实运维任务，不拼接任意用户输入为服务器命令。备份产物本身也属于高敏感数据。

### 7.14 主站、品牌、政策及其他真实模块

管理适合后台维护的主站文案、三语言内容、FAQ、公告、应用展示、正式 Logo 引用和隐私/服务页面版本。提供草稿、预览、发布、历史和回滚，防富文本/链接注入，验证前台、邮件与缓存实际更新。

保留法律主体、费用、同意记录、数据处理等实质约束；不能由代码自动编造政策或让普通文案角色改变身份/域名/安全配置。正式条款改变时遵守已有生效与同意机制。

仓库已经存在的账单、订阅、支付、商业额度、AI 供应商或其他模块必须纳入对应管理范围；没有真实业务时不创建虚假收入、付款、发票或 AI 控制台。不能以后台建设为由擅自定价、购买服务或扣款。

## 8. 审计系统必须能够解释实际发生了什么

审计记录至少涵盖可信操作者、适用的委派/支持身份、时间、环境与目标范围、动作、原因、脱敏前后差异、请求/任务/变更关联、执行与最终结果。拒绝、失败、部分成功、取消和异步完成同样有记录。

- 使用服务端产生的身份和时间，不信任前端传入“管理员姓名”。内容默认记录对象引用及必要元数据，秘密与用户正文不落入审计。
- 提供筛选、对象时间线、关联跳转和受限导出，搜索和导出本身同样鉴权并按风险审计。
- 普通管理 API 不得编辑或静默删除操作记录；保留策略通过受控流程管理，不能提供“一键清空我的日志”。
- 为真实审计存储建立与架构匹配的追加写、分权、保留与完整性保护。没有独立存储/校验支持时，不宣传“绝对不可篡改”。
- 审计写入/队列异常有明确策略：高风险动作在无法可靠记录时阻断或进入受控恢复流程，普通只读业务按风险处理；不能悄悄执行所有写入后丢记录，也不能因为监控服务故障锁死全部恢复能力。
- 基础设施级操作者可能超出应用日志的保护范围，说明真实边界；应急操作也应保留并在恢复后核对证据。

## 9. 世界级 UI、交互与动效的具体标准

1. **清楚的层级。**统一应用壳、导航、面包屑、页标题、主动作与环境标识。主任务显著，低频选项按需展开，不在每张卡片堆说明。
2. **专业的数据密度。**表格、筛选、详情和操作栏围绕工作组织；不把所有管理功能变成巨大统计卡片，不依赖横向无限滚动。
3. **完整列表体验。**排序、筛选、分页、列显示、保存视图与选择语义一致；加载更多和筛选变化不偷偷扩大选中集合。大量结果采用适当服务端查询与虚拟化，保证键盘及读屏可用。
4. **完整表单体验。**输入格式、单位、依赖、继承、敏感字段与生效方式清楚；及时校验并保留错误输入，提供未保存变更保护、并发冲突处理和准确的保存结果。
5. **操作反馈真实。**轻量同步动作即时反馈，长任务进入可返回的任务详情；未知进度不伪造百分比。危险操作不提前乐观显示已成功，不靠短暂 toast 承载唯一重要信息。
6. **动效服务理解。**导航、抽屉、弹层、列表变动和状态转换节奏一致；不阻挡输入，不闪屏，不人为加延时，尊重减少动画。实时更新不抢焦点或把正在点击的行突然移走。
7. **高质量全状态。**加载、无结果、空、无权、只读、维护、离线、过期、部分失败、重试和恢复都有合理布局及下一步；错误不可被无限 skeleton 掩盖。
8. **无障碍与响应式。**键盘路径、Esc、焦点恢复、读屏名称、对比度、缩放、触摸目标和中文输入法正常；移动端使用适合的筛选、详情与确认布局，不把桌面表格硬缩到手机。
9. **产品文案克制。**统一术语与按钮；用户需要知道的权限、影响、费用、数据范围和恢复信息必须保留，底层实现放在合适的诊断视图。
10. **品牌一致。**白蓝体系、三款正式 Logo、简繁英贯穿全部页面和状态，不重绘标志、不擅改主站风格。若已有深色主题则沿用并验证，不为此另造一套无关视觉。
11. **真实视觉验收。**用实际运行页面检查代表性桌面与手机、长名称、无数据、大列表、权限不足、失败和危险确认，修复裁切、遮挡、布局跳动及无效点击。截图和真实操作分别提供证据。

如增加智能诊断建议，必须有真实数据和模型、可追溯依据与成本/权限控制；建议不能自主越过管理审批执行删除、改权限、外发或恢复。没有完整条件就先交付确定性的搜索、规则与诊断，不放不可用的 AI 按钮。

## 10. 工程质量与管理面自身的保护

- 后台复用业务服务及一致约束，不通过直接修改数据库字段跳过应用规则。新管理 API 保持类型、错误码、分页、作用域和版本契约。
- 正确处理会话、CSRF、CORS、CSP、点击劫持、输入验证、XSS、SSRF、注入和导出中的危险公式；后台也处理不可信用户名、文件名、日志和模板内容。
- 管理端 API 与敏感响应避免被公共缓存、service worker 或普通用户页面缓存；登出/降权清理前端状态，后端仍作权威判断。
- 控制查询/导出成本、任务并发、配额与有界重试。日志查看可暂停并保持阅读位置，实时连接不重复创建，不能为了监控反而拖垮生产。
- 为每个后台动作登记对业务的依赖；共享服务变化回归受影响应用。新旧客户端、迁移和运行中任务保持适用兼容。
- 不引入默认全权数据库账号、通配云凭据、明文环境文件展示或永久调试入口。后台自身被攻破时也不应自动获得整台宿主机的所有能力。
- 生产使用真实可用依赖和配置。禁止假数据、假 API、假登录、假图表、假扫描、假发送和固定成功；测试替身仅限明确隔离测试，不冒充外部验证。

## 11. 必须执行的端到端验收

每个管理能力按同一标准验收：**有权管理员完成操作 → 服务真实执行 → 受影响业务产生预期变化 → 刷新/重试后结果正确 → 无权路径被拒绝 → 审计可追踪。**

至少建立最高管理员、受限管理员、普通用户和不同组织/空间的独立测试身份；使用明确隔离的真实数据和实际后端。适用场景使用两个独立浏览器上下文，不靠单账户切标签伪装多人。

| 场景 | 必须验证的结果 |
| --- | --- |
| 管理员授权 | 普通用户/组织管理员/受限角色直接访问管理 API 不能提权；角色撤销使旧会话和待执行操作按规则失效 |
| 最高管理员恢复 | 初始化、交接、最后管理员保护、MFA 与应急流程真实可用，不依赖假成功或万能密码 |
| 用户停用 | 已登录会话、实时连接和委托调用受影响；恢复不复活原本已撤销的权限 |
| 配额与功能开关 | 管理端改值后，普通用户上传/提交/进入应用确实遵守新策略，刷新与多实例一致 |
| 配置并发与回滚 | 两名管理员改同一版本触发冲突；待重启/部分应用如实显示；回滚后的有效值可验证 |
| 批量操作 | 本页/全筛选目标准确；超时重试不重复执行；部分失败、取消和恢复保留逐项真实结果 |
| Docs 任务 | 重试固定版本且不重复成功样本；取消不发布半成品，产物内容/格式/下载权限正确 |
| Docs 协同运维 | 两用户并发、断线/重启和受控恢复后不丢已确认修改，旧队列不能覆盖新状态 |
| Message 处置 | 成员移除/限制后，旧连接、搜索、附件与待发摘要同步遵守规则，无假已读与假撤回 |
| 通知与邮件 | 模板发布、真实测试收件、失败处理可核对；连续私信不逐条发邮件，重试不复发过期验证码 |
| API 与 Webhook | 密钥轮换/撤销、作用域及重放幂等有效；连接测试不能访问未授权内部目标 |
| 文件与存储 | 扫描故障不放行新文件，合法已接纳文件按策略工作；清理不误删共享引用或私人资源 |
| 秘密与支持访问 | API、页面、日志、审计和导出不泄露秘密；内容访问有独立授权、期限与真实操作者 |
| 审计与故障 | 成功/拒绝/失败/异步结果可关联；日志不可从普通接口改写，审计组件故障遵守既定策略 |
| 维护与恢复 | 管理和恢复路径仍可用；隔离恢复演练正确，生产恢复不能误覆盖新写入或复活旧授权 |
| 域名与发布 | 后台、五个正式入口、登录返回、资源与部署版本一致；平台其他功能未被破坏 |
| UI 与可访问性 | 三语言、桌面/手机、键盘、读屏关键路径、长内容、减少动画及完整状态可用 |

运行适用的静态检查、类型检查、生产构建、业务/权限/契约测试和真实浏览器验证。高风险逻辑补充有独立期望的回归测试；纯低风险视觉改动不强迫写重复测试。

不得删除有效断言、跳过失败、关闭安全或吞异常制造全绿。报告区分已验证、失败、受阻和未运行；模拟视口不当作真机，浏览器邮件预览不当作真实邮箱客户端，历史测试数字不算本轮证据。

验收和强制门槛通过后，除非有新证据或具体未解决风险，不继续扩大测试、反复研究或重跑相同流程；转入交付和下一批。

## 12. 分批实施，直到整体闭环

按真实依赖调整顺序，建议：

1. **基础与第一条真实控制链路**：现场恢复、能力表、管理员入口/权限/强认证、统一布局与审计，并交付一个真实账户或配置操作的业务生效验证。
2. **身份、组织与配置**：最高管理员恢复、委派角色、用户/空间管理、动态配置、版本/生效、批量任务与权限反向验收。
3. **全部业务模块**：Docs、协同、Message、通知/邮件、API/自动化和文件安全逐个形成完整管理链路，已有能力直接复用。
4. **运维与数据**：运行状态、任务处理、域名、受控发布、备份/恢复、清理与治理。
5. **整体体验与发布**：全局搜索、对象关联、保存视图、待处理中心、视觉/动效/三语言/移动端、全范围回归及正式部署后复查。

每批包含实现、真实后端、权限、审计、状态、错误恢复、UI 和证据，不能先造几十个空页面再宣布后台完成。已经可独立安全上线的批次可以先交付，剩余明确范围继续推进，不无限期放入路线图。

## 13. 执行、发布与跨会话接续纪律

- 普通调查、开发、修复与验证自主执行，不反复询问“是否继续”。本任务要求构建并验证管理能力，不意味着可以拿真实用户执行停用、删除、群发或恢复演示。
- 延续已有正常提交、推送和必要部署授权，使用现有 CI/CD，保留环境审批与分支保护；核实推送是否自动上线，满足门槛后再推送。
- 保留用户与其他代理工作，不硬重置、清库、强推或批量停止无关服务。只清理本任务创建且确认无真实依赖的验证资源。
- 新增付费服务、将用户数据发送给新供应商、改变重要授权/收费/政策或执行破坏性生产操作，先完成可审阅准备，再提出必要具体决策；已有明确授权不重复询问。
- 本任务已授权设计、实现和隔离验证管理权限、委派与恢复能力；上述确认边界指向把新的高权限实际授予真实生产身份、扩大真实用户数据访问范围等具体影响，不是正常开发这些能力。已有明确的管理员任命和权限范围直接沿用。
- 缺外部凭据、DNS/云权限、测试收件箱或本人 MFA 时，准确列明缺项和影响，完成所有可独立推进的内容；不能伪造接入，也不能因此冻结整个后台。
- 可将独立研究、模块实现和审查交给子代理，明确文件归属及接口。主代理负责集成、证据、迁移与发布；同一配置、迁移、文件和环境避免并发冲突。不支持子代理时顺序执行。
- 同一问题连续两次无进展后，检查根因并改变假设，不无限重试；修复当前已知回归后再叠加新功能。
- 维护唯一任务/交接记录，复用现有 `iteration-state`。记录分支/HEAD、变更、覆盖表、配置/迁移版本、实际测试、CI/部署状态、阻塞与下一步，不记录秘密或用户正文。
- 任务中断前保存检查点；新会话核实现场后接续，不能重复初始化管理员、重跑迁移、重复外发或重复部署。不承诺退出会话后自动继续运行。
- 只要还有具体、已授权且可执行的任务，就在完成一批后推进下一批。整体要求已验收闭环、用户要求停止或实际运行条件阻断时，保存现场并准确交接；不为保持忙碌进行无意义重构。

## 14. 交付物与最终判定

最终交付必须包含：

1. **可运行的 Synwevo Admin**：真实前后端、已接入的管理服务、配置/迁移与现有部署体系。
2. **管理能力覆盖表**：每个模块/动作的实现位置、权限、作用域、实际执行方、验证和发布状态。所有未交付项有准确原因与接续条件。
3. **管理员使用与恢复说明**：最高管理员初始化/交接/恢复、日常操作、配置生效、危险操作、备份与故障处理；敏感秘密不写入文档。
4. **可复核证据**：代表性页面截图、真实操作前后结果、权限反向用例、任务/配置/审计关联和适用文档产物，全部脱敏。
5. **准确发布记录**：相关提交、真实检查和 CI 结果、部署版本、管理员入口及线上复查。明确区分本地通过、已推送、已部署和正式业务验证。

不要把“页面完成”“接口返回 200”“保存到数据库”“通过若干测试”单独当作整体完成。必须证明管理员操作改变了正确目标、普通业务遵守结果、失败可处理、权限与审计完整。

**现在开始：恢复真实现场，建立简洁的管理能力覆盖表，优先打通安全的管理员入口和第一条真实管理链路；随后按依赖补齐全部适用模块、顶级 UI/交互/动效、故障恢复和验收，通过已有流程发布并复查。持续执行到本任务形成可检查、可运行、可部署、可恢复的完整结果，不停在计划或后台样板。**
